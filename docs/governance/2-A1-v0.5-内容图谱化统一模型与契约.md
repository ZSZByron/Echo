# 2-A1 内容图谱化统一模型与契约 v0.5

> **定位**：A1 世界观工坊「定稿 → 知识图谱」环节的**唯一权威概念模型**——数据形态、图结构、层级编号的统一契约，及据此的修改规范。与 v0.1/v0.4 冲突处以本文为准（修正清单见 §9）。
> **一句话**：自然语言进 → graphify 一次 LLM 调用做结构化+关系化 → 确定性组装为双树+tier 图 → 图谱页呈现；每对生产-消费必有契约与集成测试。

## 0. 病根与解药（为什么需要 v0.5）

2026-09-03 决策考古（`a1-contradiction-analysis.md`）确认三组系统性混淆：

| 病 | 症状 |
|----|------|
| "结构化"一词三义漂移 | 机器标记层（08-21 已死）/ v0.4 槽位内容层（纸面）/ key 层问卷字典（现状）从未对齐 |
| "L{n}" 一数两用 | v0.4 语义七层 ↔ 代码结构四层，同 notation 不同含义 |
| 契约散落 | 08-24 范式重构斩断 tag= 生产方而消费方遗留（约束边恒 0），无集成测试拦截 |

**解药 = 三条正交分离轴（§1-§3）+ 概念词典退役制（§7）+ 契约注册表（§6）。**

## 1. 轴一：数据形态分离

"结构化文件"一词**退役**。系统只有三种数据形态，各有专名，**每种形态只有一个生产方、一个消费方、一份契约**：

| 形态 | 专名 | 内容 | 生产方 | 消费方 | 生命周期 |
|------|------|------|--------|--------|---------|
| **NL** 自然语言 | `answers` | `module.subfield → 纯文本` | 访谈器（用户+LLM 自由对话） | graphify LLM（唯一） | 访谈全程持续增长；定稿后回 draft 可继续 |
| **SIR** 结构化中间表示 | `graphify 结果` | 五字段 JSON（§4） | graphify LLM（定稿时一次调用） | 组装器（唯一） | 定稿时刻生成，每次定稿全量重建，不持久化为独立资产（随 graph_json 物化） |
| **KG** 图数据 | `graph_json` | 节点（双树）+边（三类）+属性（tier） | 组装器（确定性代码） | 前端图谱页、下游 A2+ | 定稿后持久化于 file 记录，版本化（W1-vN） |

**铁律 1a**：NL 永不携带机器格式（访谈器"简洁中文提取用户原意"规则不变）。
**铁律 1b**：SIR 只在定稿时刻由 graphify 生成，任何访谈时刻的结构化尝试（tag= 标注、内联标记）均为违规。
**铁律 1c**：KG 只能由组装器产出（LLM 产物必须经组装器物化，禁止直写 graph_json）。

## 2. 轴二：图结构分离（双树 + 三类边）

| 结构 | 性质 | 节点 id | 序号 | 边 | level |
|------|------|---------|------|-----|-------|
| **概念树** | 问卷骨架投影，确定性 | `bg_{session[:8]}` / `{module_id}` / `{module_id}.{subfield_id}` | `0` / `N` / `N-M` | TREE（"包含"/"条目"） | 1 / 2 / 3 |
| **深度树** | 内容条目生长，生成性 | **`d:{anchor}:{title规范化}`（内容锚定，学 term: 模式）** | `D{锚点}-{k}`（仅 serial_number，展示用） | TREE（"分条目"） | 4 |
| **语义边** | 横穿织网，待确认 | —（引用两侧节点 id） | — | SEMANTIC / RULE / STRUCTURE（confirmed=false 起） | — |
| **约束节点** | 独立标注层 | `cst_{DIM}_{tag}` | 同 id | CROSS（"A1 \| RULE_*"） | 0 |

> **深度树 id 稳定化（R2 补丁）**：id 用**内容锚定**（anchor + title 规范化），与现行概念词 `term:{term文本}` 同模式——跨 re-finalize 天然稳定；`k` 序号仅进 serial_number 供展示，不参与 id。同锚点下同 title 去重（同 term 去重逻辑）。若 LLM 两次输出的 title 措辞有微小差异导致 id 不匹配，按"未匹配即新节点"处理并进审核台失效区提示（见 C2 匹配键），不做模糊合并。

**不变量（CI 断言）**：
1. TREE 边总数 = 模块数 + 条目数 + 分条目数
2. 概念树序号与 answers key 同构（`{module_id}.{subfield_id}` 双向可追溯——继承 v0.1 铁律）
3. 深度树序号锚点必须是合法概念树条目序号；深度树 id 必须可解析回 `{anchor}:{title}`
4. 语义边 from/to 必须引用图中存在（或本次同建的）节点 id
5. **跨 re-finalize id 稳定性（R2 补丁）**：节点 id 不得含顺序号等跨版本不稳定成分；同内容重产出必须得到同 id

## 3. 轴三：层级编号分离（tier ≠ level）

**v0.4 的 L0-L6 在代码与产品语境中一律称 `tier`（语义层）；`level` 专指图深度（结构层）。**

| 维度 | 字段 | 附加于 | 取值 | 决定者 |
|------|------|--------|------|--------|
| 图深度 | `level`（现有字段） | 一切节点 | 0 约束 / 1 背景 / 2 模块 / 3 条目 / 4 分条目 | 组装器 |
| 语义层 | `tier`（GraphNode 新增可选属性） | 仅模块节点 | 0-6（下表） | 静态映射表（v0.4 §1 编译，写死于代码） |

**tier 静态映射表**（10 模块全覆盖，封闭）：

| tier | 层名 | 模块 | 方向语义 |
|------|------|------|---------|
| 0 | 存在基座 | 世界本体 | 向上滋养 |
| 1 | 动力学 | 力量体系 | ←tier0 |
| 2 | 显现 | 地理空间、文明与社会 | ←tier0-1 |
| 3 | 时间 | 历史时间线 | 全树汇聚 |
| 4 | 表达 | 视觉设计、玩法设计DNA、骰子设定 | 纯派生汇 |
| 5 | 命题 | IP定位 | 向下投影 |
| 6 | 治理 | 设定边界 | 横向治理 |

**tier 的呈现**：概念网视图按 tier 分组布局/着色；层间派生关系由语义边承载（§4 edges，v0.4 派生边总表 ★/◆/◇ 编入词表）。**tier 不加深概念树、不占 level 编号**——七层理论以"属性+派生边"落地，而非"层节点入图"。

## 4. SIR 契约：graphify 结果五字段

定稿时一次 LLM 调用（`graphify_llm`），输入 = answers 全文 + 边词表 + 不可动清单 + tier 映射表 + 节点引用规则；输出：

```json
{
  "module_summaries": { "<module_id>": "一句话归纳（≤40字）" },
  "entries": [
    { "anchor": "<module.subfield>",
      "items": [ { "title": "…", "content": "…", "children": [ … ] } ] }
  ],
  "edges": [
    { "from": "<节点引用>", "to": "<节点引用>",
      "relation": "<词表内关系名>", "rationale": "…",
      "confidence": "semantic | rule | structure" }
  ],
  "constraint_fields": { "<DIM>.<tag>": "<值>" },
  "open_questions": [ "世界观语言问句（无术语）" ]
}
```

| 字段 | 承载能力 | 组装去向 |
|------|---------|---------|
| `module_summaries` | 总结（已知拓扑归纳） | 概念树 L2 description（失败回退 module_label） |
| `entries` | 节点提取（同级=items 并列；下级=children 嵌套） | 深度树 L4 节点 + TREE 边 |
| `edges` | 提炼（新拓扑发现，词表内） | 语义边（confirmed=false 待审核） |
| `constraint_fields` | 约束归类（重建 08-24 被斩断的生产方） | `apply_constraints` → cst_* 节点 + CROSS 边 |
| `open_questions` | 提炼（词表外关系→问用户） | file 记录 → 回访谈页 → 答后下次定稿转正为边 |

**校验规则（组装器执行，非法即丢弃并 warning）**：
1. `anchor` 必须是合法 `module.subfield`（LLM 不得发明锚点）
2. `edges.from/to` 只能引用：概念树 id / 本次 `d:{anchor}:{title}` 规则编发的深度树 id / cst id
3. `relation` 必须在封闭词表内（表外→组装器移入 open_questions）
4. `constraint_fields` 的 DIM.tag 必须在 STRUCTURED_FIELDS 21 字段白名单内
5. `children` 深度 Phase 1 不开放（只消费 items），Phase 2 起递归挂载

**降级链（finalize 永不因 LLM 失败阻塞）+ 降级可观测三机制（R1 补丁：降级≠无声）**：

| 失败 | 兜底 | 可观测信号 |
|------|------|-----------|
| 模块摘要失败 | L2 description 回退 module_label | warning |
| 条目提取失败 | 无深度树 | warning |
| 边抽取失败 | 无语义边 | warning |
| 约束归类失败 | cst 层空 | warning |
| 全部失败 | 纯概念树（同 v0.1 产物） | warning |

三机制（每级降级必须全部触发）：
1. **warning 持久化**：`rec["finalize_warnings"] = warnings`（现行代码只在响应中闪现、不落 rec——必须修），re-finalize 覆盖
2. **图谱页角标**：finalize_warnings 非空时图谱页顶部显示"本轮降级：{N} 项"角标，点击展开明细（区分"正常空"与"静默降级"）
3. **运行时断言（区分没数据 vs 降级成空）**：`constraint_fields 非空但 cst 节点=0` → 告警；`edges 非空但语义边=0` → 告警。断言失败视为组装器 bug（CI 负向用例覆盖），上线后进 interaction_log

**confirmed 匹配键（R2 补丁，写入契约正文）**：
- 语义边恢复键 = `from_node_id + to_node_id + relation` 三元组**精确匹配**（与现行 `confirmed_edges` 快照键 `term:A/term:B/relation` 同构）
- 恢复时引用失效的边（from/to 节点本次未产出）→ **进"审核台-失效区"可见展示**（"上次已确认，本轮源节点未再出现"），**禁止静默丢弃**（现行代码 `a1_routes.py:762` 的 `continue` 是静默丢弃——必须修）
- LLM 近义改写 relation 导致匹配失败 → 按未匹配处理进失效区，不做模糊合并（宁可见失效，不可误恢复）

**长内容预案（R4 补丁）**：P1 验收除明华样本外，增加超长 answers 压测样本（模拟 3-5 个模块满答 + 长文 value），实测 graphify 输入 token 量与产出质量衰减曲线，据此定"必须分块"的量化触发线（写入本文档 §8 验收附录）。若 Phase 2 需分块：按模块分块、跨块边二次合并；深度树 id 因内容锚定天然免疫跨块 k 冲突（R2 补丁的红利）。

## 5. 统一管线与执行序

```
① 访谈（NL 增长）→ ② 定稿触发
  → graphify_llm 一次调用（总结+条目提取+关系建立+约束归类，§4）
  → 组装器（确定性）：
     a. 概念树投影（现有 _build_graph 逻辑，L2 description ← module_summaries）
     b. 深度树挂载（entries → L4 节点，id=`d:{anchor}:{title}` 内容锚定；+ TREE"分条目"；serial=D{锚点}-{k} 展示序号）
     c. 语义边合并（edges → SEMANTIC/RULE/STRUCTURE，confirmed=false；
        re-finalize 时按三元组精确匹配恢复 confirmed_edges 确认态；
        引用失效边进审核台失效区，禁止静默丢弃——§4 R2 补丁）
     d. 约束注入（constraint_fields → apply_constraints，cst_* + CROSS，幂等）
     e. tier 标注（模块节点写入 tier 属性）
     f. open_questions → C6 结构化记录存 file（id/question/status/answer）
     g. warnings 持久化 rec["finalize_warnings"]（降级可观测）
  → 版本签发（W1-vN）+ stale 传播（铁律：永不删除、永不覆盖——不变）
→ ③ 图谱页：概念树视图（层级带状，含深度树 L4）/ 概念网视图（语义边织网 + tier 分组 + 审核台）
```

## 6. 契约注册表（流程铁律）

凡生产-消费格式对，必须登记 + 集成测试，缺任一不许合入：

| # | 契约 | 生产方 | 消费方 | 集成测试（CI 强制） |
|---|------|--------|--------|------------------|
| C1 | answers 格式（NL） | 访谈器 | graphify prompt 构造 | 真实访谈产出样本可被 graphify prompt 消费（冒烟） |
| C2 | graphify 五字段 schema + **节点引用规则（d: 内容锚定）+ confirmed 匹配键（三元组精确匹配，失效进审核台失效区）** | graphify LLM | 组装器 | schema 校验 + anchor/引用/relation/DIM.tag 合法性 + 降级路径全覆盖 + **负向用例：伪造 anchor / 表外 relation / 超白名单 DIM.tag / Phase1 越权 children / 幻觉节点引用，全部被拒且 warning** |
| C3 | graph_json 双树结构 + **id 内容锚定稳定性（不变量5）** | 组装器 | 前端 + 下游 A2 | §2 不变量五条断言 + **re-finalize 同 answers 同 id 快照测试** |
| C4 | 语义边词表（封闭） | 治理文档（v0.4 §3 编译） | graphify prompt | 词表封闭性；表外必进 open_questions |
| C5 | tier 映射表（静态） | 治理文档（本文 §3） | 组装器 + 概念网布局 | 10 模块全覆盖、tier∈[0,6] 断言 |
| C6 | **open_questions file 记录格式** | 组装器 | 访谈页（展示+问出） | 结构化记录 `list[{id, question, status(pending/asked/answered/skipped), answer}]` 往返序列化测试；**禁止退化为裸 list[str]**（R3：链路只活在注释里=tag= 死路复发） |
| C7 | **回答→边转正映射规则** | 访谈器（问出+记录 answer）+ graphify（下次定稿读取 answered 条目注入 prompt 为转正证据） | 组装器（转正边 confirmed=false 入图，rationale 引用用户回答） | 端到端：表外关系→问句→用户回答→下次定稿成边→审核台可见 全链测试 |

> C6/C7 的实现排在 P4，但**契约登记与测试骨架必须在 P0 完成**——用 v0.5 自己的规矩量 v0.5：链路最长的生产-消费对不允许无契约动工。

**考古教训沉淀（三流程铁律）**：
1. 凡"X 未实现"的诊断，先跑 `git log -S "X"` 排除"曾实现后被废"
2. 凡范式重构，必须盘点被替换组件的全部下游消费方（deprecation checklist）
3. 凡契约变更，生产方与消费方双侧签字（schema 即文档），禁止契约只活在解析代码注释里

## 附录 A1-T18：graphify 单调用分块触发线建议（2026-09-04 压测）

### 测量方法

压测脚本 scripts/stress_graphify.py（真 provider 计时调用 graphify_llm，--dry-run 用 StubProvider 零成本回归）。fixture 为 5 个模块满答 × 每模块 2.6k-3.2k 字中文长文（合计约 11k 字，即典型样本 ×3 体量）；token 口径为 chars/4 估算（未装 tiktoken，中文实际 token 数更高，原始字符数并列记录）。每轮采集：输入/输出 token 估算、延迟、五字段完整率（module_summaries / entries / edges / constraint_fields / open_questions 非空计）。

### 实测数据（deepseek，3 轮）

- 输入 12,970 字符（约 3.2k est-tokens）× 3 轮：全部 success=True，延迟 15.9-20.4s，五字段完整率 4/5（缺 constraint_fields 系 LLM 未按 DIM.tag 白名单归类，与长度无关）。
- 详情：.sisyphus/evidence/task-18-stress-report.md。

### 触发线建议

**输入 ≤10k 字符（约 80% 余量）单调用安全；超过该线建议触发分块。** 复测时以"success=True 且完整率 ≥4/5"为安全判据；constraint_fields 完整性受答案内容影响，不作为超长退化信号。
