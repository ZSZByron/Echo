> **⚠️ 定位升级（2026-08-05 v0.2）**
>
> A1 不再是"世界生成器"（输入种子→六维约束→知识图谱→完整世界观），也不再是"世界观产品化编辑器"（输入世界灵魂→输出操作手册）。
>
> **新定位**: A1 = **世界观IP设计工作台 (World IP Design Assistant)**
> - **交互形态**: 专业问卷 + AI设计顾问 + 自动结构化
> - **核心流程**: 专业问卷（8大模块21项）→ AI顾问分析 → 发现缺失/矛盾 → 追问补充 → 生成 World IP Schema
> - **类比**: 建筑行业——客户不会填写钢筋型号，但建筑师通过功能需求表、风格偏好表、空间需求表把需求转化成设计方案
> - **厂家体验**: 像有一个资深世界观策划陪他做IP
> - **系统内部**: 把问卷回答编译成 World IP Schema + Knowledge Graph + Rule Engine + Generation Constraints
> - 知识图谱不是交付物，而是**后台支撑层**
> - 厂家不需要看到"五图模型"，五图模型只是 AI 和系统内部理解世界的方式

> **❌ A1 不是什么**:
> - 不是"输入一句话生成世界"的AI聊天工具
> - 不是自由文本→世界观的黑盒生成器
> - 不是让厂家学习五图模型的编辑器

## 1. 架构概览

### 1.1 系统定位

A1 世界观IP设计工作台是 Echo UGC 项目的**世界品牌创造引擎**，定位为**World IP Design Assistant**：

```
厂家用户
  ↓
世界观设计问卷（9大模块25项）
  ├─ 第一部分：IP定位（名称/概念/类型/核心体验）
  ├─ 第二部分：世界本体（来源/存在物/现实规则）
  ├─ 第三部分：力量体系（来源/获取方式/代价）
  ├─ 第四部分：地理空间（主要地形/垂直层级/特殊地理）
  ├─ 第五部分：文明与社会（核心价值/冲突/势力类型）
  ├─ 第六部分：历史时间线（长度/关键节点/事件图）
  ├─ 第七部分：视觉设计（关键词/建筑风格/材质偏好）
  ├─ 第八部分：玩法设计DNA（玩家身份/主要行为/成长方式）
  └─ 第九部分：AI生成边界（可生成范围 / 不可改变范围）
  ↓
AI设计顾问分析（实时）
  - 解析每项回答的结构化含义
  - 发现缺失项和逻辑矛盾
  - 追问补充（如：选了"魔法"但未定义"力量来源"）
  ↓
World IP Schema 编译
  ├─ World Identity Card（给制作人看）
  ├─ World Schema（给AI使用）
  ├─ Knowledge Graph（人物/地点/势力/事件）
  ├─ Rule Graph（因果/约束/模拟）
  └─ Asset Generation Rules（给美术）
```

**核心交付物**（厂家可见）：
1. **世界定位卡** (WorldIdentityCard) — 厂家第一眼看到的世界概要
2. **视觉指南** (VisualBible) — "这个世界应该长什么样"
3. **玩法锚点** (GameplayAnchor) — "玩家在这个世界里反复做什么"
4. **设计说明** (DesignNote) — 给策划看的世界设计原理
5. **AI生成边界声明** (GenerationBoundary) — AI可以生成什么 / AI不能改变什么

**后台支撑层**（厂家不可见，AI 内部使用）：
6. **World Schema** — 结构化的世界观数据模型（AI使用）
7. **知识图谱** (KnowledgeGraph) — 人物/地点/势力/事件的交叉关系
8. **规则图谱** (RuleGraph) — 因果/约束/模拟规则引擎
9. **约束体系** (Constraint) — 6维约束 × 6层生成 × 权重矩阵

### 1.3 核心理念

**两个正交的"6"**（后台支撑层内部机制）：

- **6维约束** (ConstraintDimension) — "什么规则"
- **6层生成** (CreationLayer) — "生成什么"

通过 **6×6 权重矩阵** 关联，每个生成维度中 6 维约束的占比不同，权重决定：
- Prompt 占比
- 继承过滤强度  
- 编辑器 UI 优先级

> **注意**: 6×6 体系是 A1 的**内部引擎**，不是面向厂家的交付物。厂家通过问卷填写世界观设计要素，系统在后台将问卷回答编译为 6×6 约束体系驱动的内容。

## 2. 6维约束体系

### 2.1 约束维度枚举

```python
class ConstraintDimension(StrEnum):
    """6维约束维度 — 语义类别。不允许添加或修改。"""
    RED = "RED"  # 内容红线
    LAW = "LAW"  # 物理法则
    ACT = "ACT"  # 行为规则
    NAR = "NAR"  # 叙事约束
    WST = "WST"  # 世界状态
    SOC = "SOC"  # 社交生态
```

### 2.2 维度详细说明

| 维度 | 名称 | 描述 | 数据本质 |
|------|------|------|----------|
| **RED** | 内容红线 | 这个对象不能包含什么（禁止清单） | 禁止的内容条目 |
| **LAW** | 物理法则 | 这个对象服从什么世界规则（重力/魔法体系/科技水平） | 规则函数 |
| **ACT** | 行为规则 | 作用于这个对象的行为怎么判定（技能检定/社交反馈/伤害计算） | 判定逻辑 |
| **NAR** | 叙事约束 | 描述这个对象时遵循什么风格（文风/词汇/氛围/基调） | 风格指令文本 |
| **WST** | 世界状态 | 这个对象携带什么动态状态效果（天气/环境修正/buff/debuff） | 修正值/状态效果 |
| **SOC** | 社交生态 | 这个对象和谁有关系、什么关系（阵营/声望/亲缘/敌对） | 关系边 |

### 2.3 维度输出模型

每个约束维度都有独立的类型化输出模型：

```python
# 简化示例，实际每个维度都有专门的模型
class RedOutput(BaseModel):

    rules: list[str]  # 物理法则列表

    skill_checks: dict[str, int]  # 技能检定DC

# ... (NAR/WST/SOC 类似)
```

|------|------|----------|------------------|
| **WORLD** | 世界观 | 物理法则、魔法体系、科技水平、宇宙规则 | LAW(40%) + SOC(25%) + NAR(15%) |
| **REGION** | 区域文化 | 地理环境、文明特色、文化传统、生态体系 | SOC(35%) + LAW(20%) + WST(15%) |

## 4. 权重矩阵

### 4.1 矩阵结构

**文件位置**: `backend/app/config/weight_matrix.yaml`

**6×6 权重矩阵**（每行和=100）：

```yaml
world:
  RED: 5
  LAW: 40
  ACT: 10
  NAR: 15
  WST: 5
  SOC: 25

region:
  RED: 5
  LAW: 20
  ACT: 10
  NAR: 15
  WST: 15
  SOC: 35

# ... (scene, campaign, npc, asset 类似)
```

### 4.2 权重含义

权重决定三个关键参数：

1. **Prompt 占比** - 高权重的约束维度在 LLM prompt 中占据更多篇幅
2. **继承过滤强度** - 约束沿图谱边传递时的保留概率（≥10%完整传递 / 5-10%压缩为摘要 / <5%不传）
3. **UI 优先级** - 在编辑器界面中的显示顺序和重要性

### 5.2 权重矩阵条目

```python
class WeightMatrixEntry(BaseModel):
    """单个层级的权重分布。"""
    RED: int
    LAW: int
    ACT: int
    NAR: int
    WST: int
    SOC: int
    
    @model_validator(mode='after')
    def validate_sum(self):
        """验证权重和为 100。"""
        if sum([self.RED, self.LAW, self.ACT, 
                self.NAR, self.WST, self.SOC]) != 100:
            raise ValueError("权重和必须为 100")
        return self

class WeightMatrix(BaseModel):
    """6×6 权重矩阵。"""
    world: WeightMatrixEntry
    region: WeightMatrixEntry
    scene: WeightMatrixEntry
    campaign: WeightMatrixEntry
    npc: WeightMatrixEntry
    asset: WeightMatrixEntry
```

## 6. 图谱模型架构

### 6.1 7大图谱模型

| # | 图谱 | 职责 | 节点类型 | 边类型 |
|---|------|------|----------|--------|
| 1 | **KnowledgeGraph** | 核心知识图谱 | GraphNode | GraphEdge (TREE/CROSS) |
| 2 | **StoryGraph** | 跨场景剧情图 | StoryNode | StoryEdge (start/end/choice/event/condition) |
| 3 | **EventGraph** | 动态事件图 | EventNode | Trigger (time/location/state) |
| 4 | **CultureTree** | 文化层级树 | CultureNode | 递归 parent-child |
| 5 | **ConstraintTree** | 约束层级树 | ConstraintNode | HARD/SOFT 继承 |
| 6 | **SceneGraph** | 场景依赖图 | SceneNode | 空间依赖 |
| 7 | **PuzzleGraph** | 谜题求解图 | PuzzleNode | 依赖求解 |

### 6.2 KnowledgeGraph 核心模型

```python
class GraphNode(BaseModel):
    """知识图谱节点。"""
    id: str
    serial_number: str      # 层级序号 "1-1-1"
    level: int              # 深度层级
    description: str        # 视觉描述
    status: NodeStatus      # pending/generating/completed/failed

class GraphEdge(BaseModel):
    """知识图谱边。"""
    from_node_id: str
    to_node_id: str
    edge_type: EdgeType     # TREE (层级) / CROSS (交叉)
    visual_description: str # 关系描述

class KnowledgeGraph(BaseModel):
    """场景知识图谱。"""
    scene_id: str
    nodes: dict[str, GraphNode]
    edges: list[GraphEdge]
    background_node_id: str | None  # 根节点 ID
```

### 6.3 图谱查询能力

- **层级解析**: `parse_level(serial_number)` → `level`
- **依赖查询**: `get_dependencies(node_id)` → 父节点列表
- **环检测**: Kahn 算法验证无环图
- **拓扑排序**: `get_generation_waves()` → Wave 串行生成顺序

### 6.4 知识图谱结构层级与阶段产出

> **核心原则**: A1 建立**结构拓扑**（节点 + 边 = 不可覆写常量），A2/A3 在拓扑内**填充细节**（可扩展变量）。**边是结构常量，节点是阶段变量。**

#### 6.4.1 "骨架级"语义澄清

"骨架级 KG"是模糊说法。准确表述见下表：

| 错误理解 | 正确表述 |
|---------|---------|
| "骨架级" = 节点少 | "骨架级" = 结构拓扑（节点 + 边），边是不可覆写的结构常量 |
| A1 产出"简化的图谱" | A1 产出"结构拓扑"——节点数量不是关键，**边的语义定义**才是 |
| A2/A3 "完善"图谱 | A2/A3 在 A1 拓扑内**追加细节节点**，不可新建/删除/修改 A1 的结构边 |

> **结论**: 不要用"骨架级"这个词。用"**结构拓扑**"——A1 建立节点 + 边的拓扑结构，边是不可覆写的结构常量。

#### 6.4.2 A1 阶段产出 — 结构拓扑骨架

| 产出物 | 内容 | 属性 |
|--------|------|------|
| **骨架节点** | Geography / Faction / Event / Concept / Constraint（5 种实体） | `detail_level=CONCEPT`，`source_stage="A1"`，创建后不可变 |
| **结构拓扑边** | 第 1-4 类边（见 `3_knowledge-assets.md` §5 边类型词典 v0.1，共 15 种） | 不可覆写常量——A2/A3 不可新建/删除/修改 |
| **A1 独有边** | 第 2 类全部（3 种因果链）+ 第 1 类 `GEO_ABOVE`/`GEO_BELOW`（2 种垂直层级）+ 第 4 类 `CONCEPT_MANIFESTS_AS`（1 种概念具现）= **6 种仅 A1 可建** | 表达世界规则在空间维度的投影，A2/A3 不重新定义世界规则 |

**A1 独有边的语义依据**:

| 边类型 | 为何仅 A1 |
|--------|----------|
| `RULE_SHAPES_GEO` / `POWER_SATURATES_GEO` / `POWER_SOURCES_FROM_GEO`（第 2 类） | 因果链——世界规则如何塑造地形，A2/A3 不重新定义世界规则 |
| `GEO_ABOVE` / `GEO_BELOW`（第 1 类垂直层级） | 垂直层级（天空层/地下世界）是世界规则在空间维度的投影，属于结构拓扑而非地名标签 |
| `CONCEPT_MANIFESTS_AS`（第 4 类） | 概念具现——抽象力量体系如何具现为地理实体，A2/A3 不重新定义力量体系 |

**数据来源**:
- **Geography**: 问卷模块 4（地理空间）显式提取 — 主要地形/垂直层级/特殊地理，AI 设计顾问结合模块 2（世界本体）+ 模块 3（力量体系）推导 shaping_rules / power_sources 关联
- **Faction / Event**: 问卷模块 5（文明与社会）/ 模块 6（历史时间线）显式提取
- **Concept**: 问卷模块 2（世界本体）+ 模块 3（力量体系）显式提取
- **Constraint**: 问卷模块 9（AI 生成边界）+ 6 维约束体系编译

**边为何不可覆写**:
- A1 的边表达的是**世界规则因果链与结构投影**（如"高重力→扁平大陆"、"天空层→地表"）
- A2/A3 不重新定义世界规则，只能在已有拓扑内追加细节节点
- 这是 A1 作为"世界观 IP 立项"阶段的独有价值——结构常量一旦确立，后续阶段在结构内填充内容

#### 6.4.3 A2 阶段产出 — 区域文化填充

| 产出物 | 内容 | 属性 |
|--------|------|------|
| **填充节点** | Culture（文化体） | `detail_level=REGIONAL`，`source_stage="A2"`，创建后不可变 |
| **填充边** | 第 5 类 `CULTURE_INFLUENCES`（A2+） | 可扩展变量——A2 可新建 |
| **拓扑扩展** | 沿 A1 的 `GEO_CONTAINS` / `GEO_NOURISHES` 等边下挂文化体节点 | 不修改 A1 边，只追加 A2 节点 |

**约束**:
- 只能在 A1 已有拓扑内追加，**不可新建 A1 结构边**（第 1-4 类）
- 不可修改 A1 节点的 `detail_level` / `source_stage`（创建后不可变）
- 文化体通过 `region_geo_id` 关联到 A1 的 Geography 节点

#### 6.4.4 A3 阶段产出 — 具体实体填充

| 产出物 | 内容 | 属性 |
|--------|------|------|
| **填充节点** | Character / Item / Scene（3 种实体） | `detail_level=SCENE`，`source_stage="A3"`，创建后不可变 |
| **填充边** | 第 5 类 `CHAR_BELONGS_TO` / `CHAR_LOCATED_AT` / `ITEM_OWNED_BY` / `ITEM_LOCATED_AT` / `EVENT_INVOLVES_CHAR`（A3+） | 可扩展变量——A3 可新建 |
| **拓扑扩展** | 沿 A1/A2 的边下挂具体实体节点 | 不修改 A1/A2 边，只追加 A3 节点 |

**约束**:
- 只能在 A2 区域拓扑内追加，**不可新建 A1/A2 结构边**
- Character 通过 `culture_id`（A2）/ `faction_id`（A1）关联到上游节点
- Scene 通过 `parent_geo_id` 沿 `GEO_CONTAINS` 边下挂到 A1 的 Geography 节点
- Item 通过 `location_geo_id` 关联到 A1 的 Geography 节点

#### 6.4.5 阶段产出总览

```
A1（结构拓扑骨架）
  ├─ 节点: Geography / Faction / Event / Concept / Constraint（5 种）
  ├─ 边:   第 1-4 类（共 15 种结构拓扑边，不可覆写常量）
  │        ├─ 仅 A1（6 种）: 第 2 类因果链 + GEO_ABOVE/BELOW + CONCEPT_MANIFESTS_AS
  │        └─ A1+（9 种）:   第 1 类 GEO_CONTAINS/BORDERS + 第 3 类全部 + 第 4 类其余
  └─ 来源: 专业问卷（8 大模块）+ AI 设计顾问推理 + 厂家确认
      ↓
A2（区域文化填充）
  ├─ 节点: Culture（在 A1 Geography/Faction 拓扑内）
  ├─ 边:   第 5 类 CULTURE_INFLUENCES（A2+，可扩展）
  └─ 约束: 不可新建 A1 结构边，只追加 A2 节点
      ↓
A3（具体实体填充）
  ├─ 节点: Character / Item / Scene（在 A2 区域拓扑内）
  ├─ 边:   第 5 类 CHAR_BELONGS_TO 等 5 种（A3+，可扩展）

```

## 9. 当前开发断点

### ⚠️ 核心断点 (阻塞管线)

#### 断点 A: 权重规则化生成

**问题**: 权重矩阵是硬编码静态表，无法根据种子概念动态调整。

**现状**: 
- `DimensionGenerator.generate()` → 直接读静态 YAML
- 所有种子在同一层级拿到相同权重分配
- "战斗型 NPC" 和 "外交型 NPC" 在 NPC 层都拿到 SOC=30%/ACT=25%

**需要**:
1. LLM 规则化权重生成器 — 根据种子特征动态调整
2. 权重安全机制 — 偏移警告 + 冲突检测
3. 权重缓存 — 相似种子复用

#### 断点 B: 递归生成深化

**问题**: `backward_generate()` 是单跳推理，不会用生成结果作为新种子展开下一层。

**现状**:
- 种子 "水晶祭坛" → 单轮生成 story/event/culture/constraint → 结束
- 不会递归展开更深层级

**需要**:
1. 递归深化引擎 — 生成结果作为新种子迭代
2. 深度控制 — 最大深度 / 最小粒度 / token 预算
3. 循环引用检测 — 防止 A→B→A 无限递归
4. 结果汇聚 — 多层生成合并为展开树

#### 断点 B2: 种子五维 → 六维

**问题**: `concept.py` 定义 `FIVE_DIMENSIONS` (story/asset/event/culture/constraint)，缺 **Scene** 和 **NPC**。

**现状**:
- `CreationLayer` 有全部 6 层
- 种子引擎只有 5 个 slot
- `backward_generator.py` 只有 5×4=20 个方向模板

**需要**:
1. `FIVE_DIMENSIONS` → `SIX_DIMENSIONS`
2. `backward_generator.py` 扩展到 6×5=30 个方向模板
3. `gap_detector.py` 同步扩展

### 🔧 集成断点 (模块间打通)

#### 断点 C: 6维约束 → Prompt 注入

**问题**: 约束结果尚未注入到 PromptBuilder / PromptFusion。

**需要**: PromptFusion 升级为权重感知组装器。

#### 断点 D: 生成结果拆分 → 图谱写入

**问题**: SeedEngine/DimensionGenerator 的输出不会自动写入各图模型。

**需要**: 生成结果 → 结构化分发器 → 写入图模型 → 持久化。

#### 断点 E: 图谱-树联系 (WorldKG overlay)

**问题**: 五图保持独立，缺少 overlay 交叉边层。

**需要**: 新建 `world_kg_overlay.py`、`constraint_inheritor.py`。

#### 断点 F: 约束继承传递

**问题**: 约束沿图谱边按权重过滤传递未实现。

**设计**: ≥10%完整传递 / 5-10%压缩为摘要 / <5%不传。

### 🔧 功能断点

#### 断点 G: RED 硬编码拦截器

**问题**: 资产生成前没有实际过滤禁止内容的拦截器。

**需要**: 新建 `red_filter.py`（系统级红线拒绝 / 世界观红线提示）。

#### 断点 H: 其余图层级 API + 前端编辑器

**问题**: 只有 KnowledgeGraph 有完整 API + 编辑器。

**需要**: StoryGraph / EventGraph / CultureTree / ConstraintTree / SceneGraph 的 CRUD + 编辑器。

#### 断点 I: 前端对接 + 持久化

**问题**: GraphAssetReview 使用 Mock 数据，GenerationScheduler 结果未持久化。

**需要**: 去Mock + 图谱列表API + 生成结果持久化。

## 附录B: 设计决策记录

### B.1 为什么使用6×6权重矩阵？

**决策**: 每个生成维度对6种约束维度有不同的重要性权重。

**原因**:
1. 世界观层更重视物理法则 (LAW) 和社交生态 (SOC)
2. 场景层更重视叙事约束 (NAR) 和世界状态 (WST)
3. NPC 层更重视社交生态 (SOC) 和行为规则 (ACT)

### B.2 为什么种子引擎当前是五维？

**历史原因**: 早期设计只考虑了 story/asset/event/culture/constraint 五个维度。

**设计缺口**: 系统设计需要6个生成维度，当前缺 Scene 和 NPC。

**影响**: `backward_generator.py` 只有 20 个方向模板，补全后需要 30 个。

### B.3 为什么使用 Wave 串行生成？

**决策**: 同一波内节点并行生成，波间串行等待。

**原因**:
1. 确保依赖节点的资产生成完成后再生成下游节点
2. PromptFusion 需要访问已生成节点的图像描述
3. 避免无效的重复生成
