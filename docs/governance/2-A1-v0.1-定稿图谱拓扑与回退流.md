# 2-A1 定稿知识图谱：拓扑设计与回退流 v0.1

> **定位**：A1 世界观工坊「定稿 → 知识图谱 → 展板」环节的**拓扑构建规范 + 前端呈现契约 + 回退流契约**。
> **生效代码**：`backend/app/api/a1_routes.py::_build_graph`、`backend/app/domains/creation/graph/constraint_topology.py`、`frontend/src/components/graph/A1KnowledgeGraph.tsx`、`frontend/src/pages/a1/A1Workspace.tsx`、`frontend/src/pages/a1/IPPoster.tsx`（2026-08-27 实现，131 后端单测 + 32 前端单测通过）。

---

## 0. 一句话

定稿图谱是**"设定驱动、工程骨架、约束标注"**的三源混合拓扑：骨架是问题树的确定性投影（工程），节点内容与图谱形状由用户访谈答案决定（设定），唯一语义边来自 6 维约束注入规则（约束体系）；**不从故事出发**——实体关系与叙事因果留给后续 StoryGraph/EventGraph 阶段。

---

## 1. 设计立场：初始拓扑从哪里来

| 拓扑成分 | 来源 | 性质 | 确定性 |
|---------|------|------|--------|
| L1→L2→L3 层级 + TREE 边 | **工程**（A1 问题树 10模块×子字段的结构投影） | 行政性包含（"档案怎么组织"），非语义关联（"世界里什么相关"） | 100% 确定性、幂等、可单测 |
| 节点集合与内容 | **设定**（用户访谈答案） | 图谱形状随设定生长：空模块不出现、答得多则条目多；图谱是设定的形状镜像 | 随用户输入 |
| L0 约束节点 + CROSS 边 | **约束体系**（`application_tree.yaml` 注入规则 → `RULE_*` 语义标签） | "6 维约束如何作用于世界"的拓扑（如 `RULE_SHAPES_GEO` 约束塑造地理） | 规则映射，确定性 |
| 实体-关系边 / 因果链 | **故事**（未参与） | ❌ 当前版本不存在 | — |

### 为什么不从故事出发（设计权衡）

1. **A1 阶段的产物是设定档案，不是叙事**。定稿时刻的数据只有结构化问答（`module.subfield → value`），实体识别与关系抽取尚未发生——没有"人物A 敌对 势力B"这类素材的可靠来源。
2. **定稿产物必须可靠**。问题树投影是纯函数：同样答案必然产出同样图谱，可精确断言（见测试 `test_finalize_graph_topology`）。若在定稿时刻自动跑 LLM 实体关系抽取，噪声语义会混进"已定稿"资产，且重定稿 v2 时可能产生不稳定 diff。
3. **语义拓扑已有归宿**：StoryGraph / EventGraph 数据模型已建（断点 D/H），管线后续接入；文本→图谱的 LLM 提取器也已存在（`/api/graph/extract`）可复用（见 §6 演进）。

## 2. 拓扑结构规范

### 2.1 层级与节点

| 层 | 节点类型 | id 规范 | serial_number | description | 生成规则 |
|----|---------|---------|---------------|-------------|---------|
| L0 | 约束节点 | `cst_{DIM}_{tag}`（如 `cst_LAW_world_structure`） | 同 id | `[A1] Constraint(DIM.tag=value)` | `apply_constraints` 从 6 维结构化字段创建，仅限 `STRUCTURED_FIELDS` 白名单 21 字段 |
| L1 | 世界背景（根） | `bg_{session_id[:8]}` | `"0"` | `[{IP_CODE}] 世界背景` | 每次定稿必建，即 `background_node_id` |
| L2 | 模块板块 | `{module_id}`（问题树模块 id） | `"N"`（N=第 N 个有答案的模块，从 1 起） | 模块 label（**不聚合**子字段内容） | 仅当该模块 ≥1 个子字段有非空答案 |
| L3 | 设定条目 | `{module_id}.{subfield_id}` | `"N-M"` | `{子字段label}: {答案原文}` | 每个非空答案一条目；id 与 `session.answers` key 同构 |

要点：**条目 id = answers key**。这保证了"设定条目化"的双向可追溯——从图谱节点能直接定位到问卷字段，从答案能直接推出节点。

### 2.2 边语义

| 边 | 方向 | edge_type | visual_description | 含义 |
|----|------|-----------|--------------------|------|
| 包含 | L1 → L2 | `TREE` | `"包含"` | 世界背景下辖模块 |
| 条目 | L2 → L3 | `TREE` | `"条目"` | 模块下辖设定条目 |
| 约束注入 | L0 → L1 | `CROSS` | `"A1 \| RULE_*"`（如 `A1 \| RULE_SHAPES_GEO`） | 该约束维度字段如何塑造世界（标签来自 `application_tree.yaml` 的 `source_field → target_edge_type` 映射，无映射则只建节点不建边） |

- `edge_type` 枚举仅 `TREE`/`CROSS` 两个合法值（`EdgeType`，**不允许扩充**）；`RULE_*` 语义标签存放在 `visual_description`，这是既有约定（断点 T-F）。
- TREE 边总数恒等于 **模块数 + 条目数**（可作不变量断言）。

### 2.3 构建算法（`_build_graph`，纯函数）

```
输入: session(answers, ip_code, session_id)
1. 建 bg 节点(L1)
2. 遍历 MODULES(10个模块):
   a. 收集非空答案子字段 → 空模块跳过(不建节点)
   b. 建模块节点(L2, serial=N) + TREE边 bg→模块("包含")
   c. 逐个非空答案: 建条目节点(L3, serial=N-M, id=module.sub) + TREE边 模块→条目("条目")
3. apply_constraints(graph, 6维结构化结果, stage="A1"):  追加 L0 节点 + CROSS 边(幂等)
输出: KnowledgeGraph → 存入 file_rec["graph_json"]
```

- **幂等性**：`apply_constraints` 对已存在节点/边跳过；`_build_graph` 每次定稿全量重建 graph_json。
- **版本与陈旧标记**：定稿签发 `{IP}-W{instance}-v{version}` 图谱编码；重定稿 → 版本 +1，旧版本保留不删，`stale_marker.mark_downstream_stale` 向下游（A2+）传播陈旧标记。

### 2.4 生命周期与数据依赖

```
chat 写入 file_diff ──► file.status = draft（定稿作废，graph 接口随即 409）
finalize（每模块 >50% 子字段已答）──► status = finalized + graph_json 重建 + 编码升版
GET /api/a1/file/{id}/graph ──► 仅 finalized 可读，否则 409 pending_finalize
```

## 3. 前端呈现契约（graph_view）

定稿后工坊进入 `graph_view` 阶段（取代旧 `poster_view`，localStorage 旧值自动迁移）：

- **双 Tab**：「知识图谱」（默认）/「展板预览」（复用 PosterPreview）。
- **布局**（`A1KnowledgeGraph`，React Flow 只读）：层级带状——L0 约束 y=-260 / L1 背景 y=0 / L2 模块 y=240（间距 280）/ L3 条目 y=500（间距 170，**按父模块分组对齐在其 x 下方**，父节点从 TREE 边推断）。
- **视觉编码**：L1 金色边框（✦）/ L2 紫色边框（▤）/ L3 细白边（·，"label: value" 拆分展示）/ L0 琥珀边框（⚙，解析 `Constraint(DIM.tag=value)`）；TREE 实线紫 `#a78bfa` 无标签，CROSS 琥珀虚线 `#f59e0b` 带 `RULE_*` 标签。附图例。
- **交互**：只读（禁拖拽/连线/选中），允许平移缩放（fitView，0.2~1.5x）+ MiniMap。
- **409 语义**：图谱 Tab 收到 `pending_finalize` 时提示"设定已修改回草稿，请重新定稿后查看图谱"并引导返回引导页——与 §2.4 生命周期闭环。

## 4. 回退流契约（单步直达 + 完整恢复）

**铁律：任何下游展示页回退，一步直达 LLM 引导页，且会话状态完整可继续深化。**

```
seed_selector → guided_chat → [finalize] → graph_view → /a1/poster
                     ▲                │           │
                     └────────────────┴───────────┘   一键回退（不再是两段式）
```

| 机制 | 实现 |
|------|------|
| 展板页回退 | IPPoster「返回世界观工坊（继续深化）」→ 写 `localStorage['a1_return_intent']='chat'` → 跳 `/a1` |
| 意图消费 | A1Workspace 初始化读到 intent 且有 sessionId → 直接进 `guided_chat`；挂载时删除该键 |
| 完整恢复（水合） | 挂载/finalize/回退时 `GET /api/a1/file/{id}` 重建：文件面板（sections）、板块进度、finalizable（每模块 >50% 规则）、graph_code；**messages 本就持久化，不丢** |
| 继续深化 | 回到 guided_chat 后继续对话 → 后端写入即打回 draft → 可再次定稿 → 图谱 v2 |
| 状态迁移 | 旧 `poster_view` 持久化值 → `graph_view`（读档时字符串级迁移） |

## 5. 已知局限（诚实清单）

1. **TREE 边是行政拓扑**——反映档案组织结构，不是世界观内实体间的语义关联。真正的"知识图谱感"（谁 RelatedTo 谁、因果、从属）需要 §6 演进。
2. **约束 CROSS 边只指向 L1 背景**，尚未细化到"约束作用于哪个模块/条目"（application_tree 的层级映射取了 world 层首条规则）。
3. `GraphViewContent`/`A1GraphSection` 为组件内嵌套定义，父级 re-render 会重挂载导致图谱重复 GET（幂等无害，待重构提级）。
4. LLM 关系抽取未接入定稿管线（刻意，见 §1 权衡）。

## 6. 演进方向（语义拓扑补全路径）

1. **复用 `/api/graph/extract`**：对 L3 条目 description 批量做 LLM 实体-关系抽取，产出语义边（标注 `source=A1.extract`，与确定性 TREE/CROSS 边区分置信级别）。
2. **问题树加"关系类"子字段**：访谈中显式问"X 与 Y 的关系"，答案天然结构化为边（确定性优先，与 §1 立场一致）。
3. **约束边下沉**：`apply_constraints` 支持按 application_tree 层级规则把 CROSS 边指向具体 L2/L3 节点（如 `RULE_SHAPES_GEO` → 地理模块）。
4. **接 StoryGraph/EventGraph**：A2 阶段以本图谱为输入展开叙事拓扑（断点 D/H）。
