## 1. 产品骨架重述

### 1.1 旧骨架为何退役

v5 时代的产品叙事是三阶段固定流水线：**A1 工坊（10 模块世界观访谈 + 图谱）→ A2（模组产出）→ A3（内容生产）**。用户先走完 10 个世界建构模块，才能进入产出。

这套骨架在真实故事型用户面前崩塌（D14 触发证据）：E1-Lite 上线当日，真实故事向用户访谈全程翻车——只想写剧情的用户被迫回答"势力类型"，偏转被无视重问、剧情细节被误判为主剧情修改提案、降级建议聋。E1-Lite 已证明类型驱动的模块前移（置换）只能缓解、不能根治：**全集始终在那里**，门禁在查、prompt 在列、图谱在校验。这不是 prompt 调优能救的问题，是骨架问题。

证据全文：`.sisyphus/evidence/jia-requirement-evidence-interview-failure.md`；技术路线三路挖掘：`.sisyphus/evidence/a2-plan-mining-*.md`。

### 1.2 新骨架一段话

**所有模块进一个池子（模块池），用户入场时按冲动类型领一张配方（有序模块子集），访谈引擎沿配方线性游走，产出模块按需触发。** 默认配方 = 原 10 模块全集，设定型用户体验逐字节不变。路由差异全部下沉为**数据**（配方表），代码里只有一份 prompt 骨架、一个游标、一套门禁——"差异是数据不是代码"（R2）在架构层的兑现。

继续有效的产品定位（与阶段无关）：AI 辅助的世界 IP 工业化生产工具；"专业问卷 + AI 设计顾问 + 自动结构化"核心理念不变。平台外圈（社区 B / 商业 C / 多端 D / 反馈 E）不受本次重组影响。

## 2. 五层架构总览

```
┌──────────────────────────────────────────────────────┐
│ 入口层    ImpulseCards（冲动卡）· Workspace           │ 用户入场 → 冲动类型落定配方
├──────────────────────────────────────────────────────┤
│ 路由层    module_registry  ★唯一新增                  │ get_recipe() 查表，真相源唯一
├──────────────────────────────────────────────────────┤
│ 模块执行层                                            │
│   访谈模块：现有访谈引擎（参数化，按配方渲染）        │
│   产出模块：主模组文字版 / 骰子投影 / 角色投影        │ ← A2 资产平移入池
├──────────────────────────────────────────────────────┤
│ 管线层    graphify + 确定性编译（零架构变化）         │ NL → SIR → KG 三铁律不变
├──────────────────────────────────────────────────────┤
│ 基础层    store（schema v2）/ 护栏 / 发号（机制不变） │
└──────────────────────────────────────────────────────┘
```

五层详图、运行时调用时序、单文件数据流：见 [[2026-09-22-jia-modular-architecture-design]] §1（架构模块图 / 一次故事型会话的生命周期 / 数据流三张图），本文不复制。

要点：路由层 `module_registry` 是唯一新增的真相源；执行层访谈侧复用现有引擎（参数化），产出侧平移 A2 资产；管线与基础层零架构变化。

## 3. 模块池三族

所有模块同池不同族（family）：

| 族 | 数量 | 成员 | 来源 |
|---|---|---|---|
| **worldbuilding 世界建构** | 10 | 原 10 个问卷模块全集 | v5 A1 原样入池 |
| **story 故事** | 2 | M11 角色 / M12 剧情（2026-09-22 重锚定定版；情感线并入 M12 场景化 + M10 爱情 preset） | 甲详细设计 §6.2 + 模块清单拓展文档 |
| **output 产出** | 8 | L2×5：主模组文字版/骰子投影/角色投影/玩法设计完整形态/商业分析报告(R)；L3×3：场景扩写/资产管线/叙事渲染 | A2 资产平移 + A3 遗迹复活（代码模块设计 §2.4） |

池封闭原则：`module_ids` 内的每个 id 必须存在于 `MODULE_POOL`，无幻影模块（[[SYSTEM_DESIGN_SPEC_v6]] §2.2）。

## 4. 8+2 冲动 × 通道

一句话：**每类冲动一张有序配方，default = 原全集**。9 条配方 = 8 冲动型 + default；另有 2 条**通道**（2026-09-22 重锚定：撤销 exploration 冲动行）。

| 配方 | 一句话画像 | 兑现物 |
|---|---|---|
| default | 原 10 模块原序，设定型体验逐字节不变 | 通用图谱 |
| plot | M12 剧情开场打头，历史退背景，节奏导向 | 开场叙事（DN5） |
| romance | M11 双人关系卡打头，携带 content_guard | 双人速写卡 + guard |
| character_driven | M11 属性卡打头，命运导向 | 速写卡文本版 |
| philosophy | 世界公理优先，追问违反后果 | 公理卡 |
| setting_heavy | 视觉提前 + 近全集，机制自洽 | 种子详情页 |
| unsure（通用线） | 故事侧默认剧情（D13 裁决延续） | 推断包 + 迁移 |
| nostalgia | default 序 + 上传预填为主，风格保真 | 预填确认页 |
| healing | 最小子集 + 大 ai_fill，陪伴低压力 | 种子直达 |
| 通道：探索态 | 着陆状态非冲动，B 类合规能力演示 | 导入 8 类 |
| 通道：玩法设计链 | 设定-重度变体 + 目的地 flag 下游产线 | 载体分支完整形态 |

**完整矩阵**（模块子集 / 首问 / 锚点要点 / ai_fill 范围 / guard）：权威版本 = [[2026-09-22-jia-modular-architecture-design]] §3.1，此处不复制。

三条优先级语义（摘要，全条见详细设计 §3.2）：①**序即优先**——一个序贯穿全链，无第二套优先级；②**子集即边界**——配方外模块对该会话不存在（门禁不查、prompt 不列、图谱不校验）；③**动态可调三杠杆**（E2 坐标层预留）——已访内容与配方边界永不动。

> ⚠️ 世界建构子集裁剪与序为 **DN6 初稿**，待产品终审。配方边界会话内不可变（`POST /session/start` 一次性落定 `recipe_id` 与 `recipe_modules`）。

## 7. 系统边界（模块池视角）

- **访谈引擎**：沿配方线性游走（游标模型不变，R6 只前移不跳过）；偏转 → 占位推进（J1 保门禁不被占位污染）；素材槽不进 answers / 门禁 / graphify
- **产出模块**：仅用户显式触发，永不自动触发；上游只读（文件永不回写 W 图谱）；required 信号缺 → 409 `upstream_missing`；stale 永不阻断，只标记 + ledger 披露（v6 §2.4）
- **图谱全景**：W 图由 graphify + 确定性编译产出；M/TD/TC/S（场景图）各自独立发号独立图谱，血缘单向指向上游（M/TD/TC → W，S → M；D15）；W 变更只做 stale 标记，永不删除、永不静默重算（v6 §2.8）
