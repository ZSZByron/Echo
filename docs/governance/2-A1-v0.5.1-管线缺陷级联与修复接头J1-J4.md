# 2-A1-v0.5.1 · 管线缺陷级联与修复接头 J1-J4

- 日期：2026-09-11
- 依据：docs/plans/2026-09-09-a1-extreme-testing-design.md §7 Mock 层证据 + §8 真跑层证据（xt 极限实验套件，12 用例 + borderline ×10 统计）
- 状态：direction-approved（用户确认系统性梳理方向，待逐接头排期）
- 定位：v0.5 系列缺陷治理附录——不动 v0.5 统一模型本体，为 J1-J4 修复预留契约接口；J2 涉及 id 不变量，落地时需 v0.6 评审
- 原则：模块级设计选择各有优缺点，不可消灭只能换着承担——修复方式是**留接头**，不是打补丁

## 1. 四条级联链（8 个确诊 bug 的根因聚类）

### 级联 A「真值链」
```
parse_modules 三态漂移（"未提及"占位值，truthy）
  → 门禁只查 key 存在（is_module_over_half）
  → 占位值放行 → graphify 把占位当"用户已确定内容"全文嵌入
  → 空壳图谱照样 finalize 成功
```
症候：#8 占位值门禁（Mock 确诊）+ 统计层②双头违规 + 35 vs 34 的计数层。

### 级联 B「方差链」
```
LLM 内容方差（显式字段改写 / 标题漂移）
  → 内容锚定 id 跟着漂（d:{anchor}:{sanitize(title)}）
  → 边匹配键 = from/to/relation 三元组精确比对 → 断裂
  → confirmed 边坠 dead_edges，同语义新边以未确认状态复活
```
症候：#12 重定稿断链（Mock 确诊）+ #7 边蒸发 + 统计层③④（31/35 字段值级方差）。

### 级联 C「截断链」
```
各层自我保护式丢弃（20000 字截断 / cap=10 / 32 字标题截断 / dedupe）
  → 警告各写各的（assemble_warnings / finalize_warnings / dead_edges / llm_result.warning）
  → 有的落库有的蒸发（警告链断裂：graphify 层边丢弃警告无持久化痕迹）
```
症候：#2 截断失忆 + #4 专名 cap 无披露 + #7 边层静默。

### 级联 D「无护栏链」
```
超长输入无预算（答案值无上限 / convert 全文直灌 / 35×5000 答案炸弹）
  → 单点 JSON store（损坏即全蒸发、写放大）
```
症候：#6 答案炸弹 + #3 convert 不截断 + #10 store 蒸发。

## 2. 模块设计权衡表

| 设计选择 | 优点 | 缺点（实验确诊） |
|---------|------|----------------|
| 门禁 = key 存在性 | 确定、简单、LLM 操纵不了 | 不辨真值：占位值/空串放行 |
| 内容锚定 id | 理论跨版本稳定、无需中央序号 | 对内容方差敏感：一字漂移即断链 |
| 硬截断（2万字/cap10/32字） | 成本确定、保护下游 | 丢什么不说（弱披露或无披露） |
| LLM 自由填表 | 任意文体可解析 | 无锚点 → 三态漂移 + 值级方差 |
| 降级哲学（never crash） | 管线极强壮 | 降级太安静："成功"掩盖空壳 |

## 3. 四个修复接头

### J1 答案真值闸（治级联 A）
- **位置**：parse_modules / interviewer fills 的统一出口（一个 canonical 函数）
- **规则**：占位词典（未提及/未明确/未知/缺少依据/N/A 等变体）+ 空串 → 不写入 answers
- **新缺点**：词典法漏新变体；不采用 LLM 判真值（会再引入方差）；漏网由 J3 兜底可见
- **改动面**：1 个新函数 + 2 个调用点 + 测试

### J2 规范化层（治级联 B，契约级）
- **位置**：id 铸造（sanitize_title/depth_id）前 + 边匹配（_make_edge_key）前
- **规则**：prompt 要求显式字段逐字摘录；标题超 32 字 → 警告并要求缩短（不静默截断）；端点匹配前先过 canonical 形式
- **边界**：不做 fuzzy 自动合并（会误合并不同条目），只做检测 + 披露
- **风险**：动 v0.5 治理文档钦定的 id 不变量 → 需"双侧签字 + 集成测试"流程，单独设计评审
- **改动面**：graphify.py + a1_routes.py 装配层 + 治理文档修订

### J3 披露协议 / warning ledger（治级联 C）
- **位置**：所有丢弃点的统一出口
- **规则**：四处 warnings（assemble/finalize/dead_edges/graphify 层）合并为一个结构化 ledger 落 `file_rec["warnings"]`（source/detail/count/level），前端出角标
- **新缺点**：警告疲劳 → 需分级（warn/info）
- **改动面**：a1_routes.py 警告汇集 + get_file 响应 + 前端角标位

### J4 预算护栏（治级联 D）
- **位置**：各写入入口
- **规则**：answer value ≤2000 字（超限截断+J3 披露）；convert 输入 ≤20000；graphify prompt 总长预算；store 备份轮转（保留 N 份历史快照）
- **新缺点**：截断丢内容 → 必须配 J3 才成立
- **改动面**：worldview_upload.py / interviewer.py / store.py + 常量配置

## 4. 实施顺序（整体最优 = 杠杆率排序）

```
J1 → J3 → J4 → J2
```

- **J1 先行**：最小改动 × 最大杠杆——一个函数闭环整条真值级联，同时兑现统计层实验结论
- **J3 次之**：把所有残余的"看不见的丢失"变成"看得见的降级"——B 类 bug 从此降级为可观察行为
- **J4 便宜保险**：纯防御，无契约牵动
- **J2 压轴**：爆炸半径最大（id 契约 + 治理文档 + 前端渲染回退联动），必须走正式设计评审

## 5. 与 xt 实验套件的闭环关系

每个接头落地后，对应 xt 用例的断言从"记录病理行为"翻转为"断言期望行为"：
- J1 落地 → test_e2 占位值门禁用例改断言 `is_finalizable(占位answers) is False`
- J2 落地 → test_e3 层3 断言边丢失进 ledger；test_e5 断言 confirmed 状态跨 canonical 匹配延续
- J3 落地 → 全部"警告不存在"断言翻转为"警告在 ledger 中"
- J4 落地 → test_e2 炸弹用例断言 prompt 被预算截断 + 披露存在

xt 套件位置：`backend/tests/xt/`（marker=xt）；真跑器：`scripts/xt/real_run.py`（borderline 语料复验跨轮稳定性）。
