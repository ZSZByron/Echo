# 2-A1-v0.5.1 · 管线缺陷级联与修复接头 J1-J4

- 日期：2026-09-11
- 依据：docs/plans/2026-09-09-a1-extreme-testing-design.md §7 Mock 层证据 + §8 真跑层证据（xt 极限实验套件，12 用例 + borderline ×10 统计）
- 状态：**J1/J3/J4 已落地**（2026-09-11，全量 1032/1032 通过，xt e1/e2/e3 闭环翻转——除 J2 范围外全部病理断言已翻转为期望行为）；J2 待排期（动 id 不变量，落地需 v0.6 评审）
- 定位：v0.5 系列缺陷治理附录——不动 v0.5 统一模型本体，为 J1-J4 修复预留契约接口；J2 涉及 id 不变量，落地时需 v0.6 评审
- 原则：模块级设计选择各有优缺点，不可消灭只能换着承担——修复方式是**留接头**，不是打补丁

## 1. 四条级联链（8 个确诊 bug 的根因聚类）

### 级联 A「真值链」
```
parse_modules 三态漂移（"未提及"占位值，truthy）
  → 门禁只查 key 存在（is_module_over_half）
  → 占位值放行 → graphify 把占位当"用户已确定内容"全文嵌入
  → 空壳图谱照样 finalize 成功
```
症候：#8 占位值门禁（Mock 确诊）+ 统计层②双头违规 + 35 vs 34 的计数层。

### 级联 B「方差链」
```
LLM 内容方差（显式字段改写 / 标题漂移）
  → 内容锚定 id 跟着漂（d:{anchor}:{sanitize(title)}）
  → 边匹配键 = from/to/relation 三元组精确比对 → 断裂
  → confirmed 边坠 dead_edges，同语义新边以未确认状态复活
```
症候：#12 重定稿断链（Mock 确诊）+ #7 边蒸发 + 统计层③④（31/35 字段值级方差）。

### 级联 C「截断链」
```
各层自我保护式丢弃（20000 字截断 / cap=10 / 32 字标题截断 / dedupe）
  → 警告各写各的（assemble_warnings / finalize_warnings / dead_edges / llm_result.warning）
  → 有的落库有的蒸发（警告链断裂：graphify 层边丢弃警告无持久化痕迹）
```
症候：#2 截断失忆 + #4 专名 cap 无披露 + #7 边层静默。

### 级联 D「无护栏链」
```
超长输入无预算（答案值无上限 / convert 全文直灌 / 35×5000 答案炸弹）
  → 单点 JSON store（损坏即全蒸发、写放大）
```
症候：#6 答案炸弹 + #3 convert 不截断 + #10 store 蒸发。

## 2. 模块设计权衡表

| 设计选择 | 优点 | 缺点（实验确诊） |
|---------|------|----------------|
| 门禁 = key 存在性 | 确定、简单、LLM 操纵不了 | 不辨真值：占位值/空串放行 |
| 内容锚定 id | 理论跨版本稳定、无需中央序号 | 对内容方差敏感：一字漂移即断链 |
| 硬截断（2万字/cap10/32字） | 成本确定、保护下游 | 丢什么不说（弱披露或无披露） |
| LLM 自由填表 | 任意文体可解析 | 无锚点 → 三态漂移 + 值级方差 |
| 降级哲学（never crash） | 管线极强壮 | 降级太安静："成功"掩盖空壳 |

## 3. 四个修复接头

### J1 答案真值闸（治级联 A）✅ 已落地 2026-09-11
- **位置**：parse_modules / interviewer fills 的统一出口（一个 canonical 函数）
- **规则**：占位词典（未提及/未明确/未知/缺少依据/N/A 等变体）+ 空串 → 不写入 answers
- **新缺点**：词典法漏新变体；不采用 LLM 判真值（会再引入方差）；漏网由 J3 兜底可见
- **改动面**：1 个新函数 + 2 个调用点 + 测试
- **落地记录**：
  - canonical 谓词 `is_truthy_answer` + 占位词典 `_PLACEHOLDER_ANSWERS`（60+ 变体逐字枚举）+ 归一化 `_truth_norm`（NFKC 全角折半 / strip / casefold / 剥首尾包裹符号与标点，纯函数零 LLM）——均在 `backend/app/domains/creation/seed/a1_question_tree.py`
  - 三个出口接线（比预估多一个：门禁计数本身也真值化，这是 xt e2 断言翻转 `is_finalizable(占位answers) is False` 的必要条件，直注/存量脏数据由此防住）：① `worldview_upload.parse_modules` 占位不写入（prefill 随之无污染）；② `guide_engine._apply_fills` 占位 fill 不写入/不拦截/不占 first-write-wins 名额（prefill 豁免通道同样拦截）；③ `module_done_ratio`/`is_module_done` 分子只数真值
  - 词典纪律："无"不入词典（合法否定答案，如"是否有神"→"无"）；纯精确匹配不做子串匹配（"未知种族的迁徙史"是真答案）；词典扩充需走治理评审（误收会吞真实答案）
  - 测试：test_question_tree（真值谓词 4 类 + 门禁真值化 5 例）、test_worldview_upload（出口过滤 1 例）、test_write_guard（fills 出口 4 例含 prefill 豁免通道）、xt test_e2 三用例断言翻转（见 §5）
  - 连带修复：存量 `_fill_all_subs`（test_a1_routes）由"跳过刷空串过门"改为真值直注——test_e2 注释预言的存量依赖

### J2 规范化层（治级联 B，契约级）
- **位置**：id 铸造（sanitize_title/depth_id）前 + 边匹配（_make_edge_key）前
- **规则**：prompt 要求显式字段逐字摘录；标题超 32 字 → 警告并要求缩短（不静默截断）；端点匹配前先过 canonical 形式
- **边界**：不做 fuzzy 自动合并（会误合并不同条目），只做检测 + 披露
- **风险**：动 v0.5 治理文档钦定的 id 不变量 → 需"双侧签字 + 集成测试"流程，单独设计评审
- **改动面**：graphify.py + a1_routes.py 装配层 + 治理文档修订

### J3 披露协议 / warning ledger（治级联 C）✅ 已落地 2026-09-11
- **位置**：所有丢弃点的统一出口
- **规则**：四处 warnings（assemble/finalize/dead_edges/graphify 层）合并为一个结构化 ledger 落 `file_rec["warnings"]`（source/detail/count/level），前端出角标
- **新缺点**：警告疲劳 → 需分级（warn/info）
- **改动面**：a1_routes.py 警告汇集 + get_file 响应 + 前端角标位
- **落地记录**：
  - 新模块 `backend/app/domains/creation/a1/warning_ledger.py`：`LedgerEntry`（source/detail/count/level）+ `entry`/`from_strings`/`from_dead_edges`（死区按 reason 聚合计数）+ `classify_level`（前缀表确定性分级：丢失性=warn，转换/开关性=info；未列出前缀一律 warn——保守取向，宁多报丢失不漏报）
  - `graphify.py`：`GraphifyResult.warnings: list[str]` 结构化真源（`apply_graphify_validation` 收集、degrade 路径单条）；`warning` 字符串保留由列表拼接（向后兼容既有降级断言）；新增 `is_title_truncated`（与 sanitize_title 同一归一化的 32 字截断判定）
  - `a1_routes.py` finalize：四处通道合并 → `file_rec["warnings"]`（upload 条目跨 finalize 存活；graphify 通道仅 success=True 时并入——degrade 警告已走 finalize 通道，避免同文案双计）；finalize 响应新增 `ledger` 字段（旧 `warnings` list[str] 保留向后兼容）；`get_file` 常驻暴露 `warnings`
  - 级联 C 披露点补全：`_assemble_depth_tree` 标题超 32 字静默截断 → 有痕（items+children 两处；id 仍截断——稳定性契约不动）；upload >20000 字截断 → `rec["warnings"]` upload 条目（此前只在响应闪现不落库）
  - additive 设计：assemble_warnings / finalize_warnings / dead_edges 三个既有通道原样保留（消费方契约不动），ledger 是合并视图 + 唯一新增落点
  - 专名 cap=10（#4）的披露归 J4 预算护栏一并处理（cap 本质是预算截断，且需改 extract_entities 返回契约）
  - 测试：test_warning_ledger（9 例）+ test_graphify_llm 扩展（warnings 双轨 + is_title_truncated 7 例）+ test_a1_warning_ledger 路由级（10 例：graphify 蒸发修复/assemble 去重/标题截断/死区聚合/降级通道/上传保留/干净空 ledger/get_file/upload 截断落库）
  - 前端角标：A1GraphSection T16 角标升级消费 ledger（warn 醒目/info 弱化、source 徽章、×N 计数；旧 finalizeWarnings 兜底保留）——visual-engineering 委派实施

### J4 预算护栏（治级联 D）✅ 已落地 2026-09-11
- **位置**：各写入入口
- **规则**：answer value ≤2000 字（超限截断+J3 披露）；convert 输入 ≤20000；graphify prompt 总长预算；store 备份轮转（保留 N 份历史快照）
- **新缺点**：截断丢内容 → 必须配 J3 才成立
- **改动面**：worldview_upload.py / interviewer.py / store.py + 常量配置
- **落地记录**：
  - **answer ≤2000**：`clip_answer` + `ANSWER_MAX_CHARS` 落 `a1_question_tree.py`（J1 谓词同家）。写入出口两处接线：`_apply_fills`（守卫分支/提案一律用截断后的值）+ `parse_modules`（返回 `clipped_answers`，经 `_prefill_session` 记入 `A1Session.answer_clips` 新字段）；finalize 时并入 ledger **source=answers**（第 6 个 source，治理批准的枚举扩充）。interviewer.py 未动——fills 统一出口在 _apply_fills（J1 先例）
  - **graphify prompt 预算**：每答案 2000（`clip_answer`）+ 答案块总长 `GRAPHIFY_ANSWERS_BUDGET=60000`（`_answers_block` 硬顶+尾部留痕）。**prompt 层是写入层护栏的必要补位**——直注/存量脏数据（inject_answers 类入口）绕过写入层。预算披露 `[budget]` 前缀进 `result.warnings`（success 与 degrade 路径都随行）；C1 verbatim 契约修订为"预算内 verbatim"
  - **convert ≤20000**：`convert_text` 内部 `_truncate` + prompt 留痕标记（"已截断，仅改写以上部分"）；convert 路由对超长原文落 ledger **source=upload**
  - **store 备份轮转**：`A1Store.save` 写前轮转 path→.bak1→.bak2→.bak3（`_BACKUP_COUNT=3`，best-effort 不阻塞主写）；`load` 主文件损坏/缺失时按新→旧尝试备份恢复，全部损坏才空态降级（#10 单点蒸发的双向缓解：写侧轮转 + 读侧恢复）
  - **专名 cap 披露**：`extract_entities` 返回 `capped: {类别: 丢弃数}`（+ `PROPER_NOUN_LABELS` 中文标签）；上传路由落 ledger source=upload（#4）
  - 测试：clip_answer 4 例 + _apply_fills 预算 3 例 + parse_modules 1 例 + graphify 预算 4 例 + ledger answers 通道 1 例 + convert 2 例 + store 轮转/恢复 4 例 + cap 披露 2 例
  - xt 闭环：test_e2 炸弹（#6）、test_e1 convert（#3）、test_e1 cap（#4）三组断言翻转（见 §5）

## 4. 实施顺序（整体最优 = 杠杆率排序）

```
J1 → J3 → J4 → J2
```

- **J1 先行**：最小改动 × 最大杠杆——一个函数闭环整条真值级联，同时兑现统计层实验结论
- **J3 次之**：把所有残余的"看不见的丢失"变成"看得见的降级"——B 类 bug 从此降级为可观察行为
- **J4 便宜保险**：纯防御，无契约牵动
- **J2 压轴**：爆炸半径最大（id 契约 + 治理文档 + 前端渲染回退联动），必须走正式设计评审
