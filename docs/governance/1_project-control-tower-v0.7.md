## 产品主线时序（大计划一页线 · 2026-10-09 产品方拍板）

> **来源**：产品方 2026-10-09 会话拍板，原话要旨：「物业是在大的计划里！在项目上线后再补充的社区模块！微调抽屉条是在更后面运营社区然后做AI管家！记录反馈在MVP之后做！」构想源 = [[2026-09-28-北极星构想与差距备忘]]（八环链条；差距 3/4 = 连接环/共创环）。
>
> **纪律**：本节拍的是**顺序**，不是**开工**——各段立项与排期届时不提前占用 MVP 资源（北极星备忘同款：未拍板不立项不影响现行排期）。

```
① MVP（现行阶段）
   验收线 = B1 重定义提案：故事型全流程 + 主模组文字版闭环（待产品方终审）
        ↓ 上线
② 记录反馈（MVP 之后）
   从第一天记三样：谁走上来 / 说了什么 / 回应让他往前一步还是停住
   （载体 = E0 观察台扩容，具体形状届时候立项）
        ↓
③ 社区模块（产品方语汇 =「物业」：开发商建桥 → 物业运营）
   上线后补充；北极星差距 3/4（连接环/共创环）的工程落点
        ↓ 运营社区，攒真实对话
④ AI 管家（微调入场）
   抽屉条：「等有一百段真实对话的时候再开」——攒到约一百段真实对话、
   能明确指出通用模型哪里接不住你的用户时，微调才入场（届时语聊数据是金子）
```

**术语注记**：「物业」= 上线后的社区运营阶段，是大计划内的一环，不是新开的线；「记录反馈」三样读本同时是日后抽检与微调入场判定的数据底座（先开发商〔提示词+流程做出气质〕→ 再物业〔真实对话流进来、存下来〕，现在不微调）。
