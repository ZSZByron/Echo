> **状态**: 设计规范
> **关联**: [[2-A1-v0.2-6维约束体系×6层生成维度]] A1输出, [[2_product-architecture]] §3 A2边界, [[plans/2026-08-04-trpg-pipeline-mapping]] Sprint规划

## 文档定位

本文档详细描述 A2 **产品策划工作台 (Product Planning Workbench)** 的核心架构 — **AI 产品策划分析 + 模组合成** 的完整设计，包括数据模型、知识库结构、推荐引擎、工作流程、技术实现和当前开发断点。

> **⚠️ 定位升级（2026-08-05 v0.2）**
>
> A2 不再仅仅是"筛选层"（自顶向下从 A1 完整世界提取全局设定）。
>
> **新定位**: A2 = **产品策划工作台 (Product Planning Workbench)**
> - **交互形态**: 世界特征分析 → 游戏类型推荐 → AI 辅助模组定义 → 结构化输出
> - **核心流程**: World IP Schema → 特征提取 → 类型匹配 → 案例推理 → 推荐方案 → 模组合成
> - **类比**: 影视行业——导演有一个世界观，制片人分析：做电影？电视剧？游戏？动画？A2 就是这个"制片人"角色
> - **厂家体验**: 像有一个资深产品策划帮你看"这个世界适合做成什么"
> - **系统内部**: LLM 特征提取 + 规则引擎匹配 + RAG 案例推理 + LLM 综合推荐
> - **管线契约**: A2 的输出仍然是 `main_module.json`，A3 不需要知道 A2 内部有产品分析
>
> **❌ A2 不是什么**:
> - 不是商业分析 AI（市场趋势/销量预测/成本评估 → 远期 AI 3）
> - 不是自动游戏设计师（A2 推荐方向，A3 生产具体内容）
> - 不是让厂家学习游戏类型分类学的工具

## 1. 架构概览

### 1.1 系统定位

A2 产品策划工作台是 Echo UGC 管线中的 **"制片人"环节**，定位为 **Product Planning Workbench**：

```
厂家用户
  ↓
A1 世界观IP设计工作台
  ├─ 专业问卷（8大模块21项）
  ├─ AI设计顾问实时分析
  └─ 编译为 World IP Schema
  ↓  world_package.json
┌─────────────────────────────────────────────┐
│ A2 产品策划工作台                             │
│                                              │
│ Phase 1: 产品策划分析（Product Analyst）      │
│   World IP Schema                            │
│     ↓                                        │
│   FeatureExtractor (LLM)                      │
│     ↓                                        │
│   WorldFeatureProfile (7维特征向量)            │
│     ↓                                        │
│   GenreMatcher (规则引擎 — 纯计算，零LLM)     │
│     ↓                                        │
│   原始类型得分 + 候选过滤                      │
│     ↓                                        │
│   CaseRetriever (JSON检索)                    │
│     ↓                                        │
│   相似IP案例 + 成功经验                        │
│     ↓                                        │
│   PlanSynthesizer (LLM)                      │
│     ↓                                        │
│   ProductPlan (推荐方案)                       │
│                                              │
│ Phase 2: 模组编成（Module Composer）            │
│   ProductPlan + A1 WorldPackage               │
│     ↓                                        │
│   ModuleComposer (LLM)                        │
│     ↓                                        │
│   MainModule (main_module.json)              │
│                                              │
│ Phase 3: 骰子模板生成（Dice Template）           │
│   WorldPackage + ProductPlan + MainModule       │
│     ↓                                        │
│   骰子核心 → 等级系统 → 难度系统 → 数值边界      │
│     ↓                                        │
│   DiceTemplate (dice_template.json)             │
│                                              │
│ Phase 4: 角色模板生成（Character Template）   │
│   WorldPackage + MainModule + DiceTemplate     │
│     ↓                                        │
│   数据提取（世界本体 + 玩法DNA）              │
│     ↓                                        │
│   映射 → 排序 → 精简                          │
│     ↓                                        │
│   CharacterTemplate (角色卡模板)              │
└──────────────────────┬──────────────────────┘
                       ↓  main_module.json + dice_template.json + character_template.json
┌──────────────────────┐
│ A3 次模组编辑器       │
└──────────────────────┘
```

### 1.2 核心理念

**A2 的逻辑方向转变**：

| 维度 | 原设计（筛选层） | 新设计（策划+合成） |
|------|-----------------|-------------------|
| **方向** | 自顶向下（世界→局部） | 先分析后筛选 |
| **核心算法** | 全局性筛选器 | FeatureExtractor + GenreMatcher + RAG |
| **输出价值** | `main_module.json`（仅给下游） | `ProductPlan`（给厂家看）+ `main_module.json`（给下游） |
| **厂家可见** | 仅模组内容 | 特征画像 + 推荐理由 + 参考案例 + 模组内容 |
| **AI 角色** | 无（手动筛选） | 产品策划顾问 |

### 1.3 四阶段职责隔离

| 阶段 | 职责 | 输入 | 输出 | AI 依赖 |
|------|------|------|------|--------|
| **Phase 1: 产品分析** | 分析世界特征，推荐产品方向 | `WorldPackage` | `ProductPlan` | LLM + RAG |
| **Phase 2: 模组编成** | 根据推荐方向，从A1世界筛选模组内容 | `ProductPlan` + `WorldPackage` | `MainModule` | LLM |
| **Phase 3: 骰子模板生成** | 根据世界观+游戏类型+玩法DNA，生成判定规则与数值区间 | `WorldPackage` + `ProductPlan` + `MainModule` | `DiceTemplate` | LLM + 规则引擎 |
| **Phase 4: 角色模板生成** | 从世界本体+玩法DNA+骰子模板提取数据，映射到4相位，排序精简，生成角色卡模板 | `WorldPackage` + `MainModule` + `DiceTemplate` | `CharacterTemplate` | LLM + 规则引擎 |

四个阶段可**独立调用**：
- `/api/planning/analyze` — 仅 Phase 1（探索用，厂家只看推荐不急着编模组）
- `/api/planning/compose` — Phase 1 + Phase 2（完整流程）
- `/api/planning/dice-template` — Phase 3（生成骰子模板，详见 §6）
- `/api/planning/character-template` — Phase 4（生成角色卡模板，详见 §7）

### 1.4 与上下游的关系

```
A1 输出（WorldPackage）
  ├─ world_identity: WorldIdentityCard        → FeatureExtractor 使用
  ├─ gameplay_anchor: GameplayAnchor           → FeatureExtractor 使用
  ├─ design_note: DesignNote                   → FeatureExtractor 使用
  ├─ constraints: DimensionResultSet            → FeatureExtractor 使用（权重信号）
  ├─ knowledge_graph: KnowledgeGraph            → ModuleComposer 使用（筛选节点）
  └─ visual_bible: VisualBible                 → ModuleComposer 使用
       ↓
A2 输出（MainModule + DiceTemplate + CharacterTemplate）
  ├─ product_plan: ProductPlan                  → 厂家查看 + 前端展示
  ├─ constraint_level: "MODULE"                 → A3 继承规则
  ├─ scope_boundary: dict                       → A3 不可超越的边界
  ├─ world_ref: str                             → 指回 A1 WorldPackage
  ├─ dice_template: DiceTemplate                → 判定规则+数值区间（给 GM/PC，详见 §6）
  └─ character_template: CharacterTemplate      → 角色卡模板（给 GM/PC，详见 §7）
       ↓
A3 输入（MainModule）
```

## 2. 数据模型

### 2.1 A1 → A2 数据契约：WorldPackage

> **定位**: A1 编译后的完整世界包 — A2 的唯一输入格式。
>
> **注意**: `WorldPackage` 是 A1 已有输出的**编译适配器**，不是重写。A1 当前已有的 `DimensionResultSet` + `KnowledgeGraph` + `ConceptNode` 组装即可。A1 问卷完成后 `identity`/`visual_bible`/`gameplay_anchor` 自然填充。

```python
# backend/app/models/world_package.py (NEW)

class WorldPackage(BaseModel):
    """A1 → A2 的完整世界包"""
    world_identity: WorldIdentityCard              # 世界定位卡
    visual_bible: VisualBible                      # 视觉指南
    gameplay_anchor: GameplayAnchor                # 玩法锚点
    design_note: DesignNote                        # 设计说明
    generation_boundary: GenerationBoundary        # AI 生成边界
    constraints: DimensionResultSet               # 6维约束结果（已有）
    knowledge_graph: KnowledgeGraph               # 知识图谱（已有）
    seed_concepts: list[ConceptNode]              # 种子概念（已有）
```

> **MVP 降级策略**: A1 问卷未完成时，`world_identity`/`visual_bible`/`gameplay_anchor` 可为 `None`。`FeatureExtractor` 用 `DimensionResultSet` 的权重信号 + `ConceptNode` 的语义内容即可提取 7 维特征。

### 2.2 A2 核心数据模型

```python
# backend/app/models/product_planning.py (NEW)

class GameGenre(StrEnum):
    """游戏类型。不允许添加或修改。"""
    OPEN_WORLD_RPG = "open_world_rpg"        # 开放世界RPG
    DUNGEON_CRAWLER = "dungeon_crawler"      # 地牢探索
    TACTICAL_RPG = "tactical_rpg"            # 回合制战棋
    VISUAL_NOVEL = "visual_novel"            # 视觉小说/文字冒险
    SURVIVAL_CRAFT = "survival_craft"        # 生存建造
    SOCIALIZING_TRPG = "socializing_trpg"    # 社交TRPG
    INVESTIGATION = "investigation"          # 推理解谜
    ACTION_ADVENTURE = "action_adventure"    # 动作冒险


class WorldFeatureProfile(BaseModel):
    """从 A1 World IP Schema 提取的7维世界特征向量（LLM分析结果）。

    每个维度 0.0-1.0，表示该维度在世界中的显著程度。
    由 FeatureExtractor (LLM) 生成，供 GenreMatcher (规则引擎) 使用。
    """
    exploration_level: float    # 世界开放度/探索空间
    conflict_intensity: float    # 冲突激烈度/战斗比重
    social_complexity: float    # 社交关系/势力博弈复杂度
    mystery_depth: float         # 悬疑/解谜/历史秘密深度
    power_fantasy: float         # 力量成长/变强幻想程度
    narrative_weight: float      # 叙事/剧情比重
    survival_pressure: float    # 生存压力/资源紧张程度


class GenreRecommendation(BaseModel):
    """单个游戏类型推荐结果。"""
    genre: GameGenre
    match_score: float              # 0-100, 综合匹配度（特征匹配 + 案例相似度加权）
    reasoning: str                  # 推荐理由（引用案例库经验，厂家可读）
    similar_cases: list[str]       # 参考IP案例ID列表
    key_gameplay_hooks: list[str]  # 核心玩法钩子（从案例库提取）
    target_users: list[str]        # 目标用户画像


class ProductPlan(BaseModel):
    """A2 Phase 1 输出 — 产品规划方案。

    这是厂家可见的核心交付物。Phase 2 的 ModuleComposer 基于此方案编成模组。
    """
    world_feature_profile: WorldFeatureProfile
    recommendations: list[GenreRecommendation]  # 按 match_score 降序
    recommended_direction: GenreRecommendation   # 首选推荐（最高分）
    module_fantasy: str           # 模组核心幻想描述（一句话）
    gameplay_hooks: list[str]     # 推荐的玩法钩子列表
    target_users: list[str]       # 目标用户画像
    analysis_notes: str           # AI 策划分析备注（为什么选这个方向）


class MainModule(BaseModel):
    """A2 最终输出 — main_module.json。

    管线契约：A3 次模组编辑器消费此数据。
    Phase 2 ModuleComposer 产出。
    """
    # 产品分析（新增 — 保留完整策划上下文）
    product_plan: ProductPlan

    # 模组定义（原设计保留）
    constraint_level: Literal["MODULE"]
    world_ref: str                    # 指向 world_package.json 的引用
    selected_eras: list[str]          # 选中的时代
    selected_regions: list[str]       # 选中的区域
    main_faction: str                 # 主势力
    main_conflict: str                # 主线冲突
    gameplay_focus: GameGenre         # 聚焦的玩法类型
    scope_boundary: dict              # 模组范围边界（A3 不可超越）
    generation_constraints: dict      # 本模组的生成约束（继承自A1 + A2裁剪）
```

### 2.3 模型关系图

```

    ├─→ FeatureExtractor ──→ WorldFeatureProfile (7维向量)

```

## 3. RAG 知识库

### 3.1 知识库目录

```
backend/data/knowledge/
├── ip_case_library.json       # 历史IP案例库（MVP: 30条，长期: 50-500+）
```

### 4.3 GenreMatcher — 类型匹配

**职责**: 纯规则引擎，零 LLM 依赖。

```python
class GenreMatcher:
    """7维特征 → 8种游戏类型匹配度"""

    def match(self, profile: WorldFeatureProfile) -> dict[GameGenre, float]:
        """点积计算：特征向量 × 亲和度矩阵 → 原始得分"""
        scores = {}
        features = profile.model_dump()
        for genre, weights in self.matrix.items():
            score = sum(features[dim] * w for dim, w in weights.items()) / len(weights)
            scores[genre] = round(score * 100, 1)  # 转为 0-100
        return scores

    def filter_thresholds(self, scores: dict) -> list[tuple[GameGenre, float]]:
        """过滤低于阈值的候选（默认 ≥ 40 分）"""
        return [(g, s) for g, s in scores.items() if s >= self.threshold]
```

### 4.4 CaseRetriever — 案例检索

**职责**: 根据候选类型和世界特征，检索最相似的历史 IP 案例。

```python
class CaseRetriever:
    """JSON 文件检索 — 无需向量库"""

    def retrieve(
        self,
        candidates: list[tuple[GameGenre, float]],
        profile: WorldFeatureProfile,
        top_k: int = 5
    ) -> dict[GameGenre, list[IPCase]]:
        """对每个候选类型，按特征距离排序返回 Top-K 案例"""
        results = {}
        target_vector = profile.model_dump()
        for genre, score in candidates:
            genre_cases = [c for c in self.cases if c.genre == genre]
            # 余弦相似度排序
            scored = [(c, cosine_sim(target_vector, c.features)) for c in genre_cases]
            scored.sort(key=lambda x: x[1], reverse=True)
            results[genre] = [c for c, _ in scored[:top_k]]
        return results
```

## 6. 骰子模板生成器（Phase 3: Dice Template Generator）

> **版本**: v0.1（2026-08-07 新增）
> **状态**: 设计规范
> **关联**: [[2-A1-v0.2-6维约束体系×6层生成维度]] §1.2 模块2世界本体 + 模块8玩法DNA, §7 角色模板生成器（Phase 4，消费 DiceTemplate）

### 6.1 系统定位

**骰子模板生成器 (Dice Template Generator)** 是 A2 的第三个 Phase，为厂家生成判定规则与数值区间模板。

| 维度 | 内容 |
|------|------|
| **使用者** | 厂家（世界 IP 创作者） |
| **输入** | `WorldPackage`（A1输出）+ `ProductPlan`（Phase 1输出）+ `MainModule`（Phase 2输出） |
| **输出** | 骰子模板（DiceTemplate）— 独立交付物 |
| **模板最终给谁** | GM 和 PC（游戏运行时参与者），与 CharacterTemplate 同级发布 |
| **模板的作用** | 为角色模板提供"数值骨架"——判定方式、等级刻度、难度量程。角色模板的机制相位处理端、资源相位数值边界、定向相位等级映射均由 DiceTemplate 确定 |
| **厂家的唯一职责** | 确认骰子核心类型与等级系统倾向是否符合 IP 基调 |
| **设计原则** | 骰子模板 = 引擎（判定动力与输出方式）+ 标尺（刻度与量程）。角色模板 = 容器（装结果的框架） |

> **❌ 骰子模板生成器不是什么**:
> - 不是生成具体的骰子数值（模板是规则框架，具体数值在角色卡/运行时填写）
> - 不是战斗系统设计器（骰子模板管"怎么判定"，不管"判定后发生什么"——那是 A3 的职责）
> - 不是让厂家手写数学公式（厂家只确认方向，LLM + 规则引擎生成具体参数）

### 6.2 数据来源

骰子模板生成器从三个输入源提取结构化数据：

| 输入源 | 提取内容 | 骰子模板用途 |
|--------|---------|-------------|
| **WorldPackage.world_identity** | 现实规则主导（material/will） | 决定骰子核心类型选择 |
| **WorldPackage.gameplay_anchor** | 玩法DNA三层：玩家身份/主要行为/成长方式 | 决定等级系统选择 + 难度系统选择 |
| **ProductPlan** | 推荐的游戏类型 + 推荐理由中的游玩元素清单 | 拆解游玩元素比例，校准等级系统倾向 |
| **MainModule** | 模组范围边界、力量体系定义 | 约束数值边界（等级上限、骰子数量上限） |

**核心数据字段**：

| 来源 | 字段 | 骰子模板用途 |
|------|------|-------------|
| **世界本体·现实规则** | `WorldSchema.reality_rule.dominant` | 物质主导→数值骰（d20/d100+修正）；意志主导→概念骰（骰池计数/百分比对冲） |
| **玩法DNA·成长方式** | `GameplayAnchor.growth.quantitative` | 量变倾向 → 累积型成长信号 |
| **玩法DNA·成长方式** | `GameplayAnchor.growth.qualitative` | 质变倾向 → 跃迁型成长信号 |
| **玩法DNA·成长方式** | `GameplayAnchor.growth.cost` | 代价机制 → 资源消耗规则 |
| **玩法DNA·主要行为** | `GameplayAnchor.main_behavior` | 探索/战斗/研究 → 决定检定频率与难度交互方式 |
| **ProductPlan.genre** | 推荐游戏类型 | 拆解类型内部游玩元素比例 |

### 6.3 生成逻辑：三步生成 + 一步校准

骰子模板生成分为四步，前三步顺序生成骰子核心/等级系统/难度系统，第四步用 ProductPlan 校准。

#### 6.3.1 Step 1: 骰子核心（判定引擎）

**决策点**: 判定的动力来源和输出方式是什么？

**输入信号**: `WorldSchema.reality_rule.dominant`

| 现实规则主导 | 骰子核心类型 | 判定方式 | 适用理由 |
|-------------|------------|---------|---------|
| **物质主导** | 数值骰（d20+修正 或 d100+修正） | 掷骰+修正 vs DC | 世界是精确的、可量化的——护甲有厚度、子弹有弹道，需要线性概率分布 |
| **意志主导** | 骰池计数（Xd6，5-6成功）或 百分比对冲（技能值% vs 难度%） | 计数成功数 或 概率对冲 | 世界是流动的、概念化的——SAN值检定、信念系统，需要钟形/非线性概率分布 |

**骰子来源**（骰子数量从哪来）：

| 骰子核心类型 | 骰子来源 | 示例 |
|-------------|---------|------|
| 数值骰 | 固定单骰 + 属性修正值 | d20 + 力量修正(+3) |
| 骰池计数 | 能力等级/装备槽位提供的骰子数 | 3d6（技能等级3） |
| 百分比对冲 | 固定技能值% | 调查 65% |

#### 6.3.2 Step 2: 等级系统（成长标尺）

**决策点**: 角色成长的计量方式是什么？

**判定流程（优先级递减）**：

```
Step 2a: 读 GameplayAnchor.growth（玩法DNA成长方式）
  │
  ├─ 厂家明确填写了 quantitative/qualitative 的偏好？
  │   └─ YES → 直接按厂家定义生成（用户说了算）
  │        ├─ quantitative 为主 → 槽位制倾向
  │        ├─ qualitative 为主 → 位阶制倾向
  │        └─ 两者均明确 → 混合制
  │
  └─ NO（未填写或为空）
      │
      Step 2b: 拆解 ProductPlan 推荐理由中的游玩元素
      │
      ├─ 提取所有"精确累积型"元素
      │   （技能点、装备数值、好感度数值、条件flag、资源储备...）
      ├─ 提取所有"质变跃迁型"元素
      │   （觉醒、契约、转职、剧情分支、位面穿梭...）
      ├─ 计算比例
      │
      └─ 比例判定：
          ├─ 累积型 > 70% → 槽位制为主
          ├─ 跃迁型 > 70% → 位阶制为主
          └─ 混合区间（30%-70%）→ 混合制
```

**三种等级系统**：

| 等级系统 | 成长形态 | 每级效果 | 数值边界设定 | 角色卡显示 |
|---------|---------|---------|-------------|-----------|
| **槽位制** | 台阶式渐进 | 每级获得1个能力槽位或+1固定数值 | 设定均值：Lv.1均值=10，Lv.10均值=20 | `[等级：1/10] [能力槽位：2/2]` |
| **位阶制** | 跳跃式质变 | 每阶获得叙事特权或骰子修正（+1d6） | 修正值锁定范围：-2 到 +5 | `[位阶：精英] [修正：+1d6]` |
| **混合制** | 槽位累积触发位阶跃迁 | 槽位填满到阈值时触发位阶跃迁 | 槽位管日常小成长，位阶管质变大节点 | `[位阶：精英] [槽位：3/5→下一阶]` |

**混合制说明**：

混合制的核心逻辑是**槽位累积是手段，位阶跃迁是结果**——两种成长元素不是并列关系，而是因果关系：
- 槽位（累积型）：管日常成长反馈——每用一次技能+1熟练度，每获一件装备+1收集度
- 位阶（跃迁型）：管剧情/身份质变——槽位累积到阈值时，触发位阶跃迁（如：3个核心技能满级 → 从"凡人"跃迁到"精英"）
- 视觉小说中的"好感度条满了触发剧情分支"就是这个逻辑

#### 6.3.3 Step 3: 难度系统（挑战量程）

**决策点**: 挑战的本质是什么？（需要与等级系统互动）

**输入信号**: `GameplayAnchor.main_behavior` + 等级系统选择结果

| 难度系统 | 适用场景 | DC 公式 | 与等级的互动 |
|---------|---------|---------|-------------|
| **对抗数值**（精准计算） | 等级系统为槽位制，主要行为含战斗/探索 | 标准DC = 同级玩家均值 + 挑战系数（0=简单, 5=困难） | DC 随等级线性增长 |
| **情境阻力**（定性判定） | 等级系统为位阶制，主要行为含研究/社交 | DC = 情境梯度（1-5档），不与等级直接挂钩 | 档位与叙事层级挂钩 |
| **混合难度** | 混合制等级系统 | 槽位层用对抗数值（DC=等级+系数），位阶层用情境阻力（位阶跃迁判定=固定梯度） | 双轨制 |

**难度对照表生成**：

骰子模板输出中包含一个 DC 对照表，供 GM 直接查阅：

| 难度档位 | 挑战系数/梯度 | 说明 |
|---------|-------------|------|
| 日常 | 0 / 梯度1 | 闭眼能过，用于叙事推进 |
| 简单 | +2 / 梯度2 | 几乎不会失败 |
| 标准 | +5 / 梯度3 | 同级挑战，50%成功率 |
| 困难 | +8 / 梯度4 | 需要全力投入 |
| 极限 | +12 / 梯度5 | 越级挑战，需要骰运或创造性方案 |

#### 6.3.4 Step 4: ProductPlan 校准

前三步基于 WorldPackage 的世界观信号生成初版骰子模板。Step 4 用 ProductPlan 的游戏类型推荐理由做交叉校准：

| 校准项 | 校准逻辑 |
|--------|---------|
| **骰子核心校准** | 确认推荐的游戏类型与骰子核心类型是否匹配（如推荐 tactical_rpg 但生成了骰池计数 → 检查是否需要调整为数值骰） |
| **等级系统校准** | 确认推荐理由中的游玩元素比例是否支持当前等级系统选择 |
| **数值边界校准** | 确认模组范围边界（MainModule.scope_boundary）是否约束了等级上限 |

> **校准原则**: 世界观信号优先，游戏类型信号校准。如果两者冲突（如物质主导世界 + visual_novel 推荐），以世界观信号为主，在骰子模板中标注冲突警告。

### 6.4 数据模型

```python

    """
    world_ref: str                       # 指向 world_package.json 的引用
    module_ref: str                      # 指向 main_module.json 的引用
    plan_ref: str                        # 指向 product_plan 的引用

    # 骰子核心
    dice_core: DiceCoreType              # 骰子核心类型
    dice_source: str                     # 骰子来源描述（如"能力等级提供骰数"/"固定技能值%"）
    success_criteria: str                # 成功判定方式（如"计数5-6"/"总数≥DC"/"百分比≥难度%"）

    # 等级系统
    growth_system: GrowthSystem          # 等级系统类型
    level_cap: int | None                # 等级上限（槽位制用，如10）
    tier_count: int | None               # 位阶数量（位阶制用，如5）
    tier_labels: list[str] | None        # 位阶名称列表（如["凡人","精英","英雄","传奇","神话"]）
    modifier_range: tuple[int, int] | None  # 修正值范围（位阶制用，如(-2, 5)）
    hybrid_config: dict | None           # 混合制配置（槽位阈值→位阶跃迁映射）

    # 难度系统
    difficulty_system: DifficultySystem  # 难度系统类型
    difficulty_table: list[DifficultyTier]  # 难度对照表（5档）
    dc_formula: str | None               # DC公式（对抗数值用，如"DC = 等级 + 挑战系数"）

    # 数值边界
    stat_floor: int                      # 1级/凡人的属性均值下限
    stat_ceiling: int                    # 满级/神话的属性均值上限
    dice_pool_range: tuple[int, int] | None  # 骰池数量范围（骰池制用，如(2, 8)）

    # 生成元数据
    reality_dominant: str                # 现实规则主导（material/will）
    growth_signal_source: str            # 等级系统信号来源（"gameplay_dna"/"genre_element_analysis"）
    conflict_warning: str | None         # 世界观信号与游戏类型信号冲突时的警告
```

- 骰子模板**不改变**角色模板的架构骨架（映射5条规则不变、排序4步判别法不变、精简常量vs变量不变）

**角色模板生成器 (Character Template Generator)** 是 A2 的第四个 Phase，为厂家提供角色卡模板生成能力。

| 维度 | 内容 |
|------|------|
| **使用者** | 厂家（世界 IP 创作者） |

### 7.3 映射机制：世界本体+玩法DNA → 4相位

将世界本体（3层）和玩法DNA（3层）映射到4个相位（结果容器）。共5条映射规则：3条直接映射 + 2条分裂映射。

#### 7.3.1 直接映射（3条）

| # | 源 | 目标相位 | 映射内容 |
|---|----|---------|---------|
| 1 | 世界本体·来源 | **定向相位** | 起源时间线→决定游戏的时间尺度（探索远古遗迹 / 阻止即将到来的末日）；起源力量→决定玩家的终极力量来源（神力？科技？虚空？） |
| 2 | 世界本体·现实规则 | **机制相位** | 物质主导→物理引擎、硬核弹道、装备耐久、负重系统；意志主导→立场系统、嘴炮判定、精神干涉现实、心像风景 |
| 3 | 玩法DNA·主要行为 | **机制相位** | 探索/战斗/研究→流程拓扑的输入端（玩家可用的能力列表） |

**直接映射的生成逻辑**：

- **来源→定向相位**：设定成长尽头（创世神话→弑神/成神；科学起源→技术飞升/基因改造）；确定维度身份（起源力量决定玩家是"使用者"还是"篡改者"）
- **现实规则→机制相位**：判定核心规则（物质主导→物理数值判定：攻击力/防御力；意志主导→概念修正判定：信念/恐惧）。这是最关键的"玩法DNA"转折点
- **主要行为→机制相位**：定义互动对象（存在物中的"其他"直接决定怪物图鉴和NPC交互规则）；定义成长资源（力量体系通常伴随"燃料"如魔力/以太/SAN值，这是资源相位的核心）

#### 7.3.2 分裂映射（2条）

**分裂映射**：一个源概念跨两个相位，按"过程vs结果"或"思想vs力量"分裂。

| # | 源概念 | 分裂去向 | 依据 | 映射内容 |
|---|--------|---------|------|---------|
| 4 | 玩法DNA·成长方式 | 过程→**资源相位**<br>结果→**定向相位** | 成长的过程vs结果 | 过程：量变/代价/熟练度/收集度→交换拓扑（资源池、转换器、阀门）；结果：质变/成长尽头→层级拓扑（进化树、门槛任务） |
| 5 | 世界本体·存在物 | 哲学→**叙事相位**<br>力量体系→**资源相位** | 思想vs力量 | 哲学思想→道德锚点（阵营、誓言、善恶值、理智值）；力量体系→能力货币（法力、怒气、SAN值、记忆）。宇宙学→叙事相位（地理/势力关系拓扑） |

**分裂映射的生成逻辑**：

- **成长过程→资源相位**：定义成长资源（力量体系通常伴随"燃料"如魔力/以太/SAN值）；定义转换器（经验值→等级，金币→装备）；定义阀门（等级上限、物品栏位）
- **成长结果→定向相位**：设定层级维度（社会层：流浪者→领主；法则层：使用者→篡改者）；设定终局维度（角色退隐/概念升华）
- **哲学思想→叙事相位**：转化为阵营系统与道德代价（善恶值、理智值）；定义角色与世界势力的关系
- **力量体系→资源相位**：转化为角色能力拓扑（技能树、魔法派系）；定义能力货币

> **注意**：资源相位是两个分裂映射的共同落点（成长过程 + 力量体系），内容密度容易偏高。但"是否需要精简"取决于它在当前世界是否是核心相位——核心则保留，非核心则精简。由 §7.4 的排序方法决定。

### 7.4 排序方法

排序分两个层次：**大项排序**（4相优先级）和**项内内容排序**（每相内部具体角色内容的优先级）。

#### 7.4.1 大项排序：4步判别法

**核心判别公式**：

```
核心玩法 = 现实规则的"严酷性" + 哲学思想的"冲突点"
```

两者缺一不可。严酷性是现实规则的属性，冲突点是玩家动机与世界哲学的碰撞。两者相加后才共同决定核心玩法落在哪些相位。

**术语定义**：

| 术语 | 来源 | 定义 | 映射到 |
|------|------|------|--------|
| **现实规则** | 世界本体第3层 | 世界的物理引擎——拳头还是意念改变事物。物质主导=世界是坚硬的、惯性的（枪械有弹道、护甲有厚度）；意志主导=世界是流动的、心像的（SAN值检定、信念系统、言灵） | 机制相位 |
| **严酷性** | — | 规则对玩家的限制力度/反馈强度=世界的"摩擦系数"。高严酷性=规则不可逾越，犯错代价高昂（框架稳定来源）；低严酷性=规则宽松，容错率高（自由度空间） | 决定核心/非核心相位的保留度 |
| **哲学思想** | 世界本体第2层存在物 | 世界的价值导向和终极命题——世界走向哪、对错标准。不是用来"判定"的，是用来"衡量价值"的 | 定向相位+叙事相位 |
| **冲突点** | 玩家动机(DNA) × 世界哲学 | 玩家动机撞上反人性哲学产生的两难=玩法动力源。哲学思想通常反直觉或反人性，给玩家制造"两难困境" | 核心玩法所在 |

**4步判别流程**：

| 步骤 | 动作 | 输入 | 输出 |
|------|------|------|------|
| **1. 定调** | 读现实规则倾向 | 物质主导/意志主导 | 划分核心2相 vs 次要2相 |
| **2. 定性** | 读哲学思想走向 | 虚无主义/人定胜天/秩序vs混沌/功利主义... | 给核心相位注入冲突主题 |
| **3. 定形** | 扫存在物找结构洞 | 力量体系/宇宙学/哲学哪一项独一无二 | 找出压倒一切的核心内容 |
| **4. 定动力** | 算冲突点 | 玩家动机 × 世界哲学 | 定位核心玩法落在哪两相交界 |

**定调结果**：

| 现实规则 | 核心2相（保留充分） | 次要2相（精简） |
|---------|-------------------|----------------|
| 物质主导 | 资源相位 + 机制相位 | 叙事相位 + 定向相位 |
| 意志主导 | 叙事相位 + 定向相位 | 资源相位 + 机制相位 |

**定性参考**：

| 哲学思想走向 | 核心冲突主题 | 生成机制示例 |
|-------------|-------------|-------------|
| 虚无主义 | 绝望与挣扎 | 不可避免的衰败机制 |
| 人定胜天 | 成长与突破 | 越级挑战机制 |
| 秩序vs混沌 | 阵营抉择 | 声望系统与势力冲突 |
| 功利主义 | 残酷取舍 | 道德抉择与希望值管理 |

**定形参考**（寻找结构洞）：

扫描四相，找出存在物中"独一无二"的元素——它就是整个角色模板最不能省的内容：

| 结构洞来源 | 命中的相位 | 命中的具体内容 |
|-----------|----------|--------------|
| 力量体系独一无二（如吞噬记忆获得力量） | 资源相位 | 记忆管理条目（压倒一切，金币/装备都是次要的） |
| 宇宙学独一无二（如多维度交错） | 叙事相位 | 位面穿梭背景条目（地图拓扑比战斗拓扑更重要） |

**定动力参考**（算冲突点）：

核心玩法不在单一相位里，而在玩家动机撞上世界哲学的那个交叉点上：

| 冲突点示例 | 跨界的两相 | 命中的具体内容 |
|-----------|----------|--------------|
| 探究动机 × 禁忌哲学 | 叙事×资源 | 禁忌知识条目 + 理智消耗条目 |
| 人道动机 × 功利哲学 | 叙事×资源 | 道德抉择条目 + 希望值条目 |

> **冲突点在哪两个相位的交界上，那两个相位就是排序最高的。**

#### 7.4.2 项内内容排序：6级优先级

每相内部有多个具体角色内容（字段/条目），按三条规则交叉定6级：

| 优先级 | 条件 | 处理方式 |
|--------|------|---------|
| **第1级** | 核心相位 ∩ 结构洞命中 ∩ 冲突点命中 | 厂家必设常量（风味浓度核心） |
| **第2级** | 核心相位 ∩ (结构洞命中 XOR 冲突点命中) | 厂家设常量或半常量 |
| **第3级** | 核心相位 ∩ 无命中 | 保留，设变量给玩家 |
| **第4级** | 次要相位 ∩ 结构洞命中 | 保留，设变量给玩家 |
| **第5级** | 次要相位 ∩ 冲突点命中 | 保留，设锚点 |
| **第6级** | 次要相位 ∩ 无命中 | 精简/删除，设锚点或留给玩家自填 |

### 7.5 精简原则：常量 vs 变量

排序完成后，按以下规则分配常量与变量：

| 位置 | 厂家设（常量） | 玩家设（变量） |
|------|--------------|--------------|
| **核心2相** | 硬规则 + 经济闭环 + 终极边界（风味浓度） | 组合/路径自由度（在常量框架内） |
| **次要2相** | 尽量少设或不设 | 叙事/路径自由度（最大放开） |

**原则**：核心相位里，常量管"不能崩的底线"，变量给"怎么玩的选择"。次要相位里，厂家只设"锚点"（如"你有一个死敌，请自己填是谁"），其余全交给玩家。

#### 7.5.1 自由度的设计维度（变量设计）

| 自由度类型 | 所属相位 | 设计方法 |
|-----------|---------|---------|
| **组合自由度** | 机制相位 | 提供足够多的"原子化能力"，让玩家自由组合产生化学反应（如：火球术 + 扩散 = 爆炸） |
| **叙事自由度** | 叙事相位 | 提供"留白"的锚点（如："你有一个死敌，请自己填是谁"），让玩家参与世界观构建 |
| **路径自由度** | 资源相位 | 设计网状的技能树，允许殊途同归 |

#### 7.5.2 框架稳定性的设计维度（常量设计）

| 稳定性类型 | 所属相位 | 设计方法 |
|-----------|---------|---------|
| **物理法则** | 机制相位 | 必须有不可逾越的"硬规则"（如：回合制、行动点数上限、距离单位）。防止游戏崩坏的底层代码 |
| **经济闭环** | 资源相位 | 必须有"Sink"（消耗口）。任何产出必须有对应的消耗途径，防止通货膨胀 |
| **终极边界** | 定向相位 | 设定不可调和的"哲学冲突"或"世界危机"，逼迫玩家做选择，防止玩家行为失去导向 |

#### 7.5.3 拓扑稳定性策略：结构洞与张力网

**结构洞**：在资源相位故意设计缺口（如：想学火系魔法必须先背叛水系导师）。这种"不可得"创造了戏剧张力，迫使玩家在弥补缺口的过程中产生故事，从而稳定了游戏的叙事节奏。

**张力网**：让相位之间互相牵制：

```
叙事相位（背景）──限制──→ 机制相位（可用技能）
机制相位（战斗结果）──修正──→ 资源相位（资产得失）
资源相位（资源耗尽）──推动──→ 定向相位（最终结局）
```

这种互锁结构保证了即便玩家在某一方面极度自由，其他方面也会产生制约，维持系统整体稳定。

### 7.6 四相位详细拓扑设计维度

#### 7.6.1 叙事相位（角色个人背景）：锚点拓扑

| 维度 | 内容 |
|------|------|
| **DNA来源** | 玩家身份（社会身份、维度身份、参与动机） |
| **设计目标** | 解决"我是谁"，确立玩家在世界中的坐标 |
| **拓扑结构** | 核心节点（姓名/种族/出身）→ 连线（角色与世界势力的关系）→ 锚点（限制角色不漂移的"钩子"：如债务、血仇、誓言） |
| **拓扑关系** | "点-线"关系。角色是点，背景是连接世界的线。稳定性来自"锚点"的束缚，自由度来自连线的方向 |

**设计维度参考**：

| 维度 | 设计内容 |
|------|---------|
| **动机维度（动力源）** | 推力（生存压力）：如"负债3点，每回合需还款"；拉力（探究欲望）：如"寻找失踪的妹妹（线索链）" |
| **秘密维度（信息差）** | 公开面（社会身份）：大家认为你是谁；隐藏面（维度身份）：你实际上是谁（如异端、卧底） |

#### 7.6.2 机制相位（角色互动相关）：流程拓扑

| 维度 | 内容 |
|------|------|
| **DNA来源** | 主要行为（探索、战斗、研究） |
| **设计目标** | 解决"我能做什么"，确立玩家与世界的交互规则 |
| **拓扑结构** | 输入端（玩家可用的能力列表：技能、装备）→ 处理端（检定系统：骰子、修正值）→ 输出端（结果表：成功、失败、complication/并发症） |
| **拓扑关系** | "流"关系。玩家注入意图（流），经过规则管道，转化为结果。稳定性由管道（规则）保证，自由度由注入的意图决定 |

**设计维度参考**：

| 维度 | 设计内容 |
|------|---------|
| **时间维度（时序性）** | 行动位：将时间切分为回合，保证框架稳定性；动作经济：限制每回合行动次数（如1标准+1移动），这是稳定性的基石 |
| **空间维度（位置性）** | 射程/触及：定义互动的有效范围（近战/远程）；移动拓扑：从A点到B点的路径博弈 |
| **因果维度（反馈性）** | 成功树：成功后的选项分支（造成伤害 或 追加效果）；失败树：失败后的代价分支（失去资源 或 剧情恶化） |

#### 7.6.3 资源相位（角色成长相关）：交换拓扑

| 维度 | 内容 |
|------|------|
| **DNA来源** | 成长方式（量变、质变、代价） |
| **设计目标** | 解决"我付出了什么"，确立成长的经济学 |
| **拓扑结构** | 资源池（HP、MP、金币、理智值等容器）→ 转换器（经验值→等级，金币→装备）→ 阀门（限制转换速率的上限：如等级上限、物品栏位） |
| **拓扑关系** | "守恒"关系。资源从一种形态转化为另一种形态。自由度在于玩家选择转化什么（如：加攻击力还是加防御力），稳定性在于总量守恒或转化效率固定 |

**设计维度参考**：

| 维度 | 设计内容 |
|------|---------|
| **代价维度（熵增）** | 消耗性：使用能力消耗资源（法术位/子弹）；损耗性：能力使用带来不可逆代价（如获得"堕落值"以换取力量）——维护稳定性的关键，防止无限成长 |
| **积累维度（量变）** | 熟练度：重复行为带来的修正值提升；收集度：道具与装备的拓扑扩充（背包系统） |
| **质变维度（重构）** | 进化树：解锁新机制（如二段跳、飞行），改变玩家的空间交互能力 |

#### 7.6.4 定向相位（角色IP目标）：层级拓扑

| 维度 | 内容 |
|------|------|
| **DNA来源** | IP目标、成长尽头（社会性、法则性、哲学性） |
| **设计目标** | 解决"我要去哪"，确立成长的终点与价值 |
| **拓扑结构** | 金字塔/同心圆结构：底层（物质追求：金钱、装备）→ 中层（社会追求：地位、势力建设）→ 顶层（哲学追求：改变世界观、神格化） |
| **拓扑关系** | "映射"关系。角色的成长轨迹映射到世界的层级结构上。稳定性在于世界层级是预设好的（如只有3个境界），自由度在于玩家决定在哪个层级停留或以何种方式升维 |

**设计维度参考**：

| 维度 | 设计内容 |
|------|---------|
| **层级维度（升维）** | 社会层：从流浪者到领主；法则层：从使用者到篡改者。设计手段：设置"门槛任务"，只有完成特定哲学抉择才能进入下一层级 |
| **终局维度（归宿）** | 角色退隐：达成社会性终点（退休）；概念升华：成为世界法则的一部分（成为神/怪物） |

```python
class Phase(StrEnum):
    """角色模板4大相位。不允许添加或修改。"""
    NARRATIVE = "narrative"    # 叙事相位（锚点拓扑）
    MECHANISM = "mechanism"    # 机制相位（流程拓扑）
    RESOURCE = "resource"     # 资源相位（交换拓扑）

class PhaseContent(BaseModel):
    """单个相位的内容定义。"""
    phase: Phase
    priority: int              # 排序优先级 1-6（见 §7.4.2）
    is_core: bool              # 是否核心相位（定调结果）
    structure_hit: bool        # 是否被结构洞命中
    conflict_hit: bool         # 是否被冲突点命中
    constants: list[dict]      # 厂家设的常量（硬规则/经济闭环/终极边界）
    variables: list[dict]      # 玩家填的变量（组合/叙事/路径自由度）
    anchors: list[str]         # 锚点（留白引导，如"你有一个死敌，请自己填是谁"）


class CharacterTemplate(BaseModel):
    """A2 Phase 4 输出 — 角色卡模板。

    不是完整角色卡，是约束框架/引导模板。
    给 GM 和 PC 用，引导玩家创建符合 IP 基调的角色。
    """
    world_ref: str                    # 指向 world_package.json 的引用
    module_ref: str                   # 指向 main_module.json 的引用
    dice_template_ref: str            # 指向 dice_template.json 的引用
    flavor_concentration: str         # 风味浓度声明（厂家设定的最佳游戏风味）

    # 排序元数据
    reality_dominant: str             # 现实规则主导（material/will）
    core_phases: list[Phase]          # 核心2相
    secondary_phases: list[Phase]     # 次要2相
    structure_hole: str | None        # 结构洞命中的存在物
    conflict_point: str               # 冲突点（玩家动机 × 世界哲学）

    # 4相位内容
    phases: dict[Phase, PhaseContent]
```

### 9.2 PlanningService 编排器

```python
class PlanningService:
    """A2 产品策划工作台 — 编排器"""

    def __init__(self, llm: LLMProvider):
        self.feature_extractor = FeatureExtractor(llm)
        self.genre_matcher = GenreMatcher()        # 纯规则，零LLM
        self.case_retriever = CaseRetriever()      # 纯JSON，零LLM
        self.plan_synthesizer = PlanSynthesizer(llm)
        self.module_composer = ModuleComposer(llm)
        self.dice_template_generator = DiceTemplateGenerator(llm)

    async def analyze(self, world: WorldPackage) -> ProductPlan:
        """Phase 1 only — 产品策划分析"""
        features = await self.feature_extractor.extract(world)
        raw_scores = self.genre_matcher.match(features)
        candidates = self.genre_matcher.filter_thresholds(raw_scores)
        cases = self.case_retriever.retrieve(candidates, features)
        return await self.plan_synthesizer.synthesize(features, raw_scores, candidates, cases)

    async def compose(self, world: WorldPackage, plan: ProductPlan) -> MainModule:
        """Phase 2 — 模组编成"""
        return await self.module_composer.compose(plan, world)

    async def plan(self, world: WorldPackage) -> MainModule:
        """完整 A2 管线 (Phase 1 + Phase 2)"""
        plan = await self.analyze(world)
        return await self.compose(world, plan)
```

## 附录 B: 设计决策记录

### B.1 为什么 A2 内部分四阶段？

**决策**: Phase 1（产品分析）、Phase 2（模组编成）、Phase 3（骰子模板生成）和 Phase 4（角色模板生成）独立可调用。

**原因**:
1. 厂家可能只想看"这个世界适合做什么"，还没准备好编模组
2. 产品分析结果是**厂家可见的交付物**，模组合成是**系统内部契约**
3. Phase 1 的 GenreMatcher 是纯规则引擎（<100ms），可快速响应；Phase 2 的 ModuleComposer 需要 LLM（3-5s）
4. 两个阶段可独立测试和迭代
5. Phase 3（骰子模板生成）依赖 Phase 1 的 ProductPlan + Phase 2 的 MainModule + A1 的 WorldPackage，产出 DiceTemplate 作为独立交付物
6. Phase 3 的骰子核心和难度系统是规则引擎（零LLM），等级系统判定和 ProductPlan 校准可选 LLM 辅助
7. Phase 4（角色模板生成）依赖 Phase 3 的 DiceTemplate，骰子模板为角色模板提供数值骨架
8. Phase 4 的映射+排序是规则引擎（零LLM），精简阶段可选 LLM 辅助

### B.2 为什么 MVP 不用向量数据库？

**决策**: 结构化 JSON + 特征向量点积。

**原因**:
1. 30-50 条案例 × 7 维特征，计算量极小（<1ms）
2. 案例库规模可控，线性搜索足够
3. 不引入新的外部依赖（ChromaDB/Qdrant）
4. `CaseRetriever` 接口设计为存储无关，未来可无缝切换

**升级条件**: 案例超过 500 条 + 需要语义搜索（自然语言查询案例）。

### B.3 为什么 7 维特征而不是更多？

**决策**: 7 维世界特征向量。

**原因**:
1. 对应 TRPG 世界的 7 个核心维度（探索/冲突/社交/悬疑/力量/叙事/生存）
2. 维度太多会导致矩阵噪声大，推荐不稳定
3. 维度太少会丢失区分度（如只有 3 维，开放世界RPG和生存建造无法区分）
4. 8 种游戏类型 × 7 维 = 56 个权重参数，手工调优可行

### B.4 A2 与商业分析 AI（用户说的 AI 3）的区别

**决策**: 商业分析不在 A2 范围内，远期独立模块。

**原因**:
1. A2 是**推荐系统**（这个世界适合做什么 → 类型匹配 + 案例推理）
2. AI 3 是**预测模型**（这个方向商业上值不值 → 市场数据 + 趋势分析）
3. 两者技术栈完全不同：A2 用 LLM+RAG，AI 3 用结构化数据+预测算法
4. AI 3 依赖大量商业数据（销量/评价/留存），A2 不需要
