## 1. A模块定位与阶段

### 1.1 核心定位

**A模块 = 创作系统 (Creation System)** — AI辅助的世界IP工业化生产工具，从世界品牌创造到可玩内容持续生产。

- **A1**: 世界观IP设计工作台 — 7生成器之①
- **A2**: 产品策划+模组工作台 — 7生成器之②③④⑤（策划可选增强）
- **A3**: 内容生产工作台 — 7生成器之⑥⑦
- **GM大厅**: 装配消费端

### 1.2 阶段划分

| 阶段 | 定位 | 存储方案 | 用户体系 | 功能范围 |
|------|------|---------|---------|---------|
| **M0验证** | 本地端到端跑通 | 本地SQLite+文件系统(data/assets/) | 开发者 | A模块全链路 |
| **MVP商用** | 商用最小闭环 | 云存储 | 真实用户+付费分级 | A模块+社区系统(B)基础版 |

**M0目标**: "一个新用户从选种子到大厅游玩跑通"

## 3. 工作台边界表

### 3.1 A1 世界观IP设计工作台

| 维度 | 内容 |
|------|------|
| **职责** | 种子选择→10板块引导访谈→语义编译→结构化文件→定稿图谱化→IP展板。7个独立生成器之①，可单独交付"只要IP" |
| **不负责** | 模组产品化（A2负责）、场景资产生产（A3负责）、GM运行时 |
| **输入** | 8预设种子之一（克苏鲁/赛博朋克/仙侠等）或自定义奇思妙想 |
| **输出** | IP图谱(graph_code=IPxxxx-W1-v1) + IP展板（氛围图+设定浮层）+ 结构化文件（图谱序列化导出） |
| **核心交付物** | IP展板（全屏氛围图+设定浮层） · 世界设定条目（10板块分组） · 知识图谱（约束节点+拓扑边） |
| **状态** | 🟡 M0开发中 |
| **MVP差异** | MVP需增加：多端适配、真实用户体系、云存储、付费分级 |
| **M0说明** | M0阶段存储=本地SQLite(data/assets/graph.db)+本地文件(data/assets/*.png)。图谱=内部数据结构，非前端交付物 |

### 3.2 A2 产品策划+模组工作台

| 维度 | 内容 |
|------|------|
| **职责** | ①策划分析（免费完整实现，LLM对话）→ ②AGENTS决策落定 → ③骰子投影（v+1版本化）→ ④角色投影（需骰子模板）→ ⑤主模组图谱化(finalize) |
| **不负责** | 世界观IP设计（A1负责）、场景资产生产（A3负责） |
| **输入** | A1图谱（显式选择，默认最新已定稿；stale图谱带变更集提示） |
| **输出** | 主模组图谱(IPxxxx-M{实例}-v1) + 骰子展板 + 角色展板 + 提示词组 + 主模组展板 |
| **核心交付物** | 骰子模板 · 角色模板 · 主模组展板 · 策划报告（免费可看） |
| **状态** | 🟡 M0开发中 |
| **MVP差异** | MVP需增加：策划报告存档（等级预留）、多端适配 |
| **M0说明** | 不带策划=免费TRPG线可用；策划分析免费完整实现非演示版。骰子/角色模板=图谱的类型化投影 |

### 3.3 A3 内容生产工作台

| 维度 | 内容 |
|------|------|
| **职责** | ①场景+资产扩写（LLM对话）→ ②提示词提取（标签→约束注入提示词）→ ③AI图片生成（异步+轮询+Wave分组） |

| **MVP差异** | MVP需增加：图片云存储、审批流程 |

## 5. 横切机制

### 5.1 四层编码体系

**编码规则**: `IP序号-阶段-实例-版本`

| 示例 | 解释 | 所属工作台 |
|------|------|-----------|
| `IP0001-W1-v1` | IP序号0001 - W1(World阶段) - 版本1 | A1输出 |
| `IP0001-W1-v2` | 同一IP的World阶段版本2（修改后） | A1修改分支 |
| `IP0001-M1-v1` | IP序号0001 - M1(Module主模组) - 版本1 | A2输出 |
| `IP0001-M1-S1-v1` | IP序号0001 - M1-S1(Module主模组-场景1) - 版本1 | A3输出 |

**版本规则**:
- 一切修改=追加新版本，永不就地覆盖
- 修改不污染铁律（详见§6）
- 版本v+1递增，旧版本保留

### 5.2 Stale图谱处理机制

**触发条件**: 上游变更（如A1重新定稿W1-v2）

**处理流程**:
```
A1重新定稿 W1-v1 → W1-v2
   ↓
自动标记下游图谱stale
   ├─ A2主模组图谱 M1-v1 → stale标记
   ├─ A3次级模组图谱 M1-S1-v1 → stale标记
   └─ 资产生成结果 → stale标记
   ↓
用户选择：
   ├─ 继续使用stale（留痕使用）
   └─ 重新生成（新版本v+1）
```

**关键原则**:
- Stale只标记，不删除
- 提示变更集，不阻断流程
- 用户可选择继续使用或重新生成

## 6. 核心规则

### 6.1 修改不污染铁律

**规则**: 一切修改=追加新版本，永不就地覆盖

**体现**:
- A1访谈内容修改 → 重新定稿 → W1-v2（W1-v1保留）
- A2策划决策变更 → 重新生成主模组 → M1-v2（M1-v1保留）
- A3场景扩写调整 → 重新生成 → M1-S1-v2（M1-S1-v1保留）

### 6.2 图谱=事实源

**规则**: 定稿后图谱为唯一真相，文件=图谱序列化导出，单向

**体现**:
- A1定稿后：图谱存GraphStore → 文件仅作为导出格式
- A2主模组生成：读取A1图谱 → 生成新图谱 → 文件仅作为导出格式
- 任何修改：修改图谱 → 重新导出文件（而非修改文件）

### 6.3 Stale不阻断

**规则**: 提示变更集，不阻断不删除

**体现**:
- 上游变更时自动标记stale
- 用户可选择继续使用stale图谱（带徽章提示）
- 不强制删除stale内容，由用户决定

### 6.4 GraphSelector上游显式选择

**规则**: 下游工作台必须显式选择上游图谱版本

**体现**:
- A2的GraphSelector默认选择"最新已定稿"图谱
- stale图谱带徽章提示变更
- 用户可主动切换历史版本
