## 1. 问题陈述

### 1.1 核心断点

约束体系（DimensionResultSet）与生成管线（PromptBuilder / PromptFusion）之间**存在完全断裂**。

```
语义描述 "浮岛群世界"
    ↓ LLM自由生成 ✅ 已实现
DimensionResultSet {
  LAW: { rules: ["浮岛群", "虚空边界"], mechanism: "..." }
}
    ↓ ↓ ↓
    ↓ ↓ ↓  ❌ 完全断裂
    ↓ ↓ ↓  Constraint 怎么变成 PromptBuilder 的字段？
    ↓ ↓ ↓  Constraint 怎么决定 NPC 的 skill_check 字段？
    ↓ ↓ ↓  同一个 LAW 在 NPC 层和 WORLD 层调用什么不同字段？
    ↓ ↓ ↓
PromptBuilder 8层模板 ← 完全不引用 DimensionResultSet
    ↓
最终 Prompt ← 没有约束注入
```

### 1.2 断点的本质

权重矩阵（6×6）只解决了**"LAW 在 NPC 层占 10%篇幅"**的问题，但完全没有解决以下问题：

| 问题 | 当前状态 |
|------|---------|
| **LAW 的 10% 篇幅具体调用什么字段？** | ❌ 不存在字段映射 |
| **同一个 LAW 在 NPC 层 vs WORLD 层调用的字段不同？** | ❌ 不存在层间差异映射 |
| **约束字段如何注入 PromptBuilder 的 8 层模板？** | ❌ PromptBuilder 不引用约束 |
| **约束字段如何影响拓扑节点/边的创建？** | ❌ 约束不参与图谱构建 |
| **语义描述如何编译为结构化标签=值？** | ❌ 约束输出是自由文本，无标签无枚举 |

## 2. 当前代码真实状态

### 2.1 约束输出模型——自由文本，无结构化标签

> **代码位置**: `backend/app/models/dimension.py` 第170-205行

```python
class RedOutput(BaseModel):
    forbidden: list[str]       # 自由文本列表
    note: str                  # 自由文本

class LawOutput(BaseModel):
    rules: list[str]           # ← 自由文本列表，没有结构化标签
    mechanism: str             # ← 自由文本

class ActOutput(BaseModel):
    actions: list[dict]        # ← 自由结构，trigger/check/success/failure

class NarOutput(BaseModel):
    style: str                 # ← 自由文本
    keywords: list[str]        # ← 自由文本列表
    tone: str                  # ← 自由文本

class WstOutput(BaseModel):
    effects: list[dict]        # ← 自由结构，name/type/magnitude

class SocOutput(BaseModel):
    relations: list[dict]      # ← 自由结构，target/type/value
```

**核心问题**：`LawOutput.rules` 是 `list[str]`——就是 `["高重力", "浮岛结构"]` 这样的自由文本列表。没有 `world_structure=FLOATING_ISLANDS` 这种**标签=枚举值**的结构化格式。

**后果**：
- 无法程序化判断"这条 LAW 约束是否包含世界结构信息"
- 无法程序化提取"浮岛群"→ 映射到 Geography.vertical_layer 枚举
- 无法程序化决定"这条 LAW 在 NPC 层应该影响 skill_check_method 字段"

### 2.2 DimensionPromptBuilder——按权重排序，但不分字段

> **代码位置**: `backend/app/domains/creation/constraint/dimension_generator.py` 第130-241行

**工作流程**：

```python
def build_system_prompt(self, layer, weights, intent):
    # 1. 按权重降序排列维度
    sorted_dims = sorted(weight_dict.items(), key=lambda x: x[1], reverse=True)

    # 2. 标注主要约束
    if weight >= 25: emphasis = "★主要约束"
    elif weight <= 5: emphasis = "（几乎不需要）"

    # 3. 构建 system prompt（按权重排序展示）
    # 4. 告诉 LLM "高权重多写，低权重简略"
```

**做了什么**：
- ✅ 查权重矩阵得到 NPC 层权重：SOC=30%, ACT=25%, NAR=20%, LAW=10%...
- ✅ 按权重降序排列，标注 ★主要约束
- ✅ 告诉 LLM "高权重维度多写，低权重维度简略"

**没做什么**：
- ❌ 没有定义"LAW 在 NPC 层应该关注什么"（比如：LAW 在 NPC 层应该描述"力量如何影响这个角色的身体"，而不是"世界的物理法则"）
- ❌ 没有层间差异提示（同一个 LAW 在 WORLD 层 vs NPC 层的语义焦点完全不同）
- ❌ 没有字段映射（LLM 返回的自由文本无法映射到下游的具体字段）

### 2.3 PromptBuilder——8层模板，完全不引用约束

> **代码位置**: `backend/app/domains/creation/asset/prompt_builder.py` 第48-150行

**8层模板**：

```python
# Layer 1 – World:     从 segments.world_prefix 读取
# Layer 2 – Location:  从 segments.space_prefix 读取
# Layer 3 – Camera:    从 camera_templates 按 LOD 读取
# Layer 4 – Subject:   从 objects[asset_id] + scene_data 读取
# Layer 5 – Gameplay:  从 scene_data 读取
# Layer 6 – Interaction: 从 scene_data 读取
# Layer 7 – Material:  从 segments.material_prefix 读取
# Layer 8 – Lighting:  从 style_words 读取

# 组装
layers = [world, location, camera, subject, gameplay, interaction, material, lighting]
return ", ".join(layer for layer in layers if layer)
```

**核心问题**：8层模板的每一层都从 YAML 文件 / 场景数据读取，**完全不引用 DimensionResultSet**。约束生成结果根本无法注入到 Prompt 中。

### 2.4 PromptFusion——3段式，只依赖图谱节点描述

> **代码位置**: `backend/app/domains/creation/asset/prompt_fusion.py` 第22-129行

**3段式**：

```python
def build_prompt(self, node, graph, completed_nodes):
    subject = node.description                    # 节点自身描述
    relation = [edge.visual_description ...]      # 依赖边的描述
    background = completed_nodes[bg_id].description  # 背景节点描述
    return assemble(subject, relation, background)
```

**核心问题**：PromptFusion 只使用 `GraphNode.description`（自由文本）和 `GraphEdge.visual_description`（自由文本），**完全不引用 DimensionResultSet**。

## 3. 缺失的完整链条

### 3.1 设计文档中设想的完整链条（应该有什么）

```
设计师输入语义 "这个世界是飘浮在虚空中的浮岛群"
    ↓
机器人引导（选用种子，细化世界观，填入IP问卷）
    ↓
异步 LLM 推理 → 语义解析
    ↓
约束编译器
    ├─ 语义 → 结构化标签（world_structure）
    ├─ 语义 → 枚举值（FLOATING_ISLANDS）
    ├─ 标签=值 → Constraint 节点
    └─ Constraint 节点 → 拓扑边连接
    ↓
DimensionResultSet（结构化的，不是自由文本）
    ↓
约束应用逻辑树 ← ❌ 当前完全不存在
    ├─ 查表：约束维度 × 生成层 → 调用什么字段
    ├─ 查表：字段 → 关联哪些拓扑节点/边
    └─ 查表：字段 → 注入 PromptBuilder 的哪一层
    ↓
Prompt 组装（约束感知的）
    ├─ PromptBuilder 8层模板 ← 注入约束字段
    └─ PromptFusion 3段式 ← 引用约束上下文
    ↓
结构化新节点（带约束继承的）
```

### 3.2 缺失环节清单

| # | 缺失环节 | 当前状态 | 影响范围 |
|---|---------|---------|---------|
| **A** | **语义→标签→枚举值 编译器** | ❌ 完全不存在 | Constraint 输出是自由文本，无法程序化消费 |

## 4. 逐个断点详细分析

### 断点 A：语义→标签→枚举值 编译器

**现状**：
```
设计师说："这个世界是飘浮在虚空中的浮岛群"
LLM 输出：LawOutput { rules: ["浮岛群", "虚空边界"], mechanism: "浮岛漂浮在虚空中" }
```

**需要变成**：
```
设计师说："这个世界是飘浮在虚空中的浮岛群"
    ↓ 语义解析器（LLM + 规则引擎）
    ├─ 标签识别: world_structure ← 从语义中提取"世界形态"概念
    ├─ 枚举映射: FLOATING_ISLANDS ← 从"浮岛群"映射到枚举值
    ├─ 标签识别: world_boundary ← 从语义中提取"世界边界"概念
    └─ 枚举映射: VOID_IMPASSABLE ← 从"虚空"映射到枚举值
    ↓
Constraint(LAW):
  world_structure: FLOATING_ISLANDS    ← 结构化标签=枚举值
  world_boundary: VOID_IMPASSABLE      ← 结构化标签=枚举值
```

**为什么需要**：
- 自由文本 `"浮岛群"` 无法被程序化消费（无法 `if constraint.law.world_structure == FLOATING_ISLANDS`）
- 只有结构化标签=枚举值才能驱动下游的字段映射和拓扑构建

**缺失内容**：
1. 标签词典（定义 LAW 维度下有哪些合法标签：world_structure / gravity / conservation / divine_intervention / afterlife / ...）
2. 枚举词典（每个标签有哪些合法值：FLOATING_ISLANDS / SPHERE / TREE / ...）
3. 语义→标签→枚举的映射规则（可以是 LLM + 规则引擎混合）

### 断点 B：约束输出模型的结构化

**现状**（`dimension.py` 第180-183行）：

```python
class LawOutput(BaseModel):
    rules: list[str]       # ["浮岛群", "虚空边界"]
    mechanism: str         # "浮岛漂浮在虚空中"
```

**需要变成**：

```python
class LawOutput(BaseModel):
    # 结构化字段（可程序化查询）
    world_structure: WorldStructure | None       # FLOATING_ISLANDS
    world_boundary: WorldBoundary | None          # VOID_IMPASSABLE
    gravity: GravityLevel | None                  # HIGH / NORMAL / LOW / ZERO
    conservation: bool | None                     # True=守恒 / False=非守恒
    divine_intervention: DivineLevel | None       # NONE / PASSIVE / ACTIVE
    afterlife: AfterlifeType | None               # DISSIPATION / UNDERWORLD / REBIRTH
    # 自由文本字段（补充描述）
    rules: list[str]                              # 保留，作为自然语言补充
    mechanism: str                                # 保留
```

**影响范围**：每个 Output 模型（RED/LAW/ACT/NAR/WST/SOC）都需要从自由文本升级为结构化字段+自由文本混合。

### 断点 C：约束应用逻辑树（核心缺失）

**现状**：完全不存在。

**需要什么**：

一个 **约束维度 × 生成层 → 字段调用映射表**，定义：

```
同一个 LAW 约束在不同生成层调用的字段完全不同：

                    WORLD 层              NPC 层              SCENE 层            ASSET 层
LAW.world_structure → Geography.vertical_layer  → 影响 NPC 的移动方式  → 影响场景的空间布局  → 影响物品的物理属性
LAW.gravity         → 地形塑造(RULE_SHAPES_GEO) → 影响 NPC 的移动判定  → 影响场景的重力描述  → 影响物品的重量描述
LAW.conservation    → 力量体系交互法则         → 影响 NPC 的技能消耗  → 影响场景的能量状态  → 影响物品的耐久消耗
LAW.divine_intervention → 事件因果链约束       → 影响 NPC 的命运判定  → 影响场景的奇迹事件  → 影响物品的神圣属性
```

**逻辑树的数据结构**：

```
约束应用逻辑树 = {
  (约束维度, 生成层) → [
    {
      source_field: "LAW.world_structure",       # 从约束的哪个字段读
      target_layer_prompt: "World",              # 注入到 PromptBuilder 的哪一层
      target_node_field: "Geography.vertical_layer",  # 影响什么节点字段
      target_edge_type: "GEO_ABOVE",             # 触发什么拓扑边
      transform: "map_to_vertical_layer_enum",   # 用什么转换函数
      priority: 1,                               # 在该层内的注入优先级
    },
    ...
  ]
}
```

**为什么是树而不是表**：
- 同一个约束字段在一个生成层可能有多个注入目标（LAW.gravity 在 NPC 层既要影响移动判定，又要影响身体描述）
- 注入目标之间有优先级（移动判定比身体描述重要）
- 这构成了一棵树：约束字段 → 分支到多个注入目标 → 每个目标有优先级

### 断点 E：约束→PromptFusion 注入

**现状**（`prompt_fusion.py` 第66-67行）：

```python
def _build_subject(node: GraphNode) -> str:
    return node.description
    # ← 纯文本描述，不引用约束
```

**需要变成**：

```python
def _build_subject(node: GraphNode, constraints: DimensionResultSet) -> str:
    base = node.description
    # 按约束增强描述
    if constraints.LAW.world_structure == WorldStructure.FLOATING_ISLANDS:
        base += f"（环境：{constraints.LAW.world_structure.value}）"
    # 按SOC约束添加关系描述
    for relation in constraints.SOC.relations:
        base += f"，与{relation['target']}存在{relation['type']}关系"
    return base
```

### 断点 H：层间语义焦点差异

**现状**：`DimensionPromptBuilder.build_system_prompt()` 对所有层使用同一个模板（第167-229行），只改变权重数字。

**问题**：

```
同一个 LAW 约束：

在 WORLD 层：
  LLM 应该关注："这个世界的物理法则是什么？重力如何运作？世界结构是什么？"
  语义焦点 = 世界级宏观法则

在 NPC 层：
  LLM 应该关注："这个 NPC 遵守什么物理法则？力量获取受什么法则约束？"
  语义焦点 = 角色级法则约束

在 ASSET 层：
  LLM 应该关注："这个物品的物理属性是什么？重量？材质受什么法则影响？"
  语义焦点 = 物品级物理属性
```

**当前**：system prompt 只说"LAW 在 NPC 层占 10%"，但没有告诉 LLM "LAW 在 NPC 层你应该关注角色的物理法则约束，而不是世界的宏观法则"。

## 5. 断点之间的依赖关系

```
断点 A（语义→标签→枚举编译器）
  ↓ 产出
断点 B（约束输出模型结构化）
  ↓ 被消费
断点 C（约束应用逻辑树）  ← 核心
  ↓ 驱动
断点 D（约束→PromptBuilder 注入）
断点 E（约束→PromptFusion 注入）
断点 F（约束→拓扑节点/边创建）
  ↓ 依赖
断点 G（约束继承传递）
  ↓ 独立但影响整体质量
断点 H（层间语义焦点差异）
```

**关键路径**：A → B → C → D/E/F

- 断点 A 是源头：没有结构化标签，后面全部无法程序化消费
- 断点 C 是核心：逻辑树是连接约束和生成的桥梁
- 断点 D/E 是出口：约束最终要通过 Prompt 影响生成

## 8. 结论

### 8.1 核心判断

> **约束体系（DimensionResultSet）当前是一个孤岛——它能生成，但生成结果无人消费。**

权重矩阵解决了"每个约束维度在每层占多少篇幅"的问题，但完全没有解决：
1. 篇幅里的**具体内容**是什么（语义→标签→枚举）
2. 这些内容**映射到什么字段**（约束应用逻辑树）
3. 这些字段**注入到什么位置**（PromptBuilder/PromptFusion）

### 8.2 缺失的不是代码，是设计层

断点 A/B/C 不是"代码没写"的问题——它们是**设计层面缺少了连接层**：

```
现有设计：
  第4套（世界观拓扑）→ 第1套（约束）→ [断裂] → 第2套（生成层）→ Prompt

需要补全：
  第4套 → 语义编译器 → 结构化约束 → 约束应用逻辑树 → 约束感知 Prompt → 生成
                         ↑                ↑
                    断点 A+B            断点 C
```

### 8.3 下一步建议

1. **优先设计约束应用逻辑树（断点 C）的框架**——它是整个连接层的核心
2. **同步设计标签+枚举词典（断点 A）**——它是结构化约束的基础
3. **逐层实现层间语义焦点（断点 H）**——成本最低但改善明显
4. **最后实现约束注入（断点 D/E）**——等逻辑树和词典稳定后再改 PromptBuilder/PromptFusion
