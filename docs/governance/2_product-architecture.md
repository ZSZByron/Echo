## 3. 系统边界定义

> **填写规则**: 每个系统明确"负责什么"和"不负责什么"，防止职责混淆。

### A1. 世界编辑器

| 维度 | 内容 |
|------|------|
| **职责** | 种子输入 → 6维约束生成 → 6维世界生成 → 知识图谱输出 |
| **不负责** | 模组层级区分（A2负责）、资产生成（A1只出图谱节点） |
| **输入** | 文本种子（用户输入） |
| **输出** | KnowledgeGraph + 6维DimensionResultSet |
| **边界争议** | <!-- 填写: 是否负责图谱拆分到各子图？目前断点D未定 --> |

### A2. 主模组编辑器

| 维度 | 内容 |
|------|------|
| **职责** | 从A1输出中筛选全局性内容，标注为MODULE层级 |
| **不负责** | 世界生成（A1负责） |
| **输入** | KnowledgeGraph（完整世界） |
| **输出** | main_module.json（ConstraintLevel.MODULE） |
| **状态** | ⚪ 不存在 — 见控制塔断点D |

### A3. 次模组编辑器

| 维度 | 内容 |
|------|------|
| **职责** | 继承主模组 + 覆写局部 + 合并为完整战役包 |
| **不负责** | 主模组内容定义（A2负责） |
| **输入** | main_module.json + 局部修改 |
| **输出** | campaign_package.json |
| **状态** | ⚪ 不存在 |

### A4. 装订成册导出器

| 维度 | 内容 |
|------|------|
| **职责** | 双输出：Markdown手册（人类）+ AI配置包（机器） |
| **输入** | campaign_package.json |
| **输出** | module_handbook.md + gm_ai_config.json |
| **状态** | ⚪ 不存在 |

### A5. AI GM 运行时

| 维度 | 内容 |
|------|------|
| **职责** | 三模式（助理/全自动/教学）+ 情感熔断 + 判例缓存 |
| **输入** | gm_ai_config.json + 玩家行为 |
| **输出** | 裁决结果 + 叙事文本 + 状态变更 |
| **状态** | 🟡 仅极简 /api/action |

## 7. 架构决策原则

> **填写规则**: 记录架构层面的设计原则，后续开发必须遵守。

| # | 原则 | 说明 |
|---|------|------|
| 1 | Schema First | 数据模型（Pydantic）是唯一数据契约源，先定模型再写服务 |
| 2 | 图谱不混层 | CORE/MODULE/SCENARIO 三个层级严格区分，不可平铺 |
| 3 | 约束可继承 | 约束沿图谱边传递，按权重过滤密度 |
| 4 | 生成可覆写 | 次模组继承主模组，CORE不可覆写、MODULE默认继承 |
