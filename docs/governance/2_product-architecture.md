## 1. 产品定位

> **一句话**: AI辅助的世界 IP 工业化生产工具
>
> **当前阶段定位**: AI辅助的世界 IP 工业化生产工具 — 从世界品牌创造到可玩内容持续生产
>
> **A1 核心理念**: A1 不是"输入一句话生成世界"，而是**"AI辅助完成一套专业世界观IP立项流程"**。类似建筑行业——客户不会填写钢筋型号，但建筑师通过功能需求表、风格偏好表、空间需求表把需求转化成设计方案。A1 的交互形态是**专业问卷 + AI设计顾问 + 自动结构化**，让厂家感觉像有一个资深世界观策划陪他做IP。
>
> **阶段划分**：
> - **M0 验证阶段**（当前）：A模块全链路本地端到端跑通。存储=本地SQLite+文件系统(data/assets/)。用户=开发者。UserTier仅枚举预留。"一个新用户从选种子到大厅游玩跑通"。
> - **MVP 商用最小闭环**：在M0基础上完成商用化改造——部署/云存储/真实用户体系/付费分级/多端适配。面向真实用户。MVP=A模块能力+社区系统(B)基础版+部署。

## 3. 系统边界定义

> **填写规则**: 每个系统明确"负责什么"和"不负责什么"，防止职责混淆。

### A1. 世界观IP设计工作台 [[2-A1-v0.2-6维约束体系×6层生成维度]] [[2-A-v0.3-A模块架构总览]]

> **核心定位**: 世界观 IP 设计工作台 (World IP Design Assistant) — 通过**引导式AI访谈**覆盖A1·采集维度集10板块，逐步编译为结构化文件。访谈期文件可自由修改（无图谱），10板块必答后**定稿(finalize)**触发文件→图谱一次性转换（约束建边）→存GraphStore。此后图谱=唯一事实源。
>
> **产品形态**: 不是"输入一句话生成世界"，而是"AI辅助完成一套专业世界观IP立项流程"。厂家感觉像有一个资深世界观策划陪他做IP。
>
> **交互模式**: 引导访谈（10板块）→ **语义编译三级匹配**（创新语句→AI分类提案二选一确认卡：归入现有字段/归入其他区；常规语句→直接写入结构化文件）→ **定稿前置校验**（缺板块→409+缺失清单回访谈补齐，齐→文件转图谱一次性转换）→ IP展板（修改分支：条目浮层→去修改→回访谈定位板块→重新定稿→W1-v2旧版保留）。
>
> **知识图谱不是交付物，而是后台支撑层。** 厂家不需要看到"五图模型"，五图模型只是 AI 和系统内部理解世界的方式。

| 维度       | 内容                                                                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **职责**   | 种子选择→10板块引导访谈→语义编译→结构化文件→定稿图谱化→IP展板。7个独立生成器之①，可单独交付"只要IP" |
| **不负责**  | 模组产品化（A2负责）、场景资产生产（A3负责）、GM运行时                                                                                                                                              |
| **输入**   | 8预设种子之一 或 自定义奇思妙想                                                                                                                  |
| **输出**   | IP图谱(graph_code=IPxxxx-W1-v1) + IP展板（氛围图+设定浮层）+ 结构化文件（图谱序列化导出） |
| **核心交付物**  | IP展板（全屏氛围图+设定浮层） · 世界设定条目（10板块分组） · 知识图谱（约束节点+拓扑边）                                                                                                                                  |
| **状态**   | 🟡 M0开发中 |
| **MVP差异** | MVP需增加：多端适配、真实用户体系、云存储、付费分级 |
| **M0说明** | M0阶段存储=本地SQLite(data/assets/graph.db)+本地文件(data/assets/*.png)。图普=内部数据结构，非前端交付物 |

### A2. 产品策划+模组工作台 [[2-A2-v0.2-产品策划顾问+模组合成]]

> **核心定位**: AI 策划顾问 + 模组生成器 — **双路径架构**：路径A完整策划线（策划增强线）或路径B跳过策划线（TRPG默认线），汇合于主模组生成。**策划是可选增强而非硬前置**。

| 维度        | 内容                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **职责**    | **双路径架构**：<br>**路径A - 完整策划线（策划增强线）**：<br> ①策划分析 POST /api/a2/analyze（游戏内容建议/类似IP推荐/风险提示）→ 多轮对话决策 → 决策落定POST /api/a2/decide（生成A2'文件）→ 查看策划报告GET /api/a2/report（免费完整实现）<br>**路径B - 跳过策划线（TRPG默认线）⚡**：<br> ④骰子投影生成器 → 骰子模板图谱（v+1版本化，输入A1图谱）→ ⑤角色投影生成器（依赖图谱+骰子模板）→ 直接进入主模组生成<br>**汇合**：<br> ③主模组图谱化 POST /api/a2/file/{id}/finalize → 主模组图谱IPxxxx-M1-v1（主模组展板+提示词组+A2''文件，TRPG默认标注+下位拓展） |
| **不负责**   | 世界观IP设计（A1负责）、场景资产生产（A3负责）                                                                                           |
| **输入**    | A1图谱（显式选择，默认最新已定稿；stale图谱带变更集提示）                                                                                                 |
| **输出**    | 主模组图谱(IPxxxx-M{实例}-v1) + 骰子展板 + 角色展板 + 提示词组 + 主模组展板+ 策划报告（路径A）|
| **核心交付物** | 骰子模板 · 角色模板 · 主模组展板 · 策划报告（免费完整实现）|
| **状态**    | 🟡 M0开发中 |
| **MVP差异** | MVP需增加：策划报告存档（等级预留）、多端适配 |
| **M0说明** | 路径B=免费TRPG线可用；路径A策划分析免费完整实现非演示版。骰子/角色模板=图谱的类型化投影。骰子/角色投影端点待定（流程图未指定具体路径） |

### A3. 内容生产工作台

> **核心定位**: 场景+资产扩写与AI生图工作台 — 基于主模组图谱进行场景扩写、标签→提示词提取、异步图片生成（版本化，审批后才可用）。

| 维度 | 内容 |
|------|------|
| **职责** | ①场景+资产扩写（LLM对话）→ ②提示词提取（标签→约束注入提示词）→ ③AI图片生成（异步+轮询+Wave分组） |
| **不负责** | 世界观IP设计（A1负责）、模组产品化（A2负责） |
| **输入** | 主模组图谱（显式选择，默认最新）+ 扩写参数 |
| **输出** | 次级模组图谱(IPxxxx-M{n}-S{实例}-v1) + 资产图片(版本化) |
| **核心交付物** | 场景/资产清单 · AI生成图片 |
| **状态** | 🟡 M0开发中 |
| **MVP差异** | MVP需增加：图片云存储、审批流程 |
| **M0说明** | 图片生成复用现有GenerationScheduler(Wave调度)。资产图片存data/assets/，通过StaticFiles提供 |

## 4. 系统依赖关系

> **A模块内部管线**: 线性依赖链 + 交叉约束注入

```
A1 工作台 (/a1)
├── 种子库 → 结构化文件基底
├── 引导引擎(状态机) → 语义编译器(断点A) → 创新捕获
├── 定稿图谱化(finalize) → GraphStore ← 断点F
├── IP展板 ← 图片生成器
└── [产出] A1图谱 + IP展板

A2 工作台 (/a2) — **双路径架构**
├── GraphSelector ← A1图谱（upstream显式选择）
├── **路径A - 完整策划线（策划增强线）**：
│   ├── 策划分析器 POST /api/a2/analyze ← A1文件/图谱
│   ├── AGENTS决策 ← 策划分析
│   ├── 决策落定 POST /api/a2/decide ← AGENTS决策（生成A2'文件）
│   └── 策划报告查看 GET /api/a2/report ← 决策结果（免费完整实现）
├── **路径B - 跳过策划线（TRPG默认线）⚡**：
│   ├── 骰子投影器④ ← A1图谱（v+1版本化，端点待定）
│   └── 角色投影器⑤ ← A1图谱 + 骰子模板（端点待定）
├── **汇合**：
│   ├── 主模组生成器③ POST /api/a2/file/{id}/finalize ← A1图谱 + 可选策划决策/骰子模板/角色模板
│   └── [产出] 主模组图谱 + 展板组 + 提示词组

A3 工作台 (/a3)
├── GraphSelector ← 主模组图谱（upstream显式选择）
├── 场景扩写引擎 ← 主模组图谱
├── 资产提示词提取 ← 次级模组图谱
├── 资产生成器 ← 含场景/资产节点的图谱
└── [产出] 次级模组图谱 + 资产图片

GM大厅 (/lobby)
├── LobbyLoader ← A3次级模组图谱或主模组图谱
└── [产出] 场景图 + 资产图 + 角色卡 + 骰子面板 + 交互终端

断点修复依赖链: T4词典 → T9(B) → T10(A) → T11(C) → T12(F) → T17(G) → {T24(D), T25(E)}, H独立
```

## 8. 架构决策原则

> **填写规则**: 记录架构层面的设计原则，后续开发必须遵守。

| # | 原则 | 说明 |
|---|------|------|
| 1 | Schema First | 数据模型（Pydantic）是唯一数据契约源，先定模型再写服务 |
| 2 | 图谱不混层 | CORE/MODULE/SCENARIO 三个层级严格区分，不可平铺 |
| 3 | 约束可继承 | 约束沿图谱边传递，按权重过滤密度 |
