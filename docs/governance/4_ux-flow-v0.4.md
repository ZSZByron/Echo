## 4. 核心用户流程详解

### Flow 0: 两阶段访谈生命周期（v0.3 新增，D21——权威流程；v0.4 步骤 2 扩充 D23）

| 步骤 | 用户心理 | 用户操作 | 系统反馈 | 状态 |
|------|---------|---------|---------|------|
| 1 | "我是来讲故事的/建设定的/说不清" | 平铺选卡：主卡 + 次卡 | 主∪次联合边界落定；开场问题（按主配方入口） | ✅ 选卡已有 / 🟡 次卡参与切换待施工 |
| 2 | "按我的路线聊" | 预设流程问答 | 配方问题逐个提出（**零内部模块名**）；fills 建议（确认措辞说人话）；**语义分流（D23）**：等价/细化 → 自动合并+轻披露+可撤销，补充 → 多值格追加子条目/单值格人话确认，矛盾 → 三选一（LLM 结合语境的人话提问，非模板复读），判定缺失 → 现行确认行为 | 🟡 已有（语义分流待施工） |
| 3 | "我提到了魔法/势力" | 顺着聊下去 | D20 邀约：顺势 2-3 个世界观问题后回主线（通知说人话，如「你提到了魔法——要聊聊世界的力量规则吗？」） | 🟡 开发中（16 红半成品，随后端施工补完） |
| 4 | （系统侧）配方问完 + fills 清零 | — | **收尾三连问面板**弹出；先展示「现在能生成什么」预览 | ⚪ 规划 |
| 5a | "先拿到手" | 选「生成文档」 | 产物管线输出，全部带 α 版本标记 | 🟡 管线已有 / ⚪ 版本标记显示待补 |
| 5b | "还能继续加" | 选「继续访谈录入设定」 | 进入自由流程：补齐所有模块 → 逐级细化（KG tier 分级，细化落点 = 层级条目树）；罗盘显示坐标倾向（全员） | ⚪ 规划（坐标接口已就绪） |
| 6 | "这条和之前说的有关" | 回答对齐推测卡 | 四动作卡（关联/去重/矛盾/更新）+ 三值判定；更新类带影响预警（「将使 M α0.1 过期」） | ⚪ 规划（推断包交互复用） |

## 5. 访谈体验规则（v0.3 新增，D21⑪⑫——文案与交互铁则；v0.4 增 §5.5，D23）

### 5.1 说人话（访谈全程）

| 场景 | 规则 | 示例 |
|------|------|------|
| 提问/追问 | **零内部模块名**——只问内容本身 | ✅「你故事的开场是哪一幕？」 ❌「【剧情模块·开场事件】请回答」 |
| 进度条/阶段名 | 人话描述，不列模块表 | ✅「聊聊你的世界 3/10」 ❌「IP定位 → 历史时间线 → …」 |
| fills 确认 | 说人话确认（**旧措辞「已记入【某模块】」就此废止**） | ✅「你刚才说的力量代价，我记下来了——对吗？」 |
| **推测卡（例外）** | **可提之前记录的内容**，但引用用户原话式自然语言转述，不报模块/字段名 | ✅「你之前说过『禁咒要献祭寿命』——现在这句怎么冲突了？」 ❌「【力量体系.cost】与已记录值矛盾」 |
| D20 邀约通知 | 说人话 | ✅「你提到了魔法——要聊聊世界的力量规则吗？」 |
| 图谱页/溯源层 | **维持模块名**（用户主动查「这句话进了哪个格子」，报名字建立信任） | 「IP定位」「历史时间线」照旧 |

### 5.2 不提示（静默原则）

冲动坐标驱动的路线/画像调整**静默执行**——不弹告知、不打断（D21⑩）。被动可见面仅罗盘独立组件（全员显示——**显示归显示，提示归提示**）。
**D23 边界注记**：语义合并轻披露（§5.5）不属于「路线调整提示」——它披露的是**内容写入动作**（可撤销），不是画像调整；两者互不混淆。

### 5.3 罗盘独立组件（D21⑫）

- 一句话坐标：「目前感觉你更像：讲故事的 70%」；
- 三值纠偏按钮：更像讲故事 / 差不多 / 更像建设定（推断包三值先例，**不做滑块**）；
- 全员显示；数据源 = `/impulse-coords`（已建）；**人格卡不存在**（工程占位已划除，挂靠选项作废）。

### 5.4 α 版本标记（D21⑬）

一切输出物（文档/图谱页/产物）可见标注版本：草稿期 α0.1 → α0.11 → α0.12 →…，定稿转 β → 数字版——用户随时可辨「手里的文档是哪一版、基于哪版图谱」。

### 5.5 语义合并与层级条目（v0.4 新增，D23——访谈内容写入的铁则）

| 场景 | 规则 | 示例 |
|------|------|------|
| **等价/细化 → 自动合并** | 不弹卡不阻塞；行内轻披露一句（人话，引新旧说法）；**一句话可撤销**（「不对就说一声」） | ✅「已把『平凡的度过一生』并入【欲望】——和之前说的躺平是一个意思，说得更完整了。不对就说一声。」 |
| **补充 → 追加子条目** | 多值字段（关键关系等设计上就多段的）自动追加为新一条 + 轻披露；**同类自动归并**（与已有某条是一个东西 → 并入那条，不另起一行） | ✅「记下了第三段关键关系：与老父亲（在老家务农）。」 |
| **矛盾 → 人话三连问** | 必须用户裁决（**不豁免**）；问题由 LLM 结合语境生成，**严禁模板复读**；旧「替换/合并/放弃」三副本模板收敛单点 | ✅「之前说主角是少年郎，现在这句『千岁老祖』——是以现在为准，还是两个都要，还是先放着？」 |
| **澄清回复** | 听不懂关键词（替换/合并/放弃…九词外）→ LLM 意图分类再行动；「都不是」走正常访谈主线；**绝不原文复读同一个问题** | ✅ 用户：「这两个是一个东西」→ 系统：（识别为合并/等价）照此执行 |
| **判定缺失兜底** | LLM 没给判定/接口异常 → 回落现行确认行为（宁可多问不可瞎合） | 行为不差于现状 |
| **条目树展示** | 多值字段以多条子条目列表展示（大类→小类→更小类 = 树展开）；旧单字符串视图由确定性渲染生成，溯源/图谱页不受影响 | 关键关系：①与大道系统… ②与老父亲… ③…（可展开） |
| **披露位置** | 聊天流内行内条（非弹窗、非阻塞）；合并留痕可查（file_diff/审计） | 同 D20 邀约通知的披露形态先例 |

**铁律边界（D23 豁免条款适用范围）**：仅限等价/细化合并免确认；真矛盾/覆盖性修改必须确认；图谱直写与不可动清单红线不动；LLM 判定 = 提议，引擎单点消费（D20 同模式）。
