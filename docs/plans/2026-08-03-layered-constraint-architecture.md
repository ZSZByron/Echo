# 分层创作约束体系 — 架构设计文档

> **日期**: 2026-08-03
> **项目**: H:\UGC — Echo UGC 游戏世界生成系统
> **状态**: 设计确认阶段

---

## 一、设计动机

### 问题

当前系统的五维生成（Story / Event / Asset / Culture / Constraint）是**扁平的**——任意种子输入 → LLM 补全五维。但实际跑团创作中，DM 需要在不同层级（世界观、场景、NPC、资产...）分别创作，每个层级关心的重点不同。

"魔法消耗理智值"是角色规则，跟地点描写无关。当前系统没有能力表达这种**约束归属**。

### 解决方向

将扁平的五维生成升级为**分层创作约束体系**：
- 6 类约束维度（What）描述约束的本质类型
- 6 层创作层级（Where）描述 DM 编辑的对象
- 权重矩阵（How much）描述每个层级中各约束维度的占比
- 知识图谱边关系（How connected）描述对象间的交叉关系

---

## 二、6 类约束维度（What）

每个创作对象（不管哪个层级）都由 6 类约束维度描述：

| 维度 | 缩写 | 描述什么 | 数据本质 | 判定方式 | 已有实现 |
|---|---|---|---|---|---|
| **内容红线** | RED | 禁止生成的内容（色情/暴力/教唆/世界观偏离） | 禁止清单 | 硬编码拦截，零 LLM | ❌ 待建 |
| **物理法则** | LAW | 世界运行的底层规则（重力/魔法体系/科技水平） | 规则函数 | 规则引擎确定性判定 | ✅ `physics.py`, `WorldRule` |
| **行为规则** | ACT | 角色行为→后果的判定逻辑（技能检定/社交反馈） | 判定逻辑 | 规则引擎骰子模拟 | ✅ `rules_engine.py` 部分 |
| **叙事约束** | NAR | 生成内容的一致性约束（风格/词汇/禁忌词/剧情模板） | 提示词模板 | LLM prompt 注入 | ✅ `trpg_presets.py` |
| **世界状态** | WST | 场景/区域的动态状态效果（天气/环境修正/区域 buff） | 修正值 | 状态机 + 修正值 | ⚠️ 部分 `GodKing` |
| **社交生态** | SOC | NPC 关系网/声望/阵营对玩家行为的反应 | 关系图谱 + 声望值 | 关系图遍历 | ❌ 待建 |

### 约束维度间的依赖关系

某些维度之间存在固有的执行依赖：

```
LAW ──依赖──→ ACT   （物理法则需要行为判定来执行）
SOC ──依赖──→ NAR   （社交关系需要叙事风格来表现）
WST ──依赖──→ ACT   （环境效果需要行为判定来触发）
RED ──独立──         （红线不依赖任何其他维度）
NAR ──独立──         （风格不依赖其他维度）
```

这个依赖关系在权重偏移检测时使用（见第六节）。

## 三、6 层创作层级（Where）

DM 在不同层级编辑不同类型的创作对象：

| 层级 | 英文 | DM 编辑的内容 | 典型编辑粒度 |
|---|---|---|---|
| **世界观** | World | 魔法体系、物理法则、文明等级、全局风格 | 整个世界设定 |
| **区域文化** | Region | 文化价值观、社会制度、阵营关系 | 一个文明/国家/教派 |
| **场景/地点** | Scene | 地图描述、环境特征、可互动物体 | 一个可探索地点 |
| **战役/剧情** | Campaign | 主线/支线任务、剧情分支、Boss 设计 | 一条任务线 |
| **NPC** | NPC | 角色属性、性格、秘密、关系网 | 一个角色 |
| **资产/物品** | Asset | 外观、属性、使用条件、副作用 | 一件物品/道具 |

### 每层的种子/预设作用与编辑器提示词

| 层级 | 种子/预设作用 | 编辑器提示词示例 |
|---|---|---|
| 世界观 | 选择全局风格包（voice+lexicon）+ 定义核心物理法则 | "这个世界的基本法则是什么？魔法如何运作？" |
| 区域文化 | 选择文化模板（价值观/禁忌/美学）+ 定义阵营关系 | "这个社会崇尚什么？禁止什么？" |
| 场景/地点 | 地点生成模板（环境/气候/危险度）+ 区域状态效果 | "玩家踏入这里时看到什么？感受到什么？" |
| 战役/剧情 | 叙事骨架模板（冲突/转折/结局类型）+ 剧情禁忌 | "这场战役的核心矛盾是什么？谁在对抗谁？" |
| NPC | 角色卡模板（属性/技能/性格/秘密）+ 社交位置 | "这个 NPC 想要什么？隐藏了什么？" |
| 资产/物品 | 物品规格模板（外观/功能/稀有度）+ 使用约束 | "这个物品怎么获得？怎么使用？代价是什么？" |

## 四、权重矩阵（How much）

### 核心原则

**不是开关矩阵——每个层级都受所有 6 类约束影响，只是权重不同。**

### 默认基线权重表

| | RED | LAW | ACT | NAR | WST | SOC | 合计 |
|---|---|---|---|---|---|---|---|
| **世界观** | 20% | 30% | 5% | 35% | 5% | 5% | 100% |
| **区域文化** | 10% | 10% | 10% | 20% | 5% | 45% | 100% |
| **场景/地点** | 10% | 25% | 5% | 10% | 40% | 10% | 100% |
| **战役/剧情** | 10% | 5% | 10% | 40% | 5% | 30% | 100% |
| **NPC** | 5% | 10% | 25% | 20% | 10% | 30% | 100% |
| **资产/物品** | 10% | 30% | 30% | 10% | 10% | 10% | 100% |

### 读法

- **世界观**：NAR 最高（35%）——世界观最重要的工作是定调风格。LAW 其次（30%）——底层物理/魔法法则。SOC 最低（5%）——世界观层不关注个体关系。
- **区域文化**：SOC 最高（45%）——阵营关系、社会制度是核心。NAR 其次（20%）——文化有自己的描述风格。
- **场景/地点**：WST 最高（40%）——环境效果是场景的核心。LAW 其次（25%）——局部物理修正。
- **战役/剧情**：NAR 最高（40%）——叙事结构是核心。SOC 其次（30%）——阵营博弈驱动剧情。
- **NPC**：SOC 和 ACT 并列最高（30%/25%）——社交关系和行为判定是 NPC 的灵魂。
- **资产/物品**：LAW 和 ACT 并列最高（30%/30%）——物理属性和使用判定是物品的核心。

### 权重的三个用途

**1. Prompt 占比分配**

权重决定每类约束在 system prompt 中的篇幅：

```
NPC 层生成时，SOC 权重 30%：
    → "社交上下文"段占提示词 30% 篇幅
    → 详细列出 NPC 的所属文化、初始好感度、阵营关系

NPC 层生成时，LAW 权重 10%：
    → "物理法则"段占提示词 10% 篇幅
    → 只提一句"这个世界魔法消耗理智值"，不展开
```

**2. 继承过滤强度**

权重决定上层约束传递下来的"密度"：

```
World 层的 LAW 约束（权重 30%）→ 向下传递时完整展开
World 层的 SOC 约束（权重 5%）→ 向下传递时只传摘要
World 层的 ACT 约束（权重 5%）→ 几乎不传递
```

**3. DM 编辑器 UI 优先级**

权重决定编辑页上每个维度的展示优先级：

```
NPC 编辑页：
    第一屏：SOC（社交关系）+ ACT（行为判定）—— 权重最高的两个
    第二屏：NAR（个性化风格）
    折叠区：LAW + WST + RED —— 权重低，默认继承不编辑
```

## 五、约束继承模型

### 传递规则

约束向下游传递，**只传递同维度的约束，不跨维度**。

```
World 层定义了:
  RED: "禁止露骨内容"        → 传递到所有下层的 RED
  LAW: "魔法消耗理智值"      → 传递到 Region/Scene/Asset 的 LAW
  NAR: "克苏鲁压抑风格"      → 传递到所有下层的 NAR
  ACT: 权重 5%，几乎不传递

Region 层定义了:
  SOC: "贵族派 vs 平民派"    → 传递到 NPC 的 SOC
  LAW: "等级制度话语权"      → 传递到 NPC 的 ACT（社会规则变成行为判定依据）
```

### 继承约束的 override 规则

**继承约束可以被局部 override，但不能被删除。**

DM 在下层可以收紧或调整上层传来的约束，但不能完全移除。

```
World: RED "禁止露骨内容"（全局）
  ↓ 继承
Region: RED override → "允许中度暴力，但禁止性相关内容"（局部收紧）
  ↓ 继承
Scene: 不能移除这条 RED，只能进一步细化
```

### 传递密度按权重过滤

```
对每个创作层级 L 的每个约束 C:
    C 的维度 = C.dimension (RED/LAW/ACT/NAR/WST/SOC)
    
    向下遍历所有子层级 L':
        如果 L' 的该维度权重 >= 10%:
            将 C 作为 "继承约束" 完整传递
        如果 L' 的该维度权重 5%-10%:
            将 C 压缩为摘要传递（只传标题不传细节）
        如果 L' 的该维度权重 < 5%:
            不传递
```

## 六、权重调整安全机制（方向 B：可调 + 基线）

DM 可以调整权重，但有三层安全防线：

### 第一层：硬性上下限

每个维度的权重在一个合法区间内：

- 下限：0%（完全不考虑该维度）
- 上限：60%（不能让单个维度挤压其他维度到不可用）
- 总和：所有 6 类权重之和始终 = 100%

### 第二层：偏移警告

当 DM 的调整导致某个维度偏离基线超过阈值时，编辑器显示醒目警告：

```
偏移量 = DM设定值 - 基线值

|偏移量| > 15% → 黄色警告 + 影响说明 + 场景建议
|偏移量| > 30% → 红色强警告 + 要求 DM 确认"我了解风险"
```

警告示例：

```
⚠ SOC 从 30% 调整到 50%（+20%）
  影响：NPC 的社交关系描述会占提示词一半篇幅，
        物理法则和行为判定的生成精度会下降。
  建议：如果这个 NPC 是"社交型角色"（外交官/商人），可以接受。
        如果是"战斗型角色"，请考虑回调。
```

### 第三层：冲突检测

当存在依赖关系的两个维度之间权重差过大时，提示冲突：

```
依赖对:
    LAW ──依赖──→ ACT
    SOC ──依赖──→ NAR
    WST ──依赖──→ ACT

对每个依赖对 (D1, D2):
    如果 |D1权重 - D2权重| > 25%:
        生成冲突警告
        解释依赖关系为什么会被破坏
```

冲突示例：

```
⚠ 检测到潜在冲突：
  LAW 调到 40%（强调物理法则）
  ACT 调到 5%（几乎不判定行为）
  
  但这个世界的物理法则（LAW）包含"魔法消耗理智值"，
  这是一条需要 ACT 判定的规则。
  ACT 过低可能导致这条法则在生成时被忽略。
  
  建议：LAW 和 ACT 的权重差不应超过 25%。
```

## 七、知识图谱边关系（不合并五图）

### 设计原则

五图保持独立维护和修改，在其上增加一层 **WorldKG overlay** 交叉边层。

交叉边只存 `(source_id, relation_type, target_id)` 三元组。五图各自保持独立查询能力，overlay 负责跨图遍历。

### 边类型定义

```
WorldNode (世界观):
    ──defines_NAR──→ 所有下层对象
    ──defines_LAW──→ Scene, Asset 对象
    ──defines_RED──→ 所有下层对象

CultureNode (区域文化):
    ──shapes──→ NPC 对象
    ──conflicts──→ 其他 CultureNode（阵营对立）
    ──defines_SOC──→ NPC, Campaign 对象

SceneNode (场景/地点):
    ──contains──→ Asset, NPC 对象
    ──applies_WST──→ 场景内所有 NPC 和 Asset
    ──overrides_LAW──→ 场景内物理修正

CampaignNode (战役/剧情):
    ──involves──→ NPC, Scene, Asset
    ──branches──→ 其他 CampaignNode

NPC:
    ──belongs_to──→ CultureNode
    ──located_at──→ SceneNode
    ──governed_by──→ ConstraintNode(ACT)

Asset:
    ──owned_by──→ NPC 或 SceneNode
    ──governed_by──→ ConstraintNode(LAW)
```

### 边的自动建立

**边在生成时自动建立，不是 DM 手动连线。**

DM 生成一个 NPC 并指定它属于"星辉教派"文化 → 系统自动建 `belongs_to` 边 → 世界观的 LAW 约束沿这条边传递到这个 NPC。

## 八、生成管线（完整逻辑链）

```
DM 选择创作层级 (如 NPC)
    ↓
系统加载该层级的默认权重表
    NPC: RED=5%, LAW=10%, ACT=25%, NAR=20%, WST=10%, SOC=30%
    ↓
DM 可选：微调权重（附带偏移警告 + 冲突检测）
    ↓
沿知识图谱边收集继承约束（按权重过滤传递密度）
    World 的 NAR(35%) → 完整传递到 NPC 的 NAR(20%)
    World 的 LAW(30%) → 压缩传递到 NPC 的 LAW(10%)，只传核心条目
    Region 的 SOC(45%) → 完整传递到 NPC 的 SOC(30%)
    ↓
合并 DM 的局部 override 约束
    ↓
按权重比例组装提示词（SOC 占 30% 篇幅，ACT 占 25%...）
    system_prompt = [
        RED段 (5%): 禁止清单
        LAW段 (10%): 核心法则摘要
        ACT段 (25%): 行为判定规则详情
        NAR段 (20%): voice + lexicon + 个性化风格
        WST段 (10%): 当前环境效果
        SOC段 (30%): 社交关系上下文
    ]
    ↓
LLM 生成 NPC 内容
    ↓
自动建边 (NPC─belongs_to→Culture, NPC─located_at→Scene)
    ↓
DM 确认 → 存入知识图谱 → 回馈规则表
```

## 九、内容红线拦截（RED 维度的特殊处理）

RED 是唯一不经过 LLM 的约束维度。它在管线的最前端执行硬编码拦截。

### 三类 RED 约束

| 类型 | 来源 | 示例 |
|---|---|---|
| **系统级红线** | 硬编码，不可修改 | 色情内容、教唆犯罪、极端暴力 |
| **世界观红线** | DM 在 World 层定义 | "这个世界没有时间旅行""禁止出现火器" |
| **场景红线** | DM 在 Scene 层定义 | "寺庙内禁止暴力行为" |

### 拦截流程

```
玩家/DM 输入 → RED 拦截器检查
    ↓
命中系统级红线 → 直接拒绝，返回错误
命中世界观红线 → 拒绝，提示"违反世界观设定：{reason}"
命中场景红线 → 标记为"需要 DM 确认"，不直接拒绝
未命中 → 进入正常生成流程
```
