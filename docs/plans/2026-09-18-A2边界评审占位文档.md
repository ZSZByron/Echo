## 1. 为什么需要这次评审（三个触发因素）

| # | 触发因素 | 对 A2 的冲击 |
|---|---------|-------------|
| 1 | **角色前置模块（第 0 模块）进入 A1**（[[2026-09-18-impulse-entry-system-spec]] §7） | 角色数据的生产方从"A2 角色投影器独占"变为"A1 前置速写 → A2 投影"两段血缘；A2 的 CharacterTemplateSpec 需要决定如何消费 character_sketch 种子输入 |
| 2 | **类型路由的 A2Mode 意向**（同上 §5） | 剧情/哲理型默认 PLANNING 的假设在 A2 P2 落地前无实效；策划线（planning_analyzer/report_generator）对这两型的价值假设需要重估 |
| 3 | **疗愈型轻量化裁决 + 爱情型 A1 极简化** | A1 阶段 5/10 模块 ai_fill 预填意味着下游 A2 消费的 A1 图谱中 AI 代劳占比可过半——A2 投影器的 signal_sources 溯源语义需要与 A1 field_sources 对齐 |

## 2. 待评审问题清单（预注册，评审时逐条裁决）

1. **角色数据血缘**：character_sketch（A1 前置槽）→ TC（A2 角色投影）的合流策略——投影器是否接受 sketch 作为种子输入？sketch 结构化字段集是否与 CharacterTemplateSpec 四相位对齐或映射？
2. **A2Mode 意向生效时点**：E1 起记录的 PLANNING 意向，在 A2 P2 落地前的展示语义（占位推荐 vs 隐藏）
3. **策划线价值重估**：剧情/哲理型的 PLANNING 默认假设是否成立（入口埋点数据可用后回看）
4. **FREE 线默认性**：类型路由预设是否会实质改变"A2 默认免费线"的 B6 裁决
5. **A2 十模块布局调整**：`domains/creation/a2/` 十文件设计是否因上游入口系统调整（尤其角色线两段化）
6. **field_sources → signal_sources 语义对齐**：A1 的人工/AI 作答溯源如何流入 A2 投影器的信号源体系
7. **StageCode 封闭约束复核**：角色两段血缘是否在现有 W/TD/TC/R 枚举内自洽（预期可以，评审确认）
