## 先打个比方，看懂现在的系统

现在的系统像一家**定制旅行社**：

- 你进门先选一张「旅行卡」：剧情、爱情、角色驱动（故事线 3 类）＋哲理、设定重度、探索、怀旧、疗愈（设定线 5 类）——**一共 8 类**；外加一张「说不清」＝**通用线**入口（独立路线，不算第 9 类）。
- 每张卡背后绑了一条**固定路线**（技术上叫「配方」：规定先问什么、后问什么）。
- 选完卡，导游（AI 访谈）就按这条路线带你走，问完所有该问的，给你成品（图谱、文档、骰子）。

这个比方贯穿全文。下面六个问题，全部围绕这家旅行社。

## 问题一：8 类 + 通用线平铺（两级选择已否决，归类已锚定）

进门就是 8 张类型卡 + 1 张「说不清」通行证，一字排开，没有分组。剧情、疗愈、设定重度摆在一起，你得自己分清哪张跟哪张是一路人。

## 问题二：「说不清」的用户，系统不会随机应变

**现在是什么样**：
选「说不清」卡的人被送上**故事侧固定路线**。准确说：说不清有自己的独立配方——和剧情党走同样的模块（先剧情后角色），但开场问题不同（问「开场事件」，不是剧情党的「核心抉择」）。之后不管你答得多像设定党——比如你一直在讲魔法体系怎么运转——系统**完全不理会**，照样按固定路线走到黑。

**你要的是什么**：
说不清的用户先走故事路线，然后系统**根据他的实际回答，慢慢把路线掰向他真正想要的方向**。他越聊越像设定党，就该越来越多地问设定问题。
**（2026-09-27 修订 4 续批：两阶段访谈生命周期，续批二细化）**每个冲动分类的收集流程（= 配方）即**预设流程**，跑完即**初步数据收集**；**主、次冲动卡的配方结合询问，随用户需求在两配方间动态切换**（续批二新机制）。预设流程完成（**配方问题问完 + 填完内容**——fills 待确认清零，续批八双条件）后进入**收尾询问**：先告知用户**当前能生成什么样的成果**（基于已有答案的产物预览），再问「生成文档，还是继续访谈录入设定」；选择继续——或**中途打断**（用户要输入的内容超出主、次两个配方，均不相关）——则进入**自由流程**，冲动坐标此时激活（全员）：根据已记录的内容，先引导**补齐所有模块**，然后**逐级细化模块（分级依据 = 知识图谱深度等级 tier）**。

- 访谈窗口本就唯一：单会话单窗口（一个聊天界面全程承载，预设流程与自由流程同窗）——不存在独立分窗的「世界观工坊/故事工坊」；
- 但访谈中的 LLM 只做三件事：追问、fills 字段级建议、锚定关键词跨字段深化（雏形）——**不会参照知识图谱的已有内容做对齐**；
- 图谱侧的对齐发生在**定稿之后**：graphify 单点编译 + 概念边提取（LLM 提议 + 用户确认/拒绝）——访谈中零参与。

**你要的是什么（09-27 裁决）**：
故事与世界观在同一个访谈窗口录入（确认既有单窗架构，预设+自由流程同窗完成全旅程）；**LLM 在访谈中自动对齐知识图谱里的内容**——用户输入与图谱已有内容自动关联、去重、一致性校验、更新提示。

**差在哪**：
- ~~「3 张知识图谱」待确认~~ → **已拍（09-27 续批四）：B = W 世界图 / M 模组图族（含 TD/TC）/ S 场景图**，对齐在**同一会话内**进行（图谱 = 会话自身阶段性编译产物，不涉新会话）；
- 访谈中 LLM 读图谱 = **新的 LLM 消费路径**（现状 LLM 生产方封闭三处：interviewer / module_compile / inference_pack；图谱内容进访谈 prompt 涉及上下文预算与治理扩点评审）；
- **两条铁律约束落地方式**：① 数据形态单生产单消费（NL→SIR→KG 各一个生产方）；② LLM 只在 graphify 单点产出结构、图谱由确定性代码装配——因此访谈中的「对齐」只能以 **LLM 提议 + 确定性校验 + 用户确认** 模式落地（推断包「对/不对/接近」先例），LLM 绝不直写图谱。

**怎么解（建议方案，09-27 续批四提出，待产品方确认）——会话内「编译 → 对齐 → 继续」循环**：
1. **阶段性草稿编译**：每个收尾询问点可选触发草稿编译——W 图谱先行（graphify 现有能力）、故事内容够料后 M 模组族跟上（module_compile 现有）、场景内容出现后 S。全部同会话同 file，复用 D15/DN4 既定的 **α 草稿版本递进**（0.1→0.11→0.12→定稿 β→…）与 stale 传播；
2. **图谱摘要注入访谈**：interviewer 获得已编译图谱的**紧凑摘要**（每模块关键实体/条目清单，非全图注入——上下文预算可控）；此为新 LLM 消费路径，随立项走治理扩点评审；
3. **对齐四动作**（全部 = LLM 提议 + 用户确认，复用推断包「对/不对/接近」交互）：**关联**（输入与图谱条目相关 → 概念边提案）/ **去重**（图谱已有 → 提示复用不重录）/ **矛盾**（与已有内容冲突 → 提示二选一）/ **更新**（应改某条 → 提案 + 影响预警「将使 M v1 过期」——甲计划 L2 既定设计）；
4. **触发时机**（推荐）：每轮轻量（实体/关键词命中检测——扩展现有「锚定关键词跨字段深化」雏形）+ 模块边界深对齐（全量比对）；
5. **铁律不动**：对齐提案是 NL 层动作，LLM 绝不直写图谱；图谱实际变更只经 graphify 确定性重编译，stale 走既有传播。此循环同时是**逐级细化的执行引擎**（每循环深化一级 tier）。
6. **输出前识别知识图谱**（续批五）：每次输出（含收尾询问的产物预览）前，先**确定性识别**图谱状态——模块覆盖/缺口/版本链/stale（纯代码盘点，非 LLM 动作）；「能生成什么样的成果」预览与缺料「降级 + 诚实标注」均以识别结果为**唯一来源**；
7. **输出物版本标记**（续批五）：一切输出物（文档/图谱页/产物）**可见标注版本**，草稿期从 **α** 起（α0.1→0.11→…，定稿转 β→数字版——对齐并延伸 D15/DN4 版本语义到输出层）；循环中已输出的文档 = α 草稿态，每次重编译递进版本号——用户随时可辨「手里的文档是哪一版、基于哪版图谱」。

**需要你拍板什么**：
9. ~~「3 张知识图谱」指哪三个~~ → **已拍（09-27 续批四）：B（W/M/S）+ 不建新会话**（对齐全在 同一会话内）；剩：**上述建议方案确认**——对齐动作集与触发时机已给推荐值，确认即立项。
