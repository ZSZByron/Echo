# 访谈知识求助搜索——问题说明书（联网知识通道：触发语义 + 知识对话态）

## §0 定位与边界

- **性质**：产品方 2026-10-09 两次真机实测撞墙（原话要旨："你不告诉我医疗常识，我怎么编写剧情！还是说那你就完全没有搜索资料的功能？" / "垃圾AI根本看不懂用户的需求！"）→ 排查发现「联网搜索」功能**存在但从未生效**，抢救修复后真机验证通过；修复过程中转录取证又暴露五个新病灶 → 本文件 = 故障取证 + 修复留痕 + 病灶清单 + 预设方案 + 拍板清单。
- **病理样本**：产品方两次故事线访谈全程转录（①精神病院腕带线：用户向 AI 求医疗常识被反复引回主题；②风中旅人线：搜索通道首次真实生效后，追问被误填 + 序号错配 + 分支丢弃连环事故）。
- **本文件不做的事**：不含拍板结论（拍板清单待产品方逐项裁决）、不立项、不动台账、不升任何既有文档版本。
- **与既有决策/文档的关系（全部正向兼容，无推翻）**：
  - **方向A一期（选项前置，2026-10-09 收官）**：本文病灶 P3 即其二期遗留①②的严重度升级证据（"无感"→"吃错答案"），归口二期收口，不推翻一期任何裁决；
  - **D23（语义合并/条目层级化）**：病灶 P2 是其 B 部分「多值字段结构性矛盾」的第二实锤（第一实锤 = M11 key_relations），属增补项非翻案；
  - **2026-10-08 灵感式访谈引导说明书**：病灶 P1（讨论意图无通道）正是其方向 B「镜子-扩音器循环」的新实锤，本文为该方向补充证据不提前拍板；
  - **D21（说人话）**：病灶 P5（挫败信号）是话术层小锤，随任一批顺带；
  - **北极星备忘**：搜索通道 = 「AI 负责扩展可能性」原则的脚手架落地——用户创作需要领域知识时 AI 能即时供给，正是八环链条中「AI 赋能」一环的服务面。
- **术语注记**：本文「知识求助」指——用户在访谈中向 AI 提出领域事实性问题（如"精神病院腕带代表什么"），期待 AI 检索后给出有据回答再引回创作；对照「用户困惑」（现行规则 7 语义）指——用户听不懂访谈问题本身，需要概念解释与灵感启发。两者共用搜索管线但触发语义与话术形态不同。

### 2.2 三重故障（2026-10-09 诊断实证）

| # | 故障 | 证据 |
|---|---|---|
| F1 | **密钥是占位符**——搜索从未出过网 | `backend/.env` L62 `ZHIPU_API_KEY=your-zhipu-api-key-here`（23 字符，从 .env.example 原样拷贝）；直连冒烟两端点均 401 |
| F2 | **旧端点契约已死** | 原 `/api/paas/v4/tools`（`{"tool":"web_search",...}`）→ 有效 key 下 HTTP 400 错误码 1211「模型不存在」——智谱已改契约，旧形状**必然失败** |
| F3 | **触发语义缝隙** | 规则 6（interviewer.py L514-515）："输入是**提问**……guidance_reply 回应用户并把话题引回当前问题"——知识求助被归类为跑题；规则 7（L516-519）只覆盖「用户不理解当前问题/概念」。**用户向 AI 求知识这个意图在语义设计里不存在** |

三者叠加的工程教训：F1/F2 均被降级契约静默吞掉（返回 ""），加上零测试覆盖 + 前端零披露 → 功能死了无人知晓。

## §5 预设方案方向

### 方向 1（推荐）：扩触发语义 + 知识对话态（纯后端，前端零触碰）

- **触发扩展**：规则 6 处新增判定——用户向 AI 提领域事实性问题时，置搜索标志（复用 `user_confused` 键或新增 `knowledge_request` 键，倾向后者：语义诚实、旧解析器忽略未知键向前兼容〔D20 worldview_invites 先例〕）+ `search_query`，走既有两段式管线；二次生成指令改为「先一两句有据回答事实问题 → 再给基于资料的创作选项 → 自然引回当前问题」。
- **知识对话态**（本轮新增，P4 对策）：session 级标志——知识回答后 N 轮内（或直至用户给出明确创作内容），追问优先走搜索通道且 **fills 冻结**，杜绝"公司职员请具体"误填【对手】；对话态退出条件（用户回故事内容 / 显式确认采纳 / 超时轮数）随施工单细化。
- **诚实披露**：guidance_reply 尾注「已联网查证」（对齐项目铁律 3 诚实与可观测）。
- **顺带清偿**：web_search.py 契约测试（降级契约 + 新端点形状）；wildcard 功能治理收编（随本方向立项登记 decision-log）。

### 方向 2：前端「查一下」一键按钮

输入框旁显式按钮强制触发搜索管线。用户可控不漏触发；代价 = 新端点 + 前端组件 + 访谈 UI 变更（触碰方向A一期"reply 纯文本行前端零触碰"的边界外）。

### 方向 3：两者兼有

LLM 自动判定为主 + 按钮兜底。工作量 = 1+2，可分期不返工（方向 1 先行，按钮视 E0 触发率数据二期补）。

### 推荐路径

**方向 1 先行**（复用 §3 已验证管线，改动最小）→ 真机观察触发率与误触发 → 视数据决定是否二期补按钮。P3 并入方向A一期二期收口批；P2 随 D23-B 增补；P1 等镜子-扩音器方向拍板；P5 顺带。
