## 2. 逐点对策

### W2 定稿编译（最大痛点）→ **后台预编译**

- **现状**：用户点定稿 → graphify 一次吃 35 字段 ×≤2000 字 → 等 LLM 返回 SIR → 确定性装配。答案越满等越久——**奖励了认真创作的用户更长的等待**，方向性错误。
- **对策**：访谈过程中**每完成一个模块，后台立即预编译该模块的 SIR 片段**（module_summaries 该模块行 / entries 该锚点集）；定稿时 90% 工作已就绪——只需确定性合并 + LLM 仅补**跨模块 edges**（甚至全量预编译后 edges 也可增量补）。
- **收益**：定稿等待 20-60s → **2-5s**（或骨架即返+edges 异步补齐）。

### W3 主模组增强 → **乐观装配推广**

- 免费线"确定性骨架先行、LLM 增强异步补"已是正确设计（A2 回收）——把它从"降级路径"升格为**默认体验**：finalize 秒回骨架版文字版，增强版完成后推送差异（stale 式标记，不整篇重写）。

### W1 每轮访谈 → **流式 + 预热**

- 流式输出（SSE）：首 token 感知延迟从整段 5s → 1s 内开始逐字出——**感知痛度降一个量级**，实际时长不变。
- 预热：会话开始时预构建 prompt 组件（锚点串/字段目录/规则块拼装是纯字符串操作，毫秒级但可省）。
- 偏转路径已是零 LLM（M0 占位写入）✅。

### W4/W5 理解类生成 → **并行化**

- 开场叙事与时间线骨架**并行**（互不依赖）；推断包与提案 UI 渲染并行（答案一到即启，用户还在读题时已在生成）。
- 流式同样适用。

### W6/W7 上传链 → **分模块渐进**

- 35 字段解析可按模块分批：先解析 M1-M3（用户先看到世界观核心预填确认），M4-M9 后台续析渐进填充——确认页从"等 30s 看全量"变"3s 看到第一批、其余陆续到位"（带进度条）。

### W8 场景族 → **批量并行**

- N 幕场景扩写互不依赖 → 并行请求（并发上限可配）；L2 侧 scope/公理校验是确定性前置（毫秒）。

### W9 资产 → **维持异步状态机**（pending→generating→pending_review），UI 已是轮询+状态徽章，无需改。

## 3. 精炼成模块的候选（三个新服务模块 + 一项基建）

### 候选 A：`pre_compiler`（后台预编译服务）★最大收益

```python
# L1 服务模块（同 seed_invoker 注册为 service 类——不采集不进门禁）
def on_module_completed(session, module_id) -> None:
    """访谈每模块达标即触发：增量生成该模块 SIR 片段，缓存于 session.precompiled"""
def merge_at_finalize(session) -> PartialSIR:
    """定稿时确定性合并全部片段；仅跨模块 edges 留给 graphify（或异步补）"""
```
- 性质：**可选服务**（关闭则回退今日全量 graphify 行为，正确性不变——与种子模块同款"提效不必须"哲学）
- 成本：每模块一次小 LLM 调用摊薄定稿大调用（总 token 略增，体验质变）

### 候选 B：`optimistic_assembler`（乐观装配器）

- L2 通用化：一切 LLM 增强产物（主模组增强版/开场叙事/人格卡解读）先秒回确定性骨架 + 异步增强 + **差异推送**（沿用 stale 标记模式，不整篇重写）
- 资产状态机的文本版推广

### 候选 C：`parallel_orchestrator`（并行编排器）

- 产出批（骰子/角色/文字版骨架/场景族/开场叙事）依赖图调度：无依赖并行、有依赖流水（角色←骰子）；复用 signal_requirements 即依赖图，零新数据

### 基建 D：**流式网关**（非模块，基建）

- interviewer / inference_pack / opening_narrative / scene 文本统一走 SSE 流式；前端打字机已有先例（useTypewriter 组件复用）

## 4. 优先级矩阵与波次建议

| 候选 | 用户收益 | 实现成本 | 风险 | 建议波次 |
|---|---|---|---|---|
| A pre_compiler | ★★★（定稿 60s→3s） | 中 | 预编译片段与最终 graphify 一致性需增量契约测试（C8 扩展） | M4 前置或并行（依赖 M1b registry） |
| B optimistic | ★★★（产出秒回） | 低（免费线模式推广） | 差异推送 UI 复杂度 | M3 顺带（产出模块本批） |
| C parallel | ★★（总时长÷N） | 低 | 并发限流 | M3 顺带 |
| D streaming | ★★★（感知质变） | 中（全链 SSE） | 前端改造面 | M2-M3 渐进 |

**原则总结**（写入工程纪律候选）：①确定性优先——凡能查表不调 LLM（种子匹配/RAG 已示范）②大任务摊薄——访谈中预编译替代定稿大编译 ③乐观返回——骨架先行增强异步 ④无依赖必并行 ⑤慢的都流式或异步状态机。
