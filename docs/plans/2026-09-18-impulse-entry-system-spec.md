## 1. 问题定义与现状确认

### 1.1 产品判断（产品方原话的转译）

用户创造世界时往往不专业、无完整设定，凭一时兴起进入。**LLM 持续创作的兴奋感是承接用户冲动、保持粘性的唯一抓手**。首次交流必须：聚焦用户最关心的问题，AI 给出提问和关联内容的推断，让用户自己判定是否正确——从用户动机出发，而不是套系统模板。

### 1.2 现状锚定（工程事实，本版所有分期的地基）

| 事实 | 状态 | 含义 |
|------|------|------|
| A1 世界观工坊 MVP **已完成** | 1020 测试基线 / 16 端点全链可用（上传预填、访谈 fills/proposal/confirm、门禁、graphify、双树图谱、展板、warning ledger） | 入口系统的全部近期依赖都在 A1 域内 |
| A2 **未启动** | 09-17 规格书已定稿（十模块设计/StageCode/A2Mode/P0-P3 分期），**零代码**；P0（主模组文字版）基线 2026-09-26 | 一切 A2 承接（TC 角色投影 / TD 骰子投影 / 策划线）= **无期依赖**，入口系统不得调用、不得承诺 |
| 动机信号在系统中为零 | interviewer prompt 唯一用户上下文是种子信息（`_seed_block`） | 入口系统填补真实空白 |
| 一刀切 TRPG 全家桶 | 门禁 = 全部 10 模块各超 50% 真值（`FINALIZE_MODULE_THRESHOLD=0.5`），剧情党被迫答骰子设定 5 字段 | 类型差异通过模块顺序与 ai_fill 预填实现，**不动门禁语义** |
| Persona 全靠想象 | 两个 persona 无任何用户研究证据（[[前端拷问]] Q5）；访谈是强制主路径（Q6） | 入口埋点 = 项目第一批真实用户数据 |

### 1.3 定位声明

入口系统 = 在 `session/start` 与首轮访谈之间插入**动机识别层**，将用户类型转化为管线内部五件事的调整：①访谈模块顺序 ②访谈语气锚点 ③种子推荐 ④ai_fill 预填范围 ⑤A2 联动意向（仅记录，A2 落地后生效）。**不是**新页面体系、新管线、新登录门槛。路由终点守住 D11/B6 红线：只有 `/a1`（A2 P0 后含 `/a2`）。

## 2. 用户动机分类学（8 冲动型 + 3 横向型）

（v0.1 内容不变，摘要保留）

**8 冲动型**（入口第一分流维度）：设定-重度 / 设定-轻度（v0.2 更名**角色驱动线**，见 §7）/ 剧情 / 哲理 / 探索（含规则机制）/ 爱情 / 怀旧续写 / 逃避疗愈。

学术背书（v0.1 §2.1 验证结论保留）：设定-重度≈GNS Simulationism + ACE² Creator；设定-轻度≈同人 fix-it 动机实证；剧情≈GNS Narrativism + Laws Storyteller；哲理≈Narrativism premise（道德问题）；探索≈Yee Mechanics 子成分；爱情≈C.AI Intimate Roleplay + PENS relatedness；怀旧≈同人动机文献（PSR 研究）+ Janitor AI 基本盘；疗愈≈Yee Immersion-escapism + C.AI "Restoration"。

各型兴奋点与流失风险详表见 v0.1（git 可溯）。关键两条：设定-重度最大流失风险 = **失去方向感**（WorldAnvil 官方：动机流失是世界观项目第一杀手）；疗愈型 = need-density 伦理敏感（SDT 需求密度假说）。

**3 横向型**（功能承接，不做入口分流）：社交炫耀（人格卡/分享——SCP 实证：为社区而写；星野"崽妈"生态）、收集成长（百科完成度/里程碑——Bartle Achiever 横切）、恶搞解构（沙盒模式——最活跃的边界测试者，不用审核驱逐）。

**方法论修正（Yee 成分模型）**：动机是成分非互斥类型——入口做**主冲动 1 + 次冲动 0-1** 多选，禁止单选贴标签。PENS：选项被强加直接破坏内在动机，问答措辞 = 自我描述而非被分类。

**与 D1 漏斗正交**：D1（玩家→GM→模组作者→小作坊）是身份维，本分类是冲动维，两维矩阵互不替代。

## 3. 入口交互设计：提问 → 推断 → 用户判定

### 3.1 核心交互：推断包（产品方设计意图的机制化）

产品方意图：聚焦用户最关心的问题 → AI 给出提问与关联内容的推断 → 用户自己判定对错。项目内已有完全同构的机制（访谈 fills → pending_proposals → `/chat/confirm`），入口直接复用：

```
Q1 冲动卡（主 + 次，8+1 张）
   ↓
Q2 动态追问 ×1-2（LLM 分支展开，带具体意象选项；命中上一答，不走清单）
   ↓
推断包生成（LLM 单次调用，同 interviewer 模式）
  输入 = 冲动类型 + Q2 追问答 + 种子/custom_idea 上下文
  输出 = 3-5 条关联推断（剧情党示例）：
    "我推断你世界的张力来自【人与人的博弈】"
    "我推断开场适合【一个必须立刻做的抉择】"
    "我推断你的主角【已经身处麻烦的中心】"
   ↓
用户逐条判定：对 / 不对 / 接近          ← 复用 pending_proposals + confirm 模式
   ↓
判定结果双写：
  ① creator_profile 置信修正（路由队列微调）
  ② "对/接近"的推断 → A1 answers 热启动锚点
     （走 fills 确认写入，J1 真值闸照常拦截占位）
   ↓
进入 A1 访谈，首问 = 类型队列最前模块第一问
```

**Q1 冲动卡**（8+1，场景意象文案、禁功能词——对齐 landing D5"共鸣原则"）与 **Q2 分支题库**（设定-重度→WorldAnvil 四动机 / 哲理→何为真实/善恶/自由/存在 / 爱情→题材+边界声明 / 探索→四方向 / 剧情→张力源四象 / 怀旧→来源四类触发上传 / 疗愈→此刻想要四选）沿用 v0.1 §3.1 设计。**Q3 投射题**（可跳过："哪个画面让你起鸡皮疙瘩？"→ 预填视觉设计.keywords；留一道抽象题提升"被读懂"感）。

### 3.2 前 5 分钟流程（v0.2：2:00/3:00 已改项目原生交互）

```
0:00  冲动卡 8+1（E0）
0:20  Q2 动态追问（E1，固定题集兜底）
0:50  Q3 投射题，可跳过（E1）
1:10  "正在为你酿造开场"——后端初始化类型队列 + 推断包（E1）
1:30  首个兑现物按型交付（分期见 §8 差距表）
2:00  推断包逐条判定：对/不对/接近（复用 proposal confirm——项目已验证交互）
3:00  进入 A1 访谈：首问即最关心模块（如剧情党直问 历史时间线.main_plot），
      右栏 StructuredFilePanel 实时 diff + 完成度（已有能力，零新增）
5:00  首模块完成可见庆祝 + 门禁进度 + "存下这个世界"（D8 先玩后注册）
```

创作人格卡（命名+视觉+一句话解读，可分享）= 社交炫耀型第一个承接点，E3 交付。

## 4. 设计铁律

1. **≤4 问，每问 2-4 秒可答**（3 步引导完成率 72%，7 步跌至 16%）
2. **结果立即兑现**——aha ≤90 秒；5 分钟未达 70% 流失；问卷结果不兑现 = 纯摩擦（Netflix 教训）
3. **问卷本身是奖励**——自我相关描述激活奖赏回路；"Collect effort after trust"
4. **先玩后注册**（D8 对齐）
5. **固定题集兜底 + LLM 自适应增强**——医疗 intake 实证：固定序优于随机、自适应整体最佳；**硬性轮次上限 2-4，LLM 不可用时回退固定题集**
6. **选项给具体意象，不给抽象类别词**（scaffolding 模式）
7. **三值信号优于量表**（喜欢/无感/不喜欢；choice-based 优于 rating-based）
8. **推断只提议，判定权在用户**（v0.2 新增，D2-③ 精神延伸：推断包、模块跳转提议、一切 AI 输出均走确认通道）

## 5. 路由架构（方案 C）与路由映射表

### 5.1 架构裁决：方案 C（确定性路由 + LLM 提议偏离 + 看门狗）

三候选裁决记录：

| | 方案 A：全拆模块 + LLM-MCP 编排 | 方案 B：LLM 整体重排模块顺序 | **方案 C（定案）**：确定性路由 + LLM 提议偏离 |
|---|---|---|---|
| 机制 | 每模块=工具，LLM 逐轮决定调用 | 入口 LLM 重排一次队列 | creator_profile → 代码生成类型队列；LLM 只能**提议**跳转（同 fills/proposal 模式），用户确认才生效 |
| 裁决理由 | **否决**：控制流进 LLM 手——模块漏访/门禁死锁需看门狗；1020 测试基线与契约测试全动；MCP 协议价值在外部客户端（后续开放生态包一层 server 即可，非内部架构需要） | **否决**：LLM 单点重排有漂移风险（parse_modules 同文档两次 35 vs 34 字段的教训就在眼前） | **定案**：代码路由可测试、J1-J4 纪律全保、三铁律不破；灵活性由"推断包 + 提议通道"补足 |

**模块拆分的正确位置（产品方愿景与 v0.5 现实的对接）**：产品方"每个模块对应图谱固定层级 + 全部放一个结构化文件"**就是 v0.5 现状**——背景树 L0约束→L1背景→L2模块→L3条目 是问卷的确定性投影（不经 LLM）；35 字段 answers 就在 A1 会话单一结构化文件；graphify 拿原文做图谱编译。方案 C 补的是**模块注册表形式化**（模块=自包含单元：问题集+字段 schema+tier 映射+完成谓词），拆的是驱动策略，不是数据形态。

**看门狗（防漏访兜底）**：每 N 轮门禁检查；类型队列中未访模块在访谈后半程由确定性引擎强制回归提示（"还差骰子设定没聊过，想让 AI 替你定还是聊聊？"）——保证 `is_finalizable` 可达。

## 6. field_sources：人工/AI 作答溯源

**产品方硬要求：门禁契约必须标记人工和 AI 作答的区别。（2026-09-18 已确认，含负面影响与缓解方案）**

### 6.1 设计

铁律"NL 永不携带机器格式"→ **不能**在答案值里塞标记。解法：**平行元数据，同键空间**：

```python
# A1 会话文件新增（answers 旁边，不改 answers 本身）
field_sources: {
  "历史时间线.main_plot": "human",         # 用户口述
  "力量体系.cost":         "llm_fill",      # 访谈 fills（已经用户 confirm）
  "骰子设定.probability":  "dice_rec",      # 骰子推荐按钮
  "世界本体.origin":       "upload_prefill" # 上传预填
}
```

- **都标、自动标**：每个有值字段自动带一个来源，无例外；四个写入出口各接线一处（直答 / `_apply_fills` / `parse_modules` / 骰子推荐），用户零操作
- **只看不判**：经 confirm 的 AI 答案照常计真值（confirm 流已保证用户背书），门禁判定零改变；`module_done_ratio` 分层**展示**"亲答 X% / AI 协助 Y%"（措辞中性，仅溯源面板/字段详情显示，不进主流程、不进门禁文案）
- 血缘先例：A2 `DiceTemplateSpec.signal_sources` 溯源——field_sources 是其在 A1 侧的上游对齐（A2 消费语义归 [[2026-09-18-A2边界评审占位文档]] 问题 6）

### 6.2 负面影响与缓解（已向产品方披露）

| 影响 | 缓解 |
|---|---|
| 展示心理："AI 代劳"字样伤作品归属感 | 仅溯源面板显示；中性措辞"AI 协助"；不进主流程 |
| answers 与 sources 漂移 | 契约测试：有值字段必有来源标记；键空间 ⊆ `all_subfield_keys()`（35 字段权威清单） |
| 存量会话无来源 | `unknown` 兜底，显示"早期会话" |
| 未来滥用风险 | "人工占比做门槛"若要做是新决策，默认不做（纯可观测层，同 J3 warning ledger 精神） |

一句话：**都标、自动标、只看不判**。

### 10.1 冲动坐标（impulse coords）——E2 观测 → E3 驱动（v1.2 新增，未决②机制层，D13）

**动机**：动机是成分非类型（Yee 成分模型，三成分相关 r≈0.1）——离散选卡是 1 bit 压缩；R5 固化风险的根治 = 类型估计随行为连续修正。外部实证：Spotify 消融实验（备忘 §7）——onboarding 显式信号冷启动贡献 nDCG@50 仅 13.8%，行为数据累积后须降权 → 选卡定初值、行为接管修正值。

**结构（三件套，存于 `creator_profile`）**：

| 组件 | 形态 | 作用 |
|---|---|---|
| 叙事-建构倾向轴 | 连续 [0,100]（100=纯叙事，0=纯建构）。锚点设计初值：设定-重度≈15 / 探索≈25 / 角色驱动≈35 / 哲理≈65 / 剧情≈70 / 怀旧≈75 / 爱情≈80 / 疗愈≈85；**「说不清」初值≈70**（人口先验：故事侧 64% vs 设定侧 14%，落故事侧但置信低） | 唯一路由杠杆：只调"未访模块顺序 / 语气锚点 / ai_fill 范围"三件事 |
| 置信度 | 连续 | 决定调整步长（低置信 → 大阻尼）。选卡 = 高置信起步；说不清 = 低置信起步 |
| 安全旗（疗愈/爱情） | 离散布尔 | 驱动 content_guard 护栏（时长提醒/危机识别/文案纪律）；**单向棘轮——检测到即升起，坐标漂移永不降旗** |

锚点数值 = v1.2 写定设计初值，E2 观测期校准（预注册纪律同 [[2026-09-20-动机占比预测基线]]：写定后不随数据回调，偏离 = 复核信号）。

**四护栏（缺一不可）**：

1. **确定性更新**：坐标只吃显式信号（推断包三值判定 / fills confirm-reject / 跳过 / 改写 / 首完成模块），更新函数 = 确定性代码 + 全留痕（warning ledger 同款精神）；LLM 只能**提议**坐标调整、用户确认才生效（D2-③ 同构——防方案 B 复辟，控制流不进 LLM 手）
2. **防振荡阻尼**：滞后区间 + 每会话调整上限 + 冷却轮数（每会话至多一次队列重排）+ **只重排未访模块**（已答内容永不动）——单次较真不翻转，方向性累计才移动
3. **可达性不变式**：动态重排保持 R6"只前移不跳过"——在 `sync_position` / gate-aware 同步机制上加约束，不重写；门禁数学可达性进契约测试
4. **安全旗棘轮**："**连续值调顺序，离散旗管安全**"——R4 need-density 护栏永不参与连续插值

**分期**：E2 = 坐标落库 + 看板"反推类型迁移曲线"（备忘 §5 预注册核心图表）——**只看不判**（field_sources 先例同款路径）；E3 = 驱动路由微调 + 入口单选 sunset（行为信号成熟后选卡权重递减）。

## 11. 工程接线与契约红线

### 11.1 接线清单

1. **插入点**：`session/start` 与首轮 chat 之间；`A1Session` 加 `creator_profile` 字段组（仿 `seed_*` 三字段模式）+ `character_sketch` 扩展槽；前端 `onboarding_quiz` 态插在 `seed_selector` 与 `guided_chat` 之间——入口三路（种子/上传/一句话）全部收敛于此

3. **枚举放消费侧**：分类枚举新建 `creator_profile.py`（仿 `derive_dice_recommendation` 惯例），不进 35 字段问卷树
4. **推断包**：新 LLM 单次调用端点（同 interview 模式）；**不直写 answers**——确认后才走 fills 通道写入（J1 真值闸兼容）
5. **field_sources**：四个写入出口各接线一处（直答 / `_apply_fills` / `parse_modules` / 骰子推荐）；契约测试扩展（键空间锁定）
6. **模块顺序**：`sync_position` 类型驱动目标队列（前移式），`MODULES` 列表与 `test_module_ids_match_spec` 零触碰
7. **看门狗**：访谈后半程未访模块强制回归提示（E2）
8. **开场叙事端点**：A1 域内新 LLM 生产方——**契约评审立项**（三铁律"单生产单消费"扩展评审：NL 叙事产物消费方是前端展示，不进图谱不进 SIR，风险可控但须立项留痕）

## 12. 风险与未决项

### 12.1 风险登记（v1.1 详释版）

#### 12.1.0 总览

| # | 风险 | 缓解 | 残余 |
|---|------|------|------|
| R1 | 问卷装饰化（分类后体验无变化，用户秒察觉） | E0 诚实文案 + E1 强制兑现三件套 | 中（E0-E1 空窗期） |
| R2 | GNS 失焦（一型一版 prompt 维护爆炸） | 语气锚点=模板变量；差异锁死在五件事内 | 低 |
| R3 | 爱情型合规漂移 | 三层前置（Q1 年龄门/文案框架/content_guard 三明治） | 中（生成侧渐进漂移） |
| R4 | 疗愈/爱情型伦理风险 | 护栏与 E1 同批 + E0 文案纪律 | 中（E0 窗口期） |
| R5 | 分类偏见固化 | 次冲动可选 + 人格卡重测 + 行为修正（E3） | 中低 |
| R6 | 类型队列偏科导致门禁不可达 | 双闸：E1 保守模式（只前移不跳过）+ E2 看门狗与 ai_fill 逃生口 | 低 |

#### 12.1.1 R1 问卷装饰化——最大失败模式

- **出事样子**：用户答完冲动卡进入访谈，发现问法、语气、内容与未答过一模一样——瞬间明白问卷是摆设
- **为什么危险**：比没有问卷更糟——先消耗 60-90 秒耐心，再给"个性化"期待又摔碎；用户对产品撒谎的敏感度远超对产品粗糙的敏感度（Netflix 教训：问卷不兑现=纯摩擦）
- **检测信号**：E0 埋点选卡 vs 未选卡对照组——卡片→首问完成率、各型 D1 回访；两组无差异或更差 = R1 发生
- **缓解机理**：E0 诚实文案（明示"帮我们了解你"）；E1 强制兑现三件套（推断包/语气锚点/首个兑现物至少一项真实可感）
- **残余风险**：**E0-E1 空窗期是命门**——E0 上线而 E1 不排期则 R1 必然发生。§10 将 E1 前置定为"E0 数据回收"而非"E0 上线 N 周"正为此

#### 12.1.2 R2 GNS 失焦——一型一版 prompt 爆炸

- **出事样子**：8 型各写一套访谈 prompt——改一条规则动 8 处，型间质量漂移，半年后无人敢动
- **为什么危险**：Edwards"同时服务三议程会失焦"的工程版；违背项目血泪纪律（J1-J4 全是收敛 LLM 行为，不是扩散）
- **检测信号**：设计评审数 prompt 变体数（应恒为 1 份+锚点变量）；访谈回归测试跨型对比告警
- **缓解机理**：语气锚点=模板变量（一份 prompt 注入锚点串）；管线差异锁死在五件事（顺序/语气/种子/ai_fill/A2 意向）——**差异是数据不是代码**
- **残余风险**：低。唯一漏洞是未来有人复制整套 prompt，代码评审把关

#### 12.1.3 R3 爱情型合规漂移

- **出事样子**：三条路径——①产品侧压力下逐步放宽措辞；②卡片/引导语暧昧擦边引流；③叙事端点 LLM 长对话渐进出界
- **为什么危险**：大陆无分级空间（暂行办法第 4 条硬红线）+ 拟人化新规；1301 实证供应链中间层随时拦截——上线后才发现被拦，损失整条爱情型通道
- **检测信号**：供应商拦截错误率（照 warning ledger 模式落库）、用户举报、E0 文案审查清单走查
- **缓解机理**：三层前置——Q1 年龄门+边界声明（入口即告知）；文案第一行起即"言情叙事"框架（不事后再改）；E2+ content_guard 输出过滤三明治（输入/生成/输出）
- **残余风险**：中。生成侧长对话渐进漂移是 LLM 固有（同 graphify 漂移课题）——content_guard 必要非充分，E2+ 实测调优

#### 12.1.4 R4 疗愈/爱情伦理——need-density 人群

- **出事样子**：现实受挫用户把产品当唯一出口，连续长时间沉浸；情绪危机时产品回应不当——爆发形态是**舆情/监管事件**，不是技术故障
- **为什么危险**：SDT 需求密度假说——现实满足越差虚拟依赖越深，最不该深绑定的人群产生最深绑定；伦理+法规双杀（拟人化办法：禁止诱导情感依赖/强制危机识别/2 小时提醒）
- **检测信号**：会话时长分布（盯 P95 连续时长）、危机词命中频率、用户年龄结构
- **缓解机理**：护栏与 E1 同批（纪律：不做先上功能后补护栏）；时长提醒+危机识别对接+极端情绪升级路径（共情安抚→现实拉回→自残自杀打破人设强干预）
- **残余风险**：中。**E0 窗口期疗愈型已在引流而护栏在 E1**——E0 疗愈卡文案即刻执行纪律：**禁止诱导性承诺**（"这里永远有人陪你"类措辞不许出现）

#### 12.1.5 R5 分类偏见固化

- **出事样子**：用户随手选"剧情"卡但实为设定党——错误分类贯穿全会话甚至跨会话复利
- **为什么危险**：Yee 实证动机是成分非类型，单次选择错误率必然存在；固化让错误复利
- **检测信号**：人格卡重测率、型切换频次、次冲动留空率
- **缓解机理**：三层松绑——次冲动可选（承认动机混合）；人格卡可重测（28-37% 用户天然爱重测，重测入口是功能不是补丁）；类型随行为修正（E3 埋点反哺）。**诚实声明：行为反推 E1-E2 期间不生效，实际只有手动重测**
- **残余风险**：中低。固化窗口≈首次会话；推断包判定（对/不对/接近）本身在给用户纠偏机会

#### 12.1.6 R6 队列偏科→门禁不可达

- **出事样子**：剧情党队列前移模块聊得尽兴，40 分钟后退出——骰子设定/玩法 DNA 从未被碰，10 模块门禁永远差两块，定稿按钮永不点亮
- **为什么危险**：六风险中唯一"确定性撞确定性"——路由是确定性代码，偏科也是确定性的（剧情党 **100%** 偏科，非概率事件）；防不住即系统性卡死一类用户
- **检测信号**：各型定稿率、missing_sections 按型分桶统计（哪型总缺哪块一眼可辨）
- **缓解机理**：双闸——E1 保守模式（**只前移不跳过**：前移模块问完 sync_position 回问卷原序遍历，偏科=顺序靠后但数学上必达）；E2 看门狗（后半程强制回归提示 + ai_fill 逃生口："还差骰子设定没聊过，想让 AI 替你定还是聊聊？"）
- **残余风险**：低。门禁契约不动，E1 保守模式保证可达；看门狗把"可达"变"不难受"

#### 12.1.7 优先级分层与立即行动

| 时窗 | 风险 | 性质 |
|------|------|------|
| **马上盯**（E0 窗口） | R1 空窗期、R4 E0 文案纪律 | 工程排期 + 文案纪律 |
| 中期工程纪律（E1-E2） | R6 可达性、R3 三层前置 | 确定性可防 |
| 长期腐化（持续） | R2 prompt 爆炸、R5 固化 | 结构已锁，评审把关 |

**两条立即行动**（不排期也必须做，随 E0 执行）：
1. E0 疗愈卡/爱情卡文案落笔即执行 R4 禁令（无诱导性承诺）+ R3 框架（言情叙事措辞）——文案审查清单随 E0 交付
2. E0 埋点设计预置 R1 检测指标（选卡 vs 未选卡对照组），不等到 E1 补埋

### 12.2 未决项（v1.0 冻结后残留，均不阻塞 E0/E1）

1. **ai_fill 粒度**：模块级已入表；字段级细化与例外清单（如爱情型 `faction_type` 留给用户）待 E2 设计评审
2. **"说不清"通用线走向** → **v1.2 已锚定（D13）**：默认队列 = 故事侧（§5.2 通用线行）；机制 = 冲动坐标（§10.1：E2 只看不判 / E3 驱动路由 + 四护栏）。预注册假设"通用线行为反推分布 = 故事倾向"已入 [[2026-09-20-动机规模调研备忘]] §5 钩子表，E1 数据检验
3. **创作人格卡命名体系**（是否沿用 ECHO·回声工坊 48h 候选名规则同款治理——与台账未决"产品总名终裁"联动）
