## 1. 产品骨架重述：从三阶段流水线到模块池 + 冲动配方

### 1.1 旧骨架为何退役

v5 时代的产品叙事是 A1（世界观工坊）→ A2（产出）→ A3 的固定阶段流水线：用户先走完 10 个世界建构模块的访谈，定稿编译图谱，再进入 A2 产出。这套骨架在真实故事型用户面前崩塌——只想写剧情的用户被迫回答"势力类型"。E1-Lite 已经证明：类型驱动的模块前移（置换）只能缓解、不能根治，因为**全集始终在那里**，门禁在查、prompt 在列、图谱在校验。模块级路由的天花板被翻车记录实证：偏转被无视重问、剧情细节被误判为主剧情修改提案、降级建议聋。

### 1.2 新骨架一段话

v6 的新骨架：**所有模块进一个池子（模块池），用户入场时按冲动类型领一张配方（有序模块子集），访谈引擎沿配方线性游走，产出模块按需触发**。世界建构模块（原 10 个问卷模块）、故事模块（剧情主线/角色速写/情感线）、产出模块（主模组文字版/骰子投影/角色投影）同池不同族（worldbuilding / story / output 三家族）。默认配方 = 原 10 模块全集，设定型用户体验逐字节不变。路由差异全部下沉为**数据**（配方表），代码里只有一份 prompt 骨架、一个游标、一套门禁——这是"差异是数据不是代码"（R2）在架构层的兑现。

### 1.3 详细设计引用（单一真相源）

**架构权威**：五层架构图、运行时调用时序、单文件数据流，见详细设计 [2026-09-22-jia-modular-architecture-design.md](plans/2026-09-22-jia-modular-architecture-design.md)：

- **§1 架构模块图**（五层：入口/路由/执行/管线/基础）——关键决策：路由层 `module_registry` 是唯一新增的真相源；执行层访谈侧复用现有引擎（参数化），产出侧平移 A2 资产；管线与基础层零架构变化。
- **§2 模块调用方案**——访谈模块走同步问答环（游标模型不变）；产出模块用户显式触发，永不自动触发；一切调用经 `get_recipe()` 查表。
- **§3 冲动类型 × 模块配方矩阵**——10 条配方（9 冲动型 + default），详见本文 §2.2。
- **§4 单文件落盘结构**——store v2 schema，详见本文 §2.6。
- **§5 图谱化防乱**——五道防线，详见本文 §2.7。

本文以下各节只注册**规范级契约**（什么必须成立、什么禁止发生），实现细节以详细设计为准。

## 2. 模块化核心契约（v6 新增规范正文）

### 2.1 路由真相源唯一：module_registry

`backend/app/domains/creation/shared/module_registry.py` 是模块遍历/门禁/校验/预填/展板的**唯一入口**。任何消费方禁止直接遍历 `MODULES` 或 `MODULE_POOL` 全集，必须 `get_recipe(session)` 后按 `recipe["module_ids"]` 遍历。`get_recipe` 对未知冲动类型回落 default，永不抛异常。

**六处全集引用改造清单**（甲计划 M1，Momus 复核定稿）：

| # | 位置 | 改造 |
|---|------|------|
| 1 | finalize 门禁（a1_routes.py:1137） | 全集遍历 → 配方集遍历 |
| 2 | graphify 锚点校验（graphify.py:239/:474） | 合法键全集 → 配方并集（调用链签名随参数传入） |
| 3 | `first_module()` 默认（guide_engine.py:101-102） | 全集首模块 → 配方首模块 |
| 4 | `_build_sections`（a1_routes.py:958） | 配方感知 |
| 5 | ip_poster.py:8/:39-40（展板 panels 全集遍历） | 配方感知（故事会话展板含故事模块 panels） |
| 6 | worldview_upload.py:24-29/:193-200（上传 prompt schema 全集渲染） | default 配方渲染不变；故事型 × 上传链语义归 DN6 |

E1-Lite 三数据字典（TYPE_MODULE_PRIORITY / TYPE_ENTRY_SUBFIELD / ANCHOR_BY_TYPE）数据迁入 Recipe，原位置留 re-export 兼容 import（或一次性改全部消费点，M1 内定夺）。

**调用规则**（规范级禁令）：

- 任何消费方（guide_engine / finalize 门禁 / graphify 校验 / 上传预填 / 展板）**禁止直接遍历 MODULES 或 MODULE_POOL 全集**——必须 `get_recipe(session)` 后按 `recipe["module_ids"]` 遍历；
- `get_recipe` 对未知 impulse_type 回落 DEFAULT_RECIPE，**永不抛异常**（路由层不产生新错误面）；
- 问卷树门面函数（module_ids / get_module / all_subfield_keys / is_finalizable / next_subfield / next_module）加配方参数（`recipe: Sequence[str] | None = None`），默认 default = 全集——**MODULES 数据零改动**；
- interviewer 的 `_progress_summary` / `_field_catalog` 按配方渲染——禁止向 LLM 泄露配方外字段目录（G5 泄露修复，规范化为禁令）；
- 六处改造清单中的每一处，其"改造后行为"均须有对应契约测试锚点（§4.2）。

### 2.2 配方 schema 与 8+2+default 配方体系

`Recipe` 的字段权威定义 = 详细设计 §2.1（`impulse_type` / `module_ids` 有序子集 / `entry_subfield` / `anchor` / `ai_fill_policy` / `deliverables` / `guard_flags`）。规范级约束：

- `module_ids` 内的每个 id 必须存在于 `MODULE_POOL`（池封闭，无幻影模块）；
- `entry_subfield` 必须指向配方内模块的子字段（首问可达）；
- `anchor` 为语气锚点文本（E1-Lite ANCHOR_BY_TYPE 迁入），只影响 interviewer 语气，不影响路由；
- `guard_flags` 是配方级合规开关（如 romance 的 content_guard），封闭枚举，消费方白名单化。

**9 条配方 + 2 条通道**（产品方 2026-09-22 重锚定，撤销"探索/规则"冲动行）：default + 8 类冲动配方（plot / romance / character_driven / philosophy / setting_heavy / unsure / nostalgia / healing）+ 2 条**通道**（探索态着陆=B 类合规演示；玩法设计链=设定-重度变体+目的地 flag 下游产线——非冲动分类）。故事模块 = M11 角色 + M12 剧情（情感线并入 M12 场景化 + M10 爱情 preset）。各配方的模块子集、首问、锚点要点、预填范围、兑现物清单，权威版本 = 详细设计 §3.1，此处不复制表格，只记三条优先级语义：

1. **序即优先**：module_ids 列表序 = 访谈遍历序 = 兑现物装配信号读取序，一个序贯穿全链，无第二套优先级。
2. **子集即边界**：不在列表内的模块对该会话不存在（门禁不查、prompt 不列、图谱不校验）。
3. **动态可调三杠杆**（E2 坐标层预留，M4a 只观测）：未访模块顺序 / 锚点 / ai_fill 范围；已访内容与配方边界永不动。

**配方落定时机**：`POST /session/start` 按 creator_primary（+secondary）一次性落定 `recipe_id` 与 `recipe_modules`，会话生命周期内**配方边界不可变**——三杠杆的动态调整只在配方边界内发生（四护栏之②的规范化表述）。

**guard_flags 语义**：配方级合规开关随配方生效（如 romance 配方携带 `content_guard`，情感线模块的边界声明字段为该 guard 的内容侧承接）。guard 的具体过滤逻辑属于内容合规层，不属于路由层——配方只负责"声明"，不负责"执行"。

配方矩阵中的世界建构子集裁剪与序为 **DN6 初稿**，待产品终审（§5）。

### 2.3 默认配方 = 原 10 模块全集（存量兼容铁律）

无 creator_primary / 未知冲动值 / 存量会话 → default 配方（原 10 模块、原顺序）。这是甲计划的**回归铁律**，规范化为以下断言：

- 设定型用户体验**逐字节不变**。比较面 = 确定性输出面（Momus F5 修订）：门禁计算结果 / 模块遍历序 / 上传 schema 文本 / `_build_sections` 结构 / graphify 输入 prompt——**排除** LLM 生成体与时间戳（非确定性面不比较）；
- default 配方下 `_type_ordered_modules` 的置换语义保持（head + rest 保全集），`first_module()` 返回与 v5 逐字节一致；
- 回归用例（default 配方全链路 vs v2-modular 基线快照）每 Wave 必跑，见 §4.3；
- 无 profile 会话 / nostalgia / healing 等上传预填为主的型别，行为按各自配方定义，但不触碰 default 路径。

### 2.4 产出模块依赖契约

产出模块（主模组文字版 / 骰子投影 / 角色投影）入池（family=output）后遵守四条：

1. **signal_requirements 声明输入依赖**：每个产出模块声明所需信号键及等级（required / optional / hard）。required 缺 → 409 `upstream_missing`（错误体含缺哪些键）；hard 依赖产物缺 → 409 `missing_dice_template`（A2 错误契约族照搬，如 character_projector 硬依赖骰子产物）；optional 缺 → 保守缺省 + warning_ledger 披露（R2 风险缓解同款纪律）。
2. **409 族语义不变**：与 v5 §3 T9 门禁 409 同族，错误体结构照搬，前端按既有 409 处理路径消费，无需新增错误范式。
3. **stale 永不阻断**：上游图谱 stale 只标记、留 `used_stale` 痕迹、不拒绝调用。用户拿到的产物须披露"基于过期图谱"（ledger 透传，前端徽章）。
4. **上游只读**：产出模块经 upstream_loader 拉已定稿 W 图谱与 answers，文件永不回写图谱（交接铁律）。产出模块自身产物写独立图谱（M/TD/TC），不入 W 图命名空间（§2.7 防线三）。

触发方式：仅用户显式动作（finalize / POST dice-template / POST character-template），永不自动触发——LLM 与装配成本可控，用户心智清晰。

### 2.5 LLM 生产方封闭清单

全系统 LLM 生产方封闭为四点（D-A2-4 普适化）：

| 生产方 | 归属 | 产出 | 立项状态 |
|---|---|---|---|
| interviewer | 访谈引擎（现有） | 回复 / fills 提案 / 建议 | ✅ 存量（v5.1 §5 契约） |
| inference_pack | M4b 推断包 | 3-5 条推断 | **待 DN5 立项** |
| module_compile | M3 主模组增强线 | 编成文案 | **待 DN5**（免费线零 LLM 先行） |
| opening_narrative | M2 plot 兑现物 | 200 字开场 | **待 DN5** |

清单外任何模块不得新增 LLM 调用；全部遵守"LLM 只产内容与建议，永不产结构/数值/路由"（三铁律之 LLM 不进控制流）。配套纪律：

- 新生产方逐一走三铁律"单生产单消费"契约评审立项留痕（DN5），**先立项后写码**；
- 推断包复用 pending_proposals + confirm 交互，**不直写 answers**（J1 真值闸统一拦截占位）；
- module_compile 免费线（零 LLM 确定性装配）先行，增强线待 DN5——LLM 失败时降级为骨架 + ledger 披露，绝不阻塞主流程；
- 每个 LLM 生产方的输出面（内容/建议）与结构面（结构/数值/路由）的边界，须在其契约测试中显式断言。

### 2.6 单文件持久化 schema v2

`data/a1_store.json` v2 为 **additive 扩展**，完整 schema 权威版本 = 详细设计 §4.1。规范级要点：

- **sessions 侧新增**：`recipe_id`（""=default，存量零迁移）/ `character_sketch`（M0 素材槽）/ `field_sources`（M4a，与 answers 同键空间的平行元数据）/ `coordinates`（冲动坐标三件套，只看不判）；
- **files 侧新增**：`recipe_id` / `upstream`（graph_code + used_stale）/ `artifacts` 产物槽（一产出模块一槽：dice_template / character_template / module_doc，各嵌自身 graph_code）/ `open_questions`（M0 的 session 暂存迁此统一挂 file）/ `warnings`（ledger 透传，现有）；
- **答案键空间不变**：`module.subfield` 中文 id 全局唯一（问卷树权威），故事/世界建构/产出信号同住 answers 一层，天然无命名冲突；
- **产物槽规则**：每产出模块恰一槽；重复 finalize = 同槽版本递进，不开新 file（DN4d 已裁决 D15：α0.1 初稿 → α0.11/0.12 草稿期迭代 → 定稿 = 0.1 系列关闭转 β → 定稿后再改 β0.21/0.22… → 彻底稳定升 1.0；module_doc/dice_template/character_template/scenes/W 图谱全产物统一）；StageCode 码嵌在产物内，registry 是血缘唯一源；
- **写路径单点**：store.save 原子写（.tmp→rename）+ 三级 bak 轮转机制原样复用——一个文件 = 一份自洽快照，无跨文件一致性问题。

### 2.7 图谱防乱五防线

故事答案 + 世界建构答案 + 产出图谱混住单文件，防乱靠五道防线（机制详表 = 详细设计 §5.1，此处只记防线名与乱源）。五防线的共同哲学：**乱的根源是"本不该相遇的数据相遇了"，防线就是让它们在键空间、层带、命名空间、装配路径、比较口径五个维度上系统性不相遇**：

1. **锚点校验 = 配方并集**——graphify 合法键从全集改为配方并集（graphify.py:239/:474 改造，M1），故事会话不产生幻影世界建构节点；图谱只含配方内模块。
2. **家族-tier 固定映射**——每模块固定 tier（世界建构 0-6 现状；故事模块 DN2 初稿：M12 剧情→历史线层/M11 角色→文明层），层带按家族聚合不交错，双树带状布局不因混型错层。
3. **产物图谱独立命名空间**——W/M/TD/TC 各自独立发号、独立图谱，经 `parent_graph_code` 血缘相连，绝不分层混入同一张 KG；产物结构永不污染世界图谱（三铁律"单生产单消费"的图版）。
4. **确定性装配不变式**——同配方 + 同 answers → 逐字节同图谱（确定性代码装配，LLM 只在 graphify 单点产 SIR）；图谱可复现 = 可回归 = 不漂移。
5. **跨配方不比较**——不同配方 = 不同图谱（键空间不同）；血缘链记录"哪份配方产的图"，比对只在同配方内做——"剧情图谱 vs 设定图谱字段谁对"是伪问题。

**建议新契约**（测试化落点，详细设计 §5.3）：

- **C8 图谱确定性快照**（建议）：固定 answers fixture × 10 配方 → 图谱 JSON 快照比对（回归铁律的图谱版）。任何触及装配链的改动，快照 diff 必须可解释。
- **C9 产物隔离断言**（建议）：M/TD/TC 图谱节点永不出现于 W 图谱（命名空间互斥）。防线三的测试化表述。

### 2.8 图谱全景（谁产图、谁消费）

一句话版（详表 = 详细设计 §5.2）：**W 图**由 graphify + 确定性编译产出（消费方：图谱页/展板/上游模块）；**M/TD/TC 图**分别由 module_finalizer / dice_projector / character_projector 产出（消费方：文字版导出/角色卡/展示）。血缘单向：M/TD/TC → W；W 变更只做 stale 标记，永不删除、永不静默重算。零 LLM 的骰子/角色投影须保持"同输入同输出"确定性断言（免费线可离线跑通）。

### 2.9 访谈环与 finalize 门禁语义

- **游标模型不变**：`session.current_module / current_subfield` 单游标，`sync_position` 在配方序上线性推进——配方即该会话的全集，"只前移不跳过"（R6）自动成立；
- **finalize 门禁（DN1 默认案）**：`is_finalizable = ∀ m ∈ recipe.module_ids: is_module_over_half(m)`——配方外模块**不适用**，不进 missing_sections；门禁计数沿用真值闸语义（占位答案不计入）；
- **偏转与素材槽（M0 已落，v6 追认）**：deflect → 占位推进指针（J1 保门禁不被占位污染）；story_material → character_sketch 素材槽，**不进 answers / 门禁 / graphify**——素材是叙事原料，不是结构化答案；
- **graphify 触发时机**：finalize 时以配方并集校验锚点（§2.7 防线一），配方外字段若出现在 answers 中属数据异常，须报错而非静默编译。

## 4. 迁移与兼容

### 4.1 store v1 → v2：默认值零迁移

v6 沿用 store 兼容先例（creator_*/prefill_fields/answer_clips）：全部新增字段带默认值（`recipe_id=""` → default 配方、`character_sketch=""`、`field_sources={}`、`artifacts={}`），v1 文件 `model_validate` 直读，零迁移脚本。存量会话首访即得 default 配方，行为与 v5 逐字节一致。

版本号处置：v2 为 additive 扩展，即使不 bump 版本号也兼容；bump 留作显式标记（详细设计 §4.1 注）。读路径对 `"version": 1` 与 `"version": 2` 均接受，写路径新落盘统一写 2。

扩容边界：单用户本地场景单文件足够（当前量级 <1MB）；未来多用户/大体量 → version 3 分片（sessions 独立 + files 按用户分目录），**设计预留，本期不做**（YAGNI）。

### 4.2 API 与前端兼容

- **API 面无版本扩张**（甲计划红线沿用 v5 纪律）：新增可选字段（如 M0 的 `{"deflect": true}` 访谈 JSON 契约新增可选键，向前兼容豁免入 D14 附录），不修改/删除既有字段；
- 产出模块端点为**新增**（文档导出资源名已裁决 = `doc`、界面显示「文档输出」〔D15〕；完整路径域 `/api/a1/...` vs `/api/modules/...` 于 M3 施工前与实施稿统一），既有端点契约不变；
- 前端配方感知为增量：seeds/进度条/模块维度消费配方元数据，impulse 确认后可显示配方预览（可选、轻量）；设定型路径前端零变化；
- 错误处理复用既有 409 族（§2.4），前端无需新增错误范式。
