# 草稿：约束应用逻辑树

## 用户提出的核心问题

### 问题链条

1. **语义→标签→字段 映射不清晰**
   - 设计师说："这个世界是飘浮在虚空中的浮岛群"
   - 系统编译为：`Constraint(LAW): world_structure=FLOATING_ISLANDS`
   - 但 `world_structure` 这个标签怎么来的？`FLOATING_ISLANDS` 这个值怎么确定的？
   - **需要一个"语义解析器"把自然语言映射到结构化标签和枚举值**

2. **同一约束维度在不同生成层调用不同字段**
   - 比如 LAW 约束在 WORLD 层可能调用 `physics.gravity` 字段
   - 同一个 LAW 约束在 NPC 层可能调用 `skill_check.method` 字段
   - **需要一个"约束应用逻辑树"定义：什么层 → 什么约束 → 调用什么字段 → 生成什么**

3. **生成过程中的完整链条**
   - 语义描述 → LLM推理分析 → 种子选择 → IP问卷填写
   - 填写过程中异步发给LLM → 生成约束
   - 约束 + 权重矩阵 → 约束应用逻辑树 → 查找调用字段
   - 字段 + 拓扑边/节点 → 生成Prompt → 生成结构化新节点

### 用户想象的流程

```
设计师输入语义
  ↓
机器人引导（选用种子，细化世界观，填入IP问卷）
  ↓
异步LLM推理 → 生成约束（结构化标签=值）
  ↓
不只是权重——还需要逻辑树
  ↓
逻辑树说明：约束和生成之间的关系，谁重要，谁先定义
  ↓
同维度约束在不同层调用不同字段
  ↓
每个字段在拓扑关系上调用不同的约束节点、边
  ↓
生成提示词 → 生成结构化新节点
```
