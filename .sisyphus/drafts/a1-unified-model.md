# A1 知识图谱统一概念模型 —— 无矛盾重梳理

> **定位**：本文取代此前所有文档中的冲突表述，是唯一权威概念模型。架构文档（`a1-knowledge-graph-architecture.md`）与考古文档（`a1-contradiction-analysis.md`）与本文冲突处，**以本文为准**。
> **方法**：病根是"一词三义、一数两用、契约散落"（考古 M1-M8）。解药是三条正交分离轴 + 概念词典退役制 + 契约注册表。

## 0. 一张图看懂统一模型

```
┌─────────────────────────────────────────────────────────────────┐
│  ① 访谈（输入侧）                                               │
│  用户自由说话 → 访谈器LLM理解 → answers（自然语言答案集）         │
│                    【形态NL：module.subfield → 纯文本】          │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓ 定稿触发（唯一入口）
┌─────────────────────────────────────────────────────────────────┐
│  ② graphify（结构化+关系化，一次LLM调用）                        │
│  输入: answers + 边词表 + 不可动清单 + tier映射表                 │
│  输出: graphify结果（结构化中间表示，JSON）                       │
│        【形态SIR：五字段契约，见§2】                              │
│  职责: 模块总结 + 条目提取 + 关系建立 + 约束归类                  │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│  ③ 组装（确定性代码，零LLM）                                     │
│  概念树投影 + 深度树挂载 + 语义边合并 + tier标注 + 序号编排       │
│  输出: graph_json（图数据）                                      │
│        【形态KG：节点(双树)+边(三类)+属性(tier)】                 │
└──────────────────────────┬──────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────────┐
│  ④ 图谱页（呈现侧）                                             │
│  行政树视图（概念树+深度树层级带状）                              │
│  概念网视图（语义边织网+tier分组着色+审核台）                     │
└─────────────────────────────────────────────────────────────────┘
```

**铁律：每种形态只有一个生产方、一个消费方、一份契约。**

## 1. 轴一：数据形态分离（终结"结构化"三义之争）

"结构化文件"一词**退役**。系统只有三种数据形态，各有专名：

| 形态 | 专名 | 内容 | 生产方 | 消费方 | 存在时机 |
|------|------|------|--------|--------|---------|
| **NL** 自然语言 | `answers` | `module.subfield → 纯文本` | 访谈器 | graphify LLM（唯一） | 访谈全程，持续增长 |
| **SIR** 结构化中间表示 | `graphify结果` | 五字段 JSON（§2） | graphify LLM（唯一） | 组装器（唯一） | 定稿时刻，每次全量重建 |
| **KG** 图数据 | `graph_json` | 节点+边+属性 | 组装器（唯一） | 前端图谱页、下游A2+ | 定稿后持久化 |

考古对齐：08-21 时代 answers 曾同时承担 NL 和 SIR 两职（tag=value 片段），08-24 范式重构把 SIR 职责砍掉只剩 NL——这就是断链本质。新模型把 SIR 独立为 graphify 结果，**NL 永远不再被要求携带机器格式**（访谈器规则2不变），**SIR 永远由定稿时的 LLM 调用生成**（不再依赖访谈时刻）。

## 2. SIR 契约：graphify 结果五字段（第0号开放问题的答案）

```json
{
  "module_summaries": { "<module_id>": "一句话归纳" },
  "entries": [
    { "anchor": "<module.subfield>",
      "items": [ { "title": "…", "content": "…", "children": [...] } ] }
  ],
  "edges": [
    { "from": "<节点引用>", "to": "<节点引用>",
      "relation": "<词表内关系名>", "rationale": "…", "confidence": "semantic|rule|structure" }
  ],
  "constraint_fields": { "<DIM>.<tag>": "<枚举值或短文本>" },
  "open_questions": [ "世界观语言问句" ]
}
```

| 字段 | 承载的能力（用户原话） | 去向 |
|------|----------------------|------|
| module_summaries | 总结 | 概念树 L2 节点 description |
| entries | 节点提取（同级=items并列，下级=children嵌套） | 深度树节点 |
| edges | 提炼（词表内关系） | 语义边（confirmed=false 待审核） |
| constraint_fields | （考古修复：08-24 斩断的生产方在此重建） | apply_constraints → cst_* 节点 + CROSS 边 |
| open_questions | 提炼（词表外关系→问用户） | file 记录 → 回访谈页闭环 |

**节点引用规则**（edges 的 from/to）：概念树节点用原 id（`module_id` / `module_id.subfield_id`）；深度树节点用 `d_{anchor}_{k}`（组装器按 items 顺序编发，规则预先告知 LLM）；cst 节点用 `cst_{DIM}_{tag}`。

## 3. 轴二：图结构分离（双树 + 三类边）

图里只有**两种树结构 + 一类横穿边**，序号体系天然区分：

| 结构 | 性质 | 节点 id | 序号 | 边 |
|------|------|---------|------|-----|
| **概念树** | 问卷骨架投影（确定性） | `bg_*` / `{module_id}` / `{module.subfield}` | `0` / `N` / `N-M` | TREE（"包含"/"条目"） |
| **深度树** | 内容条目生长（生成性） | `d_{anchor}_{k}` | `D{锚点}-{k}` | TREE（"分条目"） |
| **语义边** | 横穿织网（待确认） | — | — | CROSS 系（SEMANTIC/RULE/STRUCTURE，confirmed=false） |

约束节点 `cst_*` 不属于树，是独立第0层标注节点（沿用现有机制，由 constraint_fields 复活）。

## 4. 轴三：层级编号分离（终结"L{n}"两用之争）

**规则：图深度用 `level`（结构维度），世界观语义层用 `tier`（语义维度）。v0.4 的 L0-L6 只存在于治理文档，代码里一律称 tier 0-6。**

| 维度 | 字段 | 附加于 | 取值 | 决定者 |
|------|------|--------|------|--------|
| 图深度 | `level`（现有） | 一切节点 | 0=约束 / 1=背景 / 2=模块 / 3=条目 / 4=分条目 | 组装器（确定性） |
| 语义层 | `tier`（模块节点新增属性） | 仅模块节点 | 0-6（下表） | 静态映射表（写死，v0.4 编译） |

**tier 静态映射表**（10模块全覆盖，v0.4 §1 直接编译）：

| tier | 层名 | 模块 |
|------|------|------|
| 0 | 存在基座 | 世界本体 |
| 1 | 动力学 | 力量体系 |
| 2 | 显现 | 地理空间、文明与社会 |
| 3 | 时间 | 历史时间线 |
| 4 | 表达 | 视觉设计、玩法设计DNA、骰子设定 |
| 5 | 命题 | IP定位 |
| 6 | 治理 | 设定边界 |

**tier 的呈现方式（决策6的落地方案）**：
1. 概念网视图按 tier 分组布局/着色——七层的方向性（滋养/投影/治理）肉眼可见
2. 层间派生关系 = v0.4 派生边总表编译进边词表 → 由 graphify 的 edges 提取（如 `世界本体.origin ─力量源自→ 力量体系.source` 就是 tier0→tier1 的派生边）
3. **不加深概念树**（与决策4"问卷序扁平"不冲突）、**不占 level 编号**（与决策3"L4=深度树"不冲突）

> 这同时是决策6的和解方案：A方案（层节点入图）会与决策4矛盾，C方案（不落地）辜负理论；tier 属性+语义边承载 = 唯一无矛盾解。

## 5. 概念词典（一词一义，歧义词退役）

| 退役词（曾致歧义） | 今后说 |

## 6. 契约注册表（每对生产-消费必有 schema + 集成测试）

| # | 契约 | 生产方 | 消费方 | 集成测试（CI强制） |
|---|------|--------|--------|------------------|
| C1 | answers 格式（NL） | 访谈器 | graphify prompt 构造 | 真实访谈产出样本 → graphify prompt 可消费（冒烟） |
| C2 | graphify 五字段 schema | graphify LLM | 组装器 | schema 校验 + anchor 合法性 + 节点引用合法性 + 降级路径 |
| C3 | graph_json 双树结构 | 组装器 | 前端 + 下游A2 | 双树不变量（TREE边数=模块+条目+分条目；序号格式断言） |
| C4 | 语义边词表（封闭） | 治理文档（v0.4编译） | graphify prompt | 词表封闭性 + 表外关系必进 open_questions |
| C5 | tier 映射表 | 治理文档（静态） | 组装器 + 概念网布局 | 10模块全覆盖断言 |

**流程铁律**（考古教训沉淀）：凡新增生产-消费对，先登记本表并写集成测试，否则不许合入。

## 7. 用户原话 → 模型落点（最终对齐表）

| 用户原话 | 统一模型落点 |
|---------|-------------|
| 种子/自定义 | 流程①前置（不变） |
| 访谈扩充/修改 | 流程①（不变，写入守卫保护） |
| 我给你就是纯自然语言 | answers 永为 NL（轴一），访谈器无格式义务 |
| 你自己做结构化 | graphify（流程②），SIR 独立生成 |
| 关系化 | graphify.edges + 边词表（C4） |
| 总结（已知拓扑） | module_summaries + 概念树投影（tier 让已知分层可见） |
| 提炼（新拓扑） | edges（词表内）+ open_questions（词表外→问用户→下次转正） |
| 节点提取（同级+下级） | entries.items（同级并列）+ entries.children（下级嵌套） |
| 条目就是分模块的标题 | items.title 即深度树节点标题，D 序号编排 |
| 有了标题才能嵌套往下生成 | children 递归挂载（Phase2 开放深度，Phase1 先验证一层） |
| 嵌套进拓扑结构形成一个系统 | 组装器（流程③）：双树+语义边+tier 的完整 graph_json |
| 概念树和深度树用不同序号 | 0/N/N-M vs D{锚点}-{k}（轴二） |
| 理论七层 vs 代码四层 | tier vs level 分离（轴三），七层以 tier+派生边落地 |
