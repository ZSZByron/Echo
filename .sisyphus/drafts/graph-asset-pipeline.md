# Draft: 图谱驱动的资产生成系统

## 核心概念
资产是知识图谱的节点，生成顺序由图的拓扑结构决定，prompt 必须融合：
- 节点自身描述
- 边关系描述（用户手写）
- 关联节点的描述

## Requirements (confirmed)

### 知识图谱构建方式
- **LLM 提取骨架 + 人工细化**：LLM 从场景整体描述提取节点和粗略关系，用户在图谱界面手动补充/编辑，**每条边必须手写「相对关系描述」**
- 系统检测到新边就要求用户填写关系描述

### 层级定义 = 互动深度
- **0级** = 背景视角（玩家进入就看到的画面）
- **1级** = 一次互动即可发现的资产
- **2级** = 在1级上再互动一次才能发现
- **N级** = N次嵌套互动

### 序号编码 = 层级路径（树形）
- `1` = 第一个1级资产
- `2` = 第二个1级资产
- `1-1` = 第一个1级资产的第一个子资产
- `1-1-1` = 更深层
- `2-1` = 第二个1级资产的第一个子资产
- **排序规则**：位数越多越下级，同位数按初始描述顺序排

### 生成顺序算法
- **1对1（单边）**：序号小的先生成，大的参考小的
- **1对多（星型）**：叶子节点先生成，核心节点等所有叶子完成后参考它们生成
- **逐级向上**：自底向上，先度数最低（最外围），逐步向中心收敛
- **度数优先 + 序号次优先**：同度数按序号排

### 边的方向性
- **玩家发现顺序定义上下级**：一次互动=1级，两次=2级
- 边方向 = 依赖方向：下级→上级（下级是上级的前置条件，上级参考下级生成）

### 背景定位
- 背景是**0级场景**：故事中某个地点的某个区域空间的一个视角场景
- 完整体系应有：剧情编号 + 地点编号 + 视角编号（demo简化为0级）
- Demo中当做最简的0级场景

### 跨树交叉边（Q6 confirmed）
- **B）跨树边建立全局依赖**：锁必须等密码完成才能生成
- 需要环检测：钥匙→箱子→线索→钥匙 = 死锁，建图谱时警告

### Prompt 融合结构（Q7 confirmed）
```
【生成主体】资产本身的视觉描述（古老铜锁，量子纹路...）
【关联衔接描述】与已完成关联资产在视觉上嵌合的部分
   — 只描述视觉衔接，不描述游戏逻辑（不写"密码打开锁"）
   — 只描述和主体在视觉上保持一致的东西
【背景光影】0级背景的色调描述 + 光线角度描述
   — 所有资产都是自然光状态，便于后期环境光渲染
```
核心原则：**prompt 只包含视觉相关信息，不包含游戏逻辑**

## 数学结构理解
- 主体是**树**（层级路径，互动深度）
- 可能有**跨树交叉边**（全局依赖，需环检测）
- 形成树 + 交叉边的混合图 = DAG（有向无环图）
- 生成顺序：分层拓扑排序
  - 自底向上：最深层的叶子节点先生成
  - 同层内：度数最低优先，同度数按序号排
  - 多边节点：等所有入边来源完成后才能生成
