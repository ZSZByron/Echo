## 方向决策（已确认）

### 决策 1：LLM 转化路径 = A2（分模块 LLM + 编译器合并）

**否决了**：
- 路径 1（单步 LLM 直出）— prompt 巨大，LLM 幻觉风险高
- 路径 3（两阶段节点+边）— 延迟高，节点-边分离丢失语义

**选择 A2 的理由**：输入节点不确定，分模块更可控；8 大模块天然对齐。

### 决策 2：词典深度 = B2（Prompt 模板级）

**否决了**：B1（仅 Schema 级）— 不够，LLM 怎么推理必须定义

### 决策 3：三步架构（非两步）

A2 分模块 LLM 之后，**必须加"交叉边识别"**——分模块 LLM 只能产出模块内边，跨模块边需要专门识别。

```
① 分模块 LLM（8 大模块各自提取节点 + 模块内边）
② 交叉边识别（跨模块节点之间的关系）
③ 编译器合并 + 校验（封闭枚举校验 + 阶段越权校验）
```

## 用户指出的盲区（v0.1 词典不完整）

### 盲区 1："不止地形"

v0.1 第 2 类只有"规则/力量 → 地理"。实际上 8 大模块 → 5 种 A1 实体（Geography/Faction/Event/Concept/Constraint）是**多对多映射**，不是只有"→Geography"。

**待补**：8 大模块 × 5 种 A1 实体的完整映射矩阵——每个模块产出什么节点、什么边、边的源和目标分别是什么实体类型。

### 盲区 2：LLM 自动提取能力有限

有些节点是**显式**的（模块 4 填了势力名 → 直接提取 Faction），有些是**隐式**的（模块 2 的物理法则 → 需要推理出 Geography）。

不能假设 LLM 一次就能提取全部节点。需要定义：
- 哪些节点是问卷直采（显式提取）
- 哪些节点是 LLM 推理生成（隐式提取，如 Geography 从模块 2+3 推导）
- 隐式提取的 prompt 模板

### 盲区 3：交叉边识别是独立步骤

模块 4 的 LLM 只知道 Faction，模块 3 的 LLM 只知道 Concept。"Concept → Faction"（力量体系如何影响势力格局）这种跨模块边，两个模块 LLM 都看不到全貌。

**待定义**：
- 哪些跨模块组合需要识别什么边
- 交叉边识别的触发规则
- 交叉边 LLM 的 prompt 模板（输入=全部已提取节点，输出=跨模块边）

### 2. 每种边的 Prompt 模板

对 v0.1 的 19 种边 + 可能新增的边，定义：
- LLM 输入：哪些模块的回答 + 已提取的节点列表
- LLM 输出：JSON Schema（edge_type / source_id / target_id / attributes）
- 推理指令：LLM 应该怎么从输入推理出这条边

### 3. 交叉边识别的触发规则

哪些跨模块组合需要识别什么边。例如：
- 模块 3（Concept）+ 模块 4（Faction）→ 触发 `POWER_SATURATES_FACTION`?（新边类型?）
- 模块 2（物理法则）+ 模块 4（Faction）→ 触发 `RULE_LIMITS_FACTION`?（新边类型?）

> **可能产出新边类型**：v0.1 词典可能不够，交叉边识别可能暴露需要新增的边类型 → 升级词典版本到 v0.2。

### 4. LLM 输出的 JSON Schema + 校验规则

- 边的 JSON 结构定义
- 封闭枚举校验（edge_type 必须在 v0.1/v0.2 词典内）
- 阶段越权校验（A2/A3 不可建"仅 A1"边）
- 方向校验（source_type / target_type 匹配）
- cardinality 校验（一对一/一对多/多对多）

### 5. 节点提取的显式/隐式策略

- 显式提取：问卷直接填了名字的实体（如模块 4 的势力名）
- 隐式提取：需要 LLM 从回答推理的实体（如 Geography 从模块 2+3 推导）
- 隐式提取的 prompt 模板
- 厂家确认环节（隐式提取的节点需要厂家确认才入库）
